# Design for US-10.1: SDK v0.2.0 surface — context handles and error string accessors

## Approach

The existing `include/human/hula_sdk.h` is a header-only facade: it re-exports
`human/agent/hula.h` and adds three `static inline` helpers (`hu_hula_sdk_call`,
`hu_hula_sdk_sequence`, `hu_hula_sdk_run_json`) plus version macros. v0.1.0
gave embedders convenience constructors but no opaque handle — every call
threads an `hu_allocator_t *` and manages program/exec lifetime explicitly.
That works for C callers but is hostile to FFI/ctypes/N-API bindings, which
want a single opaque pointer to attach a finalizer to.

For v0.2.0, the cheapest design that unblocks US-10.2 (Python) and US-10.3
(TypeScript) is:

1. **Add a thin opaque context type `hu_hula_ctx_t`** that owns an embedded
   allocator (defaulting to the libc allocator from `human/core/allocator.h`)
   and is the single handle bindings pass around. It is *additive only* — no
   v0.1.0 helper is touched.
2. **Add `hu_hula_error_string(hu_error_t)`** as a non-`static` extern
   function backed by a switch over the `hu_error_t` enum from
   `include/human/core/error.h`. Bindings call it to map error codes to
   human-readable strings without reimplementing the enum.
3. **Bump the version macros** to 0.2.0 and document additions in
   `bindings/sdk-changelog.md`.

Why a real symbol (not `static inline`) for `hu_hula_error_string`: the v0.1.0
helpers are inline because they have no `.c` companion and need no link. A
switch over ~60 `hu_error_t` codes inlined into every TU would bloat
embedders' binaries and risk pedantic warnings on unused-static-inline. One
extern symbol in a new `src/agent/hula_sdk.c` is the minimum cost and gives
bindings a single dlsym target.

Why opaque `hu_hula_ctx_t` and not "just expose `hu_hula_exec_t` directly":
exec is per-program and binds to a tools array; a ctx is per-binding-instance
and is what Python's `HulaContext` / TS's `new HulaContext()` instantiate
once. Keeping the field layout opaque (forward-declared struct, full
definition in the new `.c`) lets us evolve the internals without breaking
ABI in v0.3+.

## Implementation steps (for the implementer agent)

1. **Header skeleton (no behavior):**
   - In `include/human/hula_sdk.h`, change `HU_HULA_SDK_VERSION_MINOR` from `1` to `2` and `HU_HULA_SDK_VERSION_STRING` from `"0.1.0"` to `"0.2.0"`.
   - Add a forward declaration: `typedef struct hu_hula_ctx hu_hula_ctx_t;`
   - Add three prototypes guarded only by C linkage (header is already C — no `extern "C"` block needed unless one is later wanted for C++):
     ```c
     hu_error_t hu_hula_ctx_create(hu_allocator_t *alloc, hu_hula_ctx_t **out);
     void hu_hula_ctx_destroy(hu_hula_ctx_t *ctx);
     const char *hu_hula_error_string(hu_error_t err);
     ```
   - Add Doxygen-style doc comments above each, including ABI-stability note: "Stable in v0.2.0. Changes to this signature bump MAJOR."
2. **Create `src/agent/hula_sdk.c`:**
   - Define `struct hu_hula_ctx { hu_allocator_t alloc; }` — minimum field set. (Field is internal; bindings only ever see the typedef.)
   - `hu_hula_ctx_create`: NULL-check inputs (return `HU_ERR_INVALID_ARGUMENT`), use `alloc->alloc` for the ctx allocation, copy the `hu_allocator_t` by value into the struct, set `*out`, return `HU_OK`. On allocation failure return `HU_ERR_OUT_OF_MEMORY` and leave `*out` untouched (the caller asserts behavior — see test).
   - `hu_hula_ctx_destroy`: NULL-safe; capture the embedded allocator's `free` and `ctx` pointer, then `free(ctx)`. Order matters because the allocator vtable is stored *inside* the struct; copy locals before free.
   - `hu_hula_error_string`: a single `switch (err)` over every `HU_ERR_*` and `HU_OK`, each `case` returning a static string literal that equals the C identifier (e.g. `case HU_ERR_INVALID_ARGUMENT: return "HU_ERR_INVALID_ARGUMENT";`). `default: return "HU_ERR_UNKNOWN";`.
   - Use `-Wswitch-enum` — but **do not** add `default` first; put it last so the compiler still warns if new error codes are added without a string. (Mitigates AC-10.1.2 silently regressing.)
3. **Add `src/agent/hula_sdk.c` to the library target.** Verify via `cmake --build --preset dev` that the symbol is exported.
4. **Write `tests/test_hula_sdk_v2.c` (six tests, fail-first):**
   - `test_hula_sdk_version_is_v02`: assert macros equal 0.2.0.
   - `test_hula_sdk_ctx_create_destroy_roundtrip`: create with default allocator, destroy, ASan should report no leak.
   - `test_hula_sdk_ctx_create_rejects_null_alloc`: returns `HU_ERR_INVALID_ARGUMENT`, leaves `*out` unchanged.
   - `test_hula_sdk_ctx_create_rejects_null_out`: returns `HU_ERR_INVALID_ARGUMENT`.
   - `test_hula_sdk_error_string_known_codes`: `HU_OK`, `HU_ERR_INVALID_ARGUMENT`, `HU_ERR_OUT_OF_MEMORY` each return a non-NULL, non-empty, distinct string.
   - `test_hula_sdk_error_string_unknown_returns_sentinel`: `(hu_error_t)9999` returns `"HU_ERR_UNKNOWN"`.
5. **Write `bindings/sdk-changelog.md`:**
   - Header: `# HuLa SDK Changelog`
   - Entry `## 0.2.0 — 2026-05-28`
   - For each new symbol: name, signature, rationale (one sentence: "needed by Python/TS bindings for opaque lifetime / for human-readable error mapping"), ABI stability promise.
   - Note: zero removals, zero signature changes from 0.1.0.
6. **Run `/verify`** to confirm AC-10.1.1 through AC-10.1.6.

## Risks

- **Backward compat (LOW / SMALL):** v0.1.0 callers include the same header. We only **add** declarations and bump macros; no existing `static inline` body is touched, no existing symbol is renamed. Mitigation: AC-10.1.3 is verified by recompiling existing in-tree consumers of `hula_sdk.h` (find them with `grep -r "hu_hula_sdk_" --include="*.c"` and confirm no diagnostics).
- **ABI stability (MEDIUM / MEDIUM):** Once `hu_hula_ctx_create` is published, US-10.2 and US-10.3 bind to it. A v0.2.1 signature change would break ctypes/N-API at runtime (no compile-time check across the FFI boundary). Mitigation: lock the signature in the changelog with explicit "ABI-stable in 0.2.x" language; flag any reviewer attempt to change the prototype before US-10.2/US-10.3 land. Critic agent should grep for `hu_hula_ctx_create` signature drift between US-10.1 close and US-10.3 close.
- **Switch coverage (LOW / MEDIUM):** `hu_hula_error_string` will silently return `"HU_ERR_UNKNOWN"` for any future error code added without updating the switch. Mitigation: do not place `default` first; relying on `-Wswitch-enum` (when the project ships with it) makes the compiler warn. If `-Wswitch-enum` is not on by default, add a regression test that asserts every enum value from `HU_OK` up to the highest known code returns a string distinct from `"HU_ERR_UNKNOWN"`. (Skipped for this sprint to keep XS scope — added to backlog as `DEBT-` task.)
- **Pin-the-bug risk (LOW):** Per `.claude/rules/tests-that-pin-bugs.md`, `test_hula_sdk_error_string_unknown_returns_sentinel` MUST assert the sentinel literal exactly. If the implementer changes the default string later (e.g. to "unknown error"), the test must fail. Test name accurately describes a positive contract, not aspirational behavior.
- **Concurrency (LOW / SMALL):** `hu_hula_ctx_t` is per-thread by convention; no shared state introduced. Documented in changelog as "not thread-safe in 0.2.0 — out of scope per story."
- **Observability (LOW):** No production logging path added. `hu_hula_error_string` is the observability primitive bindings will use to render exceptions, which is the whole point.
- **Quality gates (`-Werror`):** New `.c` file must compile with `-Wall -Wextra -Wpedantic -Werror`. Risk: `-Wunused-parameter` on the destroy path if we capture but do not use a field. Mitigation: keep `hu_hula_ctx_destroy` minimal; only reference fields that exist.

## Test strategy

- Unit tests only (`tests/test_hula_sdk_v2.c`, 6 cases). No integration tests this story — the bindings stories (US-10.2, US-10.3) are the integration layer and have their own test seams.
- Full suite (`./build/human_tests`) must run green per AC-10.1.6 — this is enforced by the standard per-task gate, no special action needed.
- ASan must report zero leaks (AC-10.1.1) — covered by ctx round-trip test, which the dev preset runs under ASan automatically.

## Acceptance criteria mapping

- **AC-10.1.1** (compile clean, ASan-clean ctx round-trip) → `test_hula_sdk_ctx_create_destroy_roundtrip` + clean `cmake --build --preset dev` run.
- **AC-10.1.2** (error_string non-NULL, distinct, sentinel for unknown) → `test_hula_sdk_error_string_known_codes` + `test_hula_sdk_error_string_unknown_returns_sentinel`.
- **AC-10.1.3** (v0.1.0 callers compile unchanged) → in-tree compile of every consumer of `hula_sdk.h` as part of the full build. Implementer must `grep -r "hu_hula_sdk_" --include="*.c" --include="*.h"` and confirm zero diffs needed in those files.
- **AC-10.1.4** (version macros) → `test_hula_sdk_version_is_v02`.
- **AC-10.1.5** (`bindings/sdk-changelog.md` exists with rationale) → file checked into commit; manually inspected by reviewer.
- **AC-10.1.6** (full suite green, 0 ASan errors) → `/verify` PASS gate.

## Hand-off notes for implementer

- Do NOT remove or rename the existing `static inline` helpers. Even cosmetic rewrites are out of scope.
- Do NOT introduce a `default:` arm at the top of the `hu_hula_error_string` switch — it defeats `-Wswitch-enum`.
- Do NOT add fields to `struct hu_hula_ctx` beyond `hu_allocator_t alloc` — anything else is YAGNI until US-10.2/US-10.3 prove a need.
- File the changelog before running `/verify`; reviewers check it exists as part of AC-10.1.5.
- Run `scripts/check-test-references.sh tests/test_hula_sdk_v2.c` after writing the test; if the heuristic does not match (test file name → production module), add explicit `#include "human/hula_sdk.h"` and ensure the test references at least one `hu_hula_*` symbol per the project rule.
