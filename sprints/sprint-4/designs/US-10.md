# US-10: Hookify rule — test files must reference production symbols

## Approach
Two-layer enforcement: a human-readable rule (markdown in `.claude/rules/`) and a deterministic checker (shell script wired into `.githooks/pre-commit`). Rule documents intent; script enforces it.

**Authorship via the hookify plugin.** Per task hint, use `hookify:writing-rules` skill to scaffold the rule. The skill produces a rule file with the trigger, scope, and check-script reference correctly cross-linked. Avoid hand-editing `.claude/settings.json` — let the plugin manage registration.

**Detection logic (`scripts/check-test-references.sh`)**:
1. Take a list of staged file paths (passed as args, or read from `git diff --cached --name-only --diff-filter=AM`).
2. Filter to `tests/test_*.c` files.
3. For each, derive the implied production module name: strip `tests/test_` prefix and `.c` suffix → candidate module name (e.g., `daemon_e2e_validator` → `daemon` after stripping `_e2e_validator` suffix). Heuristic: try the longest matching prefix that has a corresponding `src/**/*.c`.
4. Extract non-static function names from the candidate `.c` (via `ctags` or a regex over `^[a-z_].*\\(`) — restrict to `hu_*` prefixed symbols.
5. Grep the test file for at least one such symbol.
6. Exit 0 if found; exit 1 with a human-readable error pointing at the candidate module and missing symbols.

The script must be robust to: no matching production file (warn, exit 0 — test may cover headers or be cross-module); file with only mock symbols (still requires one real production reference).

**Pre-commit hook wiring** at `.githooks/pre-commit`: append `scripts/check-test-references.sh "$@" || exit 1` to the existing hook. If no hook exists, create a minimal one following project convention.

## Implementation steps
1. Run the hookify skill: `Skill(hookify:writing-rules)` with description "flag test files that reference no production symbol".
2. Author `scripts/check-test-references.sh`. Smoke-test against `tests/test_pattern_c_paths.c` (must exit 0) and a synthetic empty test (must exit 1).
3. Wire into `.githooks/pre-commit`. Verify the hook runs by staging a known-good file and committing in a throwaway branch.
4. Run the script across the full `tests/` tree as a one-shot — surface any pre-existing offenders. If any exist, list them in PR description; do NOT auto-fix (out of scope).

## Risks
- **Module-name derivation false negatives (MED/MED)**: test file names don't always map 1:1 to source files (`test_daemon_e2e_validator.c` could mean `daemon.c` or a new module). Mitigation: heuristic with longest-prefix-match + warn-and-pass on no match. Future improvement: explicit `// @covers: src/foo.c` annotation.
- **False positives blocking commits (MED/MED)**: a legitimate cross-module test fails the check. Mitigation: bypass via `// @covers-none` magic comment + clear error message documenting the escape hatch.
- **Pre-existing offenders (LOW/SMALL)**: existing tests may not satisfy the rule. Mitigation: script enforces only on staged-new test files (`git diff --cached --diff-filter=A`), not on AM. AC-10.2 says "staged" — covers both — re-confirm with PO if needed.
- **Hook bypass (LOW)**: users can `git commit --no-verify`. Acceptable — the rule is a guardrail, not a gate. CI can enforce harder later.
