# Design for US-11.3: Persona-vector projection as an early-stopping signal

## Approach

Sprint 8's `insights-addressed.md` Insight 2 already established that `train_chosen_r`
plateau-break is an effective, empirically-grounded proxy for the Anthropic
persona-vector projection signal (paper 2507.21509). Both signals fire at the same
moment — the inflection from "model speaks in user's voice" to "optimizer maximizes
margin by tanking `rejected_r` and dragging `chosen_r` with it." The persona-vector
paper provides the theoretical justification; `chosen_r` provides the production-cheap
implementation. Sprint 11 ships the cheap one.

The design is a **log-parsing callback**, not a deep training-loop intercept. Reasoning:

1. `mlx-lm-lora` already emits `Iter N: ... chosen_r X.XXX, ...` lines on every
   reporting step (see `/tmp/dpo80.log`). No upstream patch is required.
2. `scripts/finetune-gemma.py` is the canonical entry point. It already spawns
   `mlx_lm_lora` via `subprocess.run`. We wrap that call with a streaming reader.
3. When the callback fires, it sets a sentinel file (`.early_stop`) and sends
   `SIGTERM` to the training subprocess. `mlx-lm-lora` writes adapters at every
   `save_every` window, so the prior-window adapter is already on disk.
4. The "promoted" iter is computed as `floor((stopped_iter - 1) / save_every) *
   save_every` — i.e., the most recent saved checkpoint **before** the cliff.

This deliberately avoids: a fork of `mlx-lm-lora`; in-process callbacks (which would
require monkey-patching); any model-weight inspection. It is a single Python module
with one public class, parseable with regex, runnable on a static log file in tests.

The Anthropic persona-vector projection itself — reading intermediate-layer
activations, projecting onto a precomputed user direction — is **explicitly
out of scope** per the story ("deferred to Sprint 12"). It requires a bootstrap
activation vector that we do not yet have a pipeline for. See Open Questions §6.

## Implementation steps (for the implementer agent)

1. **Skeleton.** Create `scripts/early_stopping.py` with the public surface:
   - `@dataclass class Decision: should_stop: bool; reason: str; stopped_iter: int; promoted_iter: int`
   - `class ChosenRPlateauDetector(window:int=5, drop_ratio:float=0.5, confirm_consecutive:int=2, save_every:int=20)`
   - Methods: `observe(iter:int, chosen_r:float) -> Optional[Decision]`, `_trailing_mean()`, `_emit_log(decision)`.
   - `parse_iter_line(line:str) -> Optional[Tuple[int, float]]` using regex
     `r"Iter (\d+):.*chosen_r ([-\d.]+)"`. Returns `None` for val lines / non-matches.

2. **Generate the fixture.** Write a one-shot extractor (in test setup, not committed
   as a separate script) that reads `/tmp/dpo80.log`, applies `parse_iter_line` to
   each line, writes JSONL to `tests/fixtures/sprint8_dpo80_log.jsonl`. Expected
   trajectory (confirmed from log): `[(5,17.582),(10,15.925),(15,14.938),(20,20.434),
   (25,4.303),(30,4.868),(35,9.199),(40,8.921),(45,8.713),(50,9.896),(55,7.509),
   (60,7.349),(65,3.170),(70,2.103),(75,-4.500),(80,-8.867)]`.

3. **Five failing tests.** Write `tests/test_early_stopping.py` with all five AC
   tests asserting expected `Decision` values. All should fail (module doesn't
   detect yet).

4. **Implement `observe()` one branch at a time:**
   - Branch 1: append `chosen_r` to a deque(maxlen=window+confirm_consecutive+1).
   - Branch 2: until we have ≥ `window + 1` observations, return `None`.
   - Branch 3: trailing mean = mean of values `[-(window + confirm_consecutive):
     -confirm_consecutive]` (i.e., the window that PRECEDES the current candidate
     cliff). For window=5, confirm=2 → mean of indices -7..-2.
   - Branch 4: candidate cliff = last `confirm_consecutive` observations. If all
     of them are < `drop_ratio * trailing_mean`, fire.
   - Branch 5: `stopped_iter = current_iter`. `promoted_iter = stopped_iter -
     confirm_consecutive * report_every - save_every_offset`. Concretely: for
     report_every=5, save_every=20, fixture cliff at iter 70 (second sub-50%
     confirmation), promoted_iter = 60.

5. **Verify AC-11.3.2 by hand against the fixture before claiming pass:**
   - At iter 65: trailing window (iters 35-55) values `[9.199, 8.921, 8.713, 9.896,
     7.509]` → mean 8.848. Threshold = 4.424. Iter 60 chosen_r=7.349 (above).
     Iter 65 chosen_r=3.170 (below). One confirmation. Decision: `None`.
   - At iter 70: window now (iters 40-60) `[8.921, 8.713, 9.896, 7.509, 7.349]` →
     mean 8.478. Threshold = 4.239. Iter 65=3.170 (below), iter 70=2.103 (below).
     Two consecutive sub-50%. **FIRE.** stopped_iter=70. promoted_iter=60
     (last save_every=20 boundary before stopped_iter).
   - NOTE: the story text says "halted at iter 65". The implementer must
     reconcile: with `confirm_consecutive=2`, the **decision** fires at iter 70
     after seeing iter-65 + iter-70 both below threshold; the **stopped_iter**
     in the log is 70 but the **first sub-threshold iter** ("cliff iteration")
     is 65. Both AC-11.3.2 phrasings are satisfiable: emit both fields in the
     structured log (`first_breach_iter=65`, `stopped_iter=70`,
     `promoted_iter=60`) and have AC-11.3.2 assert against `first_breach_iter`.

6. **Wire into `finetune-gemma.py`:**
   - Add `--early-stopping-signal` arg (choices: `chosen_r`, `none`; default
     `chosen_r` for new runs but verify CI scripts pass `none` for the Sprint 11
     baseline to keep AC-11.3.5 backward-compat).
   - Replace `subprocess.run(...)` with `subprocess.Popen(..., stdout=PIPE,
     stderr=STDOUT, text=True, bufsize=1)`. Iterate `for line in proc.stdout`,
     pass each line through `parse_iter_line` → `detector.observe(...)`. Echo
     each line to our own stdout (preserve user-visible logging).
   - On fire: emit structured JSON log line, write `.early_stop` sentinel into
     the adapter dir, `proc.terminate()`, wait up to 10s, then `proc.kill()`.

7. **AC mapping verification.** Run `pytest tests/test_early_stopping.py -v`.
   All five must pass. Then run `/verify`.

## Risks

- **Subprocess termination race (MED / MED).** SIGTERM may arrive between
  `mlx-lm-lora`'s gradient step and its checkpoint write, leaving a corrupt
  adapter at `stopped_iter`. **Mitigation:** we don't trust `stopped_iter`'s
  adapter — `promoted_iter` is always the prior `save_every` boundary, which
  was fully written several iterations earlier. The promotion logic must
  verify the promoted adapter file exists and is well-formed (size > 0,
  loadable via `mlx.utils.tree_flatten`) before declaring success.

- **Log-parsing brittleness (MED / SMALL).** The regex depends on
  `mlx-lm-lora`'s output format. If they reformat (e.g., scientific notation,
  added fields), parser silently returns `None` and detector never fires.
  **Mitigation:** the test fixture pins the exact format we observed in Sprint 8.
  Add a sanity assertion in `finetune-gemma.py`: if no `Iter N: ... chosen_r`
  line is parsed within the first 20% of `--iters`, abort with a clear error
  ("early-stopping signal cannot be read; check mlx-lm-lora version").

- **False positive on noisy `chosen_r` (LOW / MED).** A single noisy outlier
  could trip the threshold if `confirm_consecutive=1`. **Mitigation:**
  `confirm_consecutive=2` (story-default) requires sustained drop. Sprint 8
  fixture validates this: iter 30 had `chosen_r=4.868` (a single dip during
  warmup before the plateau) — but trailing mean at that point is the warmup
  window itself, not the plateau, so the ratio test does not fire spuriously.
  Tests must include a "single-dip" case to lock this in.

- **Backward compatibility with Sprint 8 CI scripts (LOW / SMALL).** AC-11.3.5
  explicitly covers this: `--early-stopping-signal none` is a no-op. The CI
  scripts in `scripts/check-lora-*.sh` should be inspected; if they invoke
  `finetune-gemma.py` they may need the explicit `none` flag.

- **Observability (LOW / SMALL).** The structured log line in AC-11.3.4 must
  use a stable JSON shape so downstream tooling (Sprint 11 evidence collection,
  future Pareto picker integration) can parse it. **Mitigation:** lock the
  schema in the test (`test_early_stop_log_format`) — implementer cannot drift.

- **Window math off-by-one (MED / SMALL).** Easy to get the trailing window
  wrong (does it include the current iter? the prior confirm-window?). The
  fixture-grounded test (AC-11.3.2) is the canary: if `promoted_iter != 60`,
  the math is wrong.

## Test strategy

All tests are **deterministic and offline** — no model weights, no subprocess
spawning, no network. The test seam is the JSONL fixture; tests instantiate
`ChosenRPlateauDetector` directly and feed observations from the fixture.

- `test_chosen_r_plateau_break_fires` (AC-11.3.1): synthetic minimal trajectory.
- `test_sprint8_trajectory_stops_at_iter65` (AC-11.3.2): replay
  `tests/fixtures/sprint8_dpo80_log.jsonl`; assert `first_breach_iter=65`,
  `stopped_iter=70`, `promoted_iter=60`. Capture the decision sequence to
  `sprints/sprint-11/evidence/US-11.3-replay.txt`.
- `test_stable_chosen_r_no_early_stop` (AC-11.3.3): synthetic trajectory with
  `chosen_r ∈ [8.0, 9.6]` for 80 iters; assert no decision fires.
- `test_early_stop_log_format` (AC-11.3.4): capture structured JSON log line;
  assert keys `{"event":"early_stop", "reason":"chosen_r_plateau_break",
  "first_breach_iter":..., "stopped_iter":..., "promoted_iter":...,
  "trailing_mean":..., "threshold":...}`.
- `test_disabled_signal_is_noop` (AC-11.3.5): instantiate detector with
  signal=`none` (or pass-through wrapper); feed the Sprint 8 trajectory;
  assert no fire.

For the `finetune-gemma.py` wiring, add one `subprocess.run`-mocked test that
asserts the `--early-stopping-signal` flag is present and that a mock stdout
stream containing the Sprint 8 trajectory leads to `proc.terminate()` being
called. This is the only test that touches the subprocess seam; it does not
spawn anything real.

## Open questions

1. **Anthropic persona-vector projection scope.** The story states "deferred to
   Sprint 12" in Out-of-Scope. Recommendation: **keep deferred.** Activation
   projection requires (a) a bootstrap user-voice direction (which we'd derive
   from the same DPO chosen examples — circular without an external corpus),
   (b) hooks into `mlx-lm-lora`'s forward pass that don't exist, (c) a
   calibration step to set the drift threshold. Sprint 12 should pick this up
   after we have the held-out next-utterance LL evaluator (US-11.6) which gives
   us an independent ground-truth signal to calibrate against. Until then,
   `chosen_r` is the right shipping signal.

2. **Should `stopped_iter` or `first_breach_iter` be the headline in the
   structured log?** The story uses "halted at iter 65" loosely. Proposal:
   emit both; AC-11.3.2 test asserts `first_breach_iter=65`. The Pareto picker
   downstream (US-11.6 / `pareto_picker.py`) uses `promoted_iter` regardless.

3. **`save_every` coupling.** `promoted_iter` math assumes the training script
   uses `save_every=20` (Sprint 8 setting). If a future run uses `save_every=10`,
   the promoted artifact resolution changes. Recommendation: pass `save_every`
   into the detector constructor; `finetune-gemma.py` reads it from its own
   args and forwards it. Out-of-scope to make detector inspect the adapter
   directory; that's Sprint 12.

4. **What to do when `confirm_consecutive=2` would have us stop at iter 70 but
   the user wants to stop at iter 65 (first breach)?** Add an optional
   `--early-stopping-mode {confirm,first-breach}` flag, defaulting to `confirm`
   (the safer Sprint-8-validated default). First-breach is faster but less
   robust to a single-iter dip. Recommend: ship `confirm` only; revisit if
   evidence shows we're missing the cliff window.

5. **Interaction with US-11.4 (DPOP).** If DPOP is in play, `chosen_r` should
   never drop in the first place (DPOP's positive clamp prevents it). The
   detector should still run as a defense-in-depth check, but in expectation
   it never fires. This is fine — no design coupling needed.

6. **Bootstrap activation vector for the real persona-vector path (Sprint 12+).**
   If we want to build toward 2507.21509 properly, we need: (a) a held-out
   set of 50-200 user utterances, (b) a forward-pass hook to capture
   late-layer hidden states, (c) a mean-of-differences computation between
   user vs non-user activations. None of this is needed for Sprint 11. Flag for
   Sprint 12 planning.
