# Design for US-11.8 (P1): Dual fast/slow LoRA + EMA promotion for W14 cron

**Story:** US-11.8 (Sprint 11, Wave 2, P1)
**Depends on:** US-11.7 (4-stage Pareto gate provides the cascade verdict), US-11.4 (DPOP loss is the default for fast-adapter training)
**Extends ADR:** `docs/plans/adr/2026-05-11-adapter-rollback-signal.md` (this design realizes the "last-known-good kept on disk" half of the rollback contract)
**Risk tier:** MEDIUM (touches the live W14 cron path; symlink + status JSON are C-side; EMA math is Python-side)

---

## Approach

### Fast/slow lifecycle

The current W14 cron (Sprint 7 US-7.5, `src/ml/lora_retrain_runner.c`) trains a single adapter per night, runs a `PASS/FAIL` gate, and atomically swaps `current` symlink on PASS. **Each successful night fully replaces prior weights** — there is no consolidation, and a single noisy night of corrections can overwrite weeks of accumulated learning.

OFS-DPO (arXiv 2406.05534) prescribes a two-adapter design that we adopt directly:

- **`fast.safetensors`** — trained from scratch on tonight's correction batch only (DPOP+DoRA from US-11.4/US-11.2, high LR, small rank). Disposable. Re-created every night.
- **`slow.safetensors.v{N}`** — EMA-consolidated adapter that only advances on a gate PASS. This is the artifact that `current` symlink points at; production inference loads this.
- **`current` symlink** — always points at the latest promoted `slow.safetensors.v{N}`. On PASS it advances; on REJECT it is unchanged. On `human adapter rollback` it moves back to `v{N-1}`.

The runner sequence becomes (extending Sprint 7's steps 1–5):

```
1. PID lock                           [unchanged]
2. Pair-count probe                   [unchanged]
3. Train fast adapter (DPOP+DoRA)     [unchanged subprocess, output renamed to fast.safetensors]
4. Run 4-stage Pareto gate (US-11.7)  [replaces single check-lora-ab.sh call]
5. On PROMOTE verdict:
   a. EMA helper computes: slow_new = 0.95 * slow_current + 0.05 * fast
   b. Save slow_new as slow.safetensors.v{N+1}
   c. Atomic symlink swap: current -> slow.safetensors.v{N+1}
   d. Update status JSON with versions, alpha, verdict, KL drift
6. On DEFER/REJECT verdict:
   a. Move fast.safetensors -> quarantine/{YYYY-MM-DD}.safetensors
   b. slow.safetensors unchanged; current symlink unchanged
   c. Emit `nightly_retrain_rejected` event with gate verdict + reasons
```

### EMA formula

`slow_new = alpha * slow_current + (1 - alpha) * fast` with **`alpha = 0.95`** (OFS-DPO default; `sota-continual.md` §3 confirms this is the operating value).

EMA is computed **per-tensor** over the LoRA A/B matrices. For DoRA we additionally EMA the magnitude vector `m`. **Critical constraint** for soundness: `slow_current` and `fast` must share rank, target modules, and base model. Mismatch → bail with `HU_ERR_PRECONDITION` and emit `lora_retrain_ema_skipped`; do NOT silently truncate or zero-pad (this is Risk #1, see below).

Cold start: when no `slow.safetensors.v{N}` exists (first night, or post-prune state), `slow_new := fast` and `v{0}` is established. This is documented as the bootstrap case in the EMA helper.

### KL drift computation

The STABLE gate (`sota-continual.md` paper #2, arXiv 2510.16089) requires `KL(base || candidate) < tau_kl = 0.5 nats` as one of three stability signals. **Scope decision:** US-11.7's 4-stage gate already computes a PPL floor (Stage 1) and coherence (Stage 2) — KL drift is **not** one of those four stages. We add it as a **promotion-time sanity check inside the EMA helper**, computed AFTER the Pareto gate passes but BEFORE the symlink swaps. If `KL > 0.5 nats`, we treat it as a quarantine-equivalent REJECT (emit `lora_retrain_kl_drift_rejected`) and leave `slow` unchanged.

KL is computed on a fixed 200-prompt **probe set** (`tests/fixtures/kl_probe_200.jsonl`, PII-scrubbed Seth utterances) as `mean_i KL(base_logits_i || candidate_logits_i)` where `candidate` is the proposed `slow_new`. Computation is delegated to `scripts/compute_kl_drift.py` (new) via subprocess from the runner; in tests the subprocess hook returns a fixture KL value, and `HU_IS_TEST` prevents real-model execution.

### "OLD pairs" hold-out definition

The forgetting check (STABLE signal 2) requires a stable, frozen evaluation set of pairs that the model was ABLE to handle BEFORE tonight's training. We define **OLD pairs** as:

- The same correction pair format as `dpo_pairs.db`, but stored separately at `tests/fixtures/old_pairs_holdout.jsonl`.
- **Curation rule:** a pair enters OLD-pairs only after it has been seen by 2 successive promoted `slow` adapters without regression (i.e., the corrected response under both adapters has lower NLL than the original).
- **Size:** target 100 pairs, minimum 30 (matches Sprint 8 holdout cadence).
- **Refresh:** appended to (never replaced) by `scripts/promote_old_pair.py` after each successful promotion. Older pairs persist for at least 90 days.

This curation discipline is critical (Risk #2 below): a poorly-curated OLD set either hides real forgetting (too small / too narrow) or generates false-rejects (too noisy). Sprint 11 ships with a manually seeded fixture of 30 pairs; the curation script lands in Sprint 12.

The OLD-pair forgetting check itself is reused from US-11.6's YNTP evaluator — we just point `twin-eval` at `old_pairs_holdout.jsonl` instead of the standard fixture, with the threshold `delta_nll >= -0.02` (regression up to 2% NLL is tolerated; deeper is a forgetting trip).

## Implementation steps (sequenced for the implementer)

1. **Header skeleton.** Extend `hu_lora_retrain_ctx_t` with the new context + output fields. Add new `hu_lora_ema.h`. Compile clean against existing call sites by initializing new fields to `NULL`/`0` (no behavior change yet). Tests must still pass.

2. **EMA helper module (no runner integration yet).** Implement `hu_lora_ema_apply` + `hu_lora_ema_compat_check` with subprocess delegation to `scripts/lora_ema.py`. Add unit tests against tiny fixture safetensors (rank-4, 2 modules). Verify rank-mismatch refusal path. **Verify ASan clean.**

3. **KL drift subprocess wrapper.** Add the `compute_kl_drift` invocation path inside the EMA helper (gated by `HU_IS_TEST` mock). Unit test the parse of `{"kl_nats": ..., "n_prompts": ...}` and the threshold comparison.

4. **Status JSON v2.** Extend the writer/parser pair atomically (writer first, parser second, then update consumers in `cmd_doctor`). Round-trip test in `test_scheduler_status.c`. This is reversible — if downstream chokes, revert just this layer.

5. **Runner integration — happy path first.** Wire the new STEP 5 (EMA + KL + symlink) into `lora_retrain_runner.c` behind a context flag `ctx->dual_lora_enabled` defaulting to **false**. With the flag false, behavior is identical to Sprint 7. Add 1 happy-path test (`test_dual_adapter_artifacts_created`).

6. **Runner integration — reject paths.** Add quarantine flow and the KL/forgetting reject branches. Add reject-path tests (`test_quarantine_on_reject`, `test_kl_drift_rejected`, `test_old_pairs_forget_rejected`).

7. **Rollback CLI.** Implement `human adapter rollback` enumerating versions and moving symlink. Add `test_adapter_rollback_cli`.

8. **Enable the flag.** Flip `ctx->dual_lora_enabled` default to true in the scheduler bootstrap. Run the full simulated 4-night test fixture (2 promote, 2 reject) — this is AC-11.8.1–AC-11.8.3 in aggregate.

9. **Doctor command rendering.** Surface the new fields via `human doctor scheduler` — required by AC-11.8.5.

10. **`/verify` pass + critic review** before claiming done.

## Risks

### Risk #1 — EMA between LoRA matrices may be unsound for certain rank configs (HIGH probability / MEDIUM impact)

**What goes wrong:** EMA over LoRA `A` and `B` matrices is **not** mathematically equivalent to EMA over the materialized delta `BA`. The product is bilinear, so `0.95*B0*A0 + 0.05*B1*A1 ≠ (0.95*B0 + 0.05*B1)*(0.95*A0 + 0.05*A1)`. For small alpha contributions and similar adapters (the common case after a few nights of convergence), the difference is small — but for early nights with large fast/slow divergence, the matrix-EMA can drift in a direction that neither parent points at.

**Probability:** HIGH that some divergence exists; MEDIUM that it matters at our scale (DoRA at rank 8–16 on small adapters).

**Impact:** MEDIUM — could cause inference quality to oscillate even after a PROMOTE; could trigger spurious rollbacks via ADR signals.

**Mitigation:**
1. **Pre-flight check in `hu_lora_ema_compat_check`:** require `rank`, `lora_alpha`, target-modules, base-model-hash all match between `slow` and `fast`. Refuse otherwise (return `HU_ERR_PRECONDITION`). This is the table-stakes guard.
2. **Sanity gate post-EMA:** the existing 4-stage Pareto gate is run AGAIN on the materialized `slow_new` (cheap — we already have the fixtures). If `slow_new` fails coherence, the EMA is abandoned and we keep `slow_current`. Adds one Stage-1+2 invocation per promotion night.
3. **OFS-DPO empirical precedent:** the paper does straight tensor EMA at this scale without reported instability — but at rank 16+ with curated preference data. Sprint 12 should add a numerical study against Seth's actual data before considering rank changes.
4. **Open question to resolve in Sprint 12** (see below): whether to instead EMA the materialized `BA` delta and re-decompose. This is more expensive but mathematically clean. Out of scope for US-11.8.

### Risk #2 — "OLD pairs" hold-out is bootstrap-fragile (MEDIUM / MEDIUM)

**What goes wrong:** The OLD-pairs set is meant to detect catastrophic forgetting. But it has a bootstrap problem: in Sprint 11 we ship a manually-seeded 30-pair fixture, NOT a fixture that has actually been observed-stable across 2 promoted adapters. So early in the cron's life, the OLD-pairs check is testing pairs the model may genuinely struggle with for reasons unrelated to forgetting.

**Probability:** MEDIUM (high if the manual seed isn't representative).
**Impact:** MEDIUM — false REJECTs block promotion until manually overridden; if we relax the threshold to compensate, real forgetting goes undetected.

**Mitigation:**
1. **Sprint 11 ships with `forget_tau_nll = -0.02` (lenient)** — only fires on >2% NLL regression. Documented as tunable per ADR-style decision.
2. **Manually seed the 30-pair fixture from Sprint 8 best-adapter outputs**: only include pairs where the Sprint 8 iter-60 adapter handled them correctly (lower NLL on continuation than base). This gives us a fixture that two prior adapters have already handled.
3. **Defer auto-curation script** (`scripts/promote_old_pair.py`) to Sprint 12 with the dedicated curation discipline outlined in the Approach section.
4. **Telemetry:** count `nightly_retrain_rejected` events by `reason=old_pairs_forget` for the first 14 nights. If frequency >2 in 7 nights, the fixture is wrong — surface to operator (the ADR's "rollback frequency >1 per 7 nights" pattern applies).

### Risk #3 — Cascade gate (US-11.7) dependency timing (MEDIUM / LARGE)

**What goes wrong:** US-11.7 must land before US-11.8 can integrate. If US-11.7's interface (the JSON verdict shape from `scripts/check-lora-ab.sh --staged-gate`) changes after US-11.8 starts, we have to rework integration. Wave 2 is sequential after Wave 1 (per `stories.md` dependency graph), but parallel implementer assignment within Wave 2 is risky.

**Probability:** MEDIUM (US-11.7 is also new and large).
**Impact:** LARGE — wrong gate-verdict parsing could either block all promotions OR (catastrophic) let broken adapters through.

**Mitigation:**
1. **Pin the gate-verdict JSON contract in this design doc** (below). US-11.7's implementer references this section as the public contract; US-11.8 parses against it.
2. **Sequence US-11.7 BEFORE US-11.8 within Wave 2.** Do not parallel-implement. Tech-lead enforces.
3. **Defensive parsing:** US-11.8's verdict parser accepts the existing `"verdict": "PASS|SKIP|FAIL"` shape from Sprint 7 AS A FALLBACK (treat missing-keys as REJECT, never as PROMOTE). Belt-and-braces against contract drift.
4. **Integration test in `test_w14_dual_lora.c`:** uses a fixture stdout that matches US-11.7's documented JSON shape verbatim. Any drift fails the test loudly.

#### Pinned gate-verdict contract (from US-11.7)

```json
{
  "verdict": "PROMOTE | DEFER | REJECT",
  "stages": {
    "ppl_floor":  {"passed": bool, "value": float, "threshold": float},
    "coherence":  {"passed": bool, "pad_rate": float, "threshold": float},
    "prm":        {"passed": bool, "score": float, "stub": bool},
    "ensemble":   {"passed": bool, "aggregation": "min"}
  },
  "delta_nll": float,
  "pad_rate": float
}
```

US-11.8 reads `verdict` as authoritative. `PROMOTE` proceeds to EMA + KL + OLD-pairs; `DEFER` and `REJECT` both quarantine. (`DEFER` is observability-only in Sprint 11 — same disposition as `REJECT` for promotion purposes; the distinction is for the Pareto-picker analytics, not the cron's behavior.)

## Open questions (tech-lead → product-owner / Sprint 12)

1. **Matrix-vs-delta EMA:** Should the EMA happen on `(A, B)` separately, or on the materialized `BA` delta with re-decomposition? Sprint 11 ships the simpler matrix-EMA; Sprint 12 evaluates numerically. (Risk #1.)
2. **OLD-pairs auto-curation:** Sprint 12 needs `scripts/promote_old_pair.py`. (Risk #2.)
3. **`DEFER` semantics:** Sprint 11 treats `DEFER` as REJECT for the cron. Sprint 12 could promote DEFER candidates to a "shadow" slot for offline A/B without affecting `current`. Out of scope here.
4. **Quarantine retention:** ADR specifies "at least 30 days or 3 rollback cycles." Sprint 11 does not implement GC — the directory grows monotonically. Sprint 12 lands `human adapter prune`.
5. **Multi-user adapters:** Single-user scope per the story's out-of-scope list. Multi-user adapter management is a Sprint 12+ concern.
