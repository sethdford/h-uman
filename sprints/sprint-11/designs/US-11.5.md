# Design for US-11.5: Wire ORPO train_step (finish Sprint 7 US-7.10 stub)

## 1. Approach

This story finishes the ORPO half of the `hu_rl_trainer_t` vtable shipped in
Sprint 7 US-7.10. The vtable surface, the `hu_pref_pair_logprobs_t`
injection seam, and the CLI router are all stable; SimPO is the reference
implementation. Symmetric to US-7.10:

1. **One new TU** — `src/ml/rl_trainer_orpo.c` — that owns a context
   struct, a static vtable, a `compute_loss` body that implements the
   ORPO formula in pure double precision against injected logprobs, a
   `train_step` body that returns `HU_ERR_NOT_SUPPORTED` outside
   `HU_IS_TEST` (mirroring SimPO's deliberately-deferred forward-pass —
   see Risk R1), and a `hu_rl_trainer_orpo_create` factory.
2. **One CLI dispatch edit** in `src/ml/cli.c` to peel `orpo` out of the
   "not yet implemented" branch and route it to the new factory, with a
   `--lambda-orpo` flag parser symmetric to `--beta`/`--gamma`.
3. **One golden test file** — `tests/test_rl_trainer_orpo.c` — that
   asserts `loss == NLL(chosen) + λ · OR_penalty` to 1e-4 against a
   hand-computed fixture (no model instantiation).

The ORPO loss used here, per Hong et al. arXiv 2403.07691 Eq. 7 and as
referenced in `sprints/sprint-9-plus/research/sota-dpo.md` line 51:

```
L_ORPO = L_SFT + λ · L_OR
L_SFT  = -(1/|y_w|) · logπ(y_w | x)                     # length-normalized NLL on chosen
L_OR   = -log σ( log_odds(y_w|x) - log_odds(y_l|x) )
log_odds(y|x) = logπ(y|x) - log(1 - π(y|x))
```

The key numerical trick that survives in double precision and matches the
HuggingFace TRL reference implementation: rewrite `log(1 - exp(logp))`
using `log1p(-exp(logp))` and clamp `logp` to `[-∞, -ε]` (because a
chosen with logp == 0 means π == 1 → 1 - π == 0 → log diverges). The
SimPO file's `HU_SIMPO_SIGMOID_FLOOR = 1e-10` is the precedent for the
floor pattern (rl_trainer_simpo.c line 33); we mirror it as
`HU_ORPO_LOG1MEXP_FLOOR` for the `1 - π` term and
`HU_ORPO_SIGMOID_FLOOR = 1e-10` for the outer `-log σ`.

The cheapest design is to **reuse the existing seam verbatim**. No vtable
widening, no new header types, no new fixture format. The `rejected_*`
fields of `hu_pref_pair_logprobs_t` are required by AC-11.5.2's golden
fixture (ORPO does compare chosen vs rejected for the OR term — the AC
text saying "no `rejected` field required" refers to the *training data
schema* per Hong et al. §3.3, not the in-memory `compute_loss`
struct). The single-stage SFT-only special case (when `rejected_token_count
== 0` is passed) reduces to `loss == NLL(chosen)` by zeroing out the OR
term — see §4 / AC-11.5.2 mapping.

This is the **boring option** by design: it copies the SimPO file's
layout line-for-line, swaps the loss math, and adds one CLI flag. No
new abstractions earn their keep here.

## 2. Existing-code interface notes

- **`include/human/ml/rl_trainer.h`** (already shipped): the
  `hu_pref_pair_logprobs_t` struct exposes
  `chosen_logprob_sum / chosen_token_count / rejected_logprob_sum /
  rejected_token_count`. These are sums of token-level
  `logπ(token_i | context_i)` — exactly the per-sequence `logπ(y|x)`
  ORPO Eq. 7 needs. No struct change required.
- **`src/ml/rl_trainer_simpo.c`** (template): the file structure
  (`hu_simpo_ctx_t` → static vtable → factory) is the contract for the
  new ORPO TU. Copying it keeps reviewer cognitive load minimal.
- **`src/ml/rl_trainer.c`**: the dispatcher already includes
  `HU_RL_TRAINER_ORPO` in `hu_rl_trainer_type_name`. **No edit needed
  to rl_trainer.c** beyond what the AC requires — the factory call
  lives in `cli.c`, not in a registry table. (Story prompt suggests a
  factory dispatch edit in rl_trainer.c, but the existing US-7.10 code
  shows the factories are called directly from the CLI; we follow the
  existing pattern.)
- **`src/ml/cli.c` line 3163**: the current branch
  `if (strcmp(algorithm, "orpo") == 0 || strcmp(algorithm, "grpo2") == 0)`
  emits the NOT_SUPPORTED stub. The edit is to split this into
  "orpo→new factory path" and "grpo2→keep emitting NOT_SUPPORTED"
  (AC-11.5.5 requires GRPO-2 to still exit 2).
- **`include/human/ml/rl_trainer.h`**: add `hu_orpo_config_t` with one
  field (`float lambda`) plus the nullable `hu_model_t *model` (for
  parity with SimPO, even though `train_step` is a stub today). Add
  the `hu_rl_trainer_orpo_create` prototype. ~15 LOC.
- **`CMakeLists.txt`**: register `src/ml/rl_trainer_orpo.c` and
  `tests/test_rl_trainer_orpo.c`. Same pattern as US-7.10 added the
  SimPO files (search for `rl_trainer_simpo` in the file).

## 5. Implementation steps (for implementer agent)

1. **Header** — add `hu_orpo_config_t { float lambda; hu_model_t *model; }`
   and `hu_rl_trainer_orpo_create` prototype to
   `include/human/ml/rl_trainer.h`. Compile (won't link yet).
2. **Skeleton TU** — create `src/ml/rl_trainer_orpo.c` by copying
   `rl_trainer_simpo.c`, renaming `simpo`→`orpo`, replacing the loss
   body with `*out_loss = 0.0; return HU_OK;`. Register in
   `CMakeLists.txt`. Full suite green.
3. **Golden fixture** — write `tests/fixtures/orpo_golden.json` with a
   hand-computable example: e.g. `chosen_logprob_sum = -1.5,
   chosen_token_count = 3, rejected_logprob_sum = -4.5,
   rejected_token_count = 3, lambda = 0.1`. Compute `expected_loss`
   in a Python comment in the JSON and lock-in the value. Add
   `test_orpo_loss_golden` (will fail — loss is 0).
4. **Loss body** — implement `orpo_compute_loss`:
   - `avg_chosen_logp = chosen_logprob_sum / chosen_token_count`
   - `nll = -avg_chosen_logp`
   - if `rejected_token_count == 0` → set `or_penalty = 0`, skip OR
     term (SFT-only mode; AC-11.5.2 fallback path)
   - else: `avg_rejected_logp = rejected_logprob_sum / rejected_token_count`
   - Compute `log_odds(y) = logp - log1mexp(logp)` for each, where
     `log1mexp(x) = log(1 - exp(x))` with the floor; clamp `logp`
     above by `-HU_ORPO_LOG1MEXP_FLOOR` to keep `1 - exp(logp) > 0`
   - `or_logits = log_odds_chosen - log_odds_rejected`
   - `or_penalty = -log(max(σ(or_logits), HU_ORPO_SIGMOID_FLOOR))`
   - `*out_loss = nll + (double)lambda * or_penalty`
5. Run `test_orpo_loss_golden` — should pass at 1e-4.
6. Implement edge tests (AC-11.5.3, SFT-only special case, invalid
   lambda, deinit-idempotent). All green.
7. **CLI wiring** — edit `src/ml/cli.c` line ~3163:
   - Split the dual-branch so `grpo2` keeps emitting NOT_SUPPORTED
     and `orpo` falls through.
   - After the SimPO block (~line 3179), add a parallel ORPO block
     parsing `--lambda-orpo`, calling `hu_rl_trainer_orpo_create`,
     calling `train_step` under `HU_IS_TEST` for AC-11.5.1.
   - Update `--help` text to remove "(not yet implemented)" next to
     `orpo` and keep it next to `grpo2`.
8. Add `test_orpo_train_exits_0` to `tests/test_ml_cli_rl_train.c`.
   Run the existing `test_rl_train_unimplemented_algorithms` to confirm
   grpo2 still exits 2 (AC-11.5.5).
9. Full suite + ASan; ensure 0 failures, 0 leaks.
10. Run `/verify` with the AC list.

## 6. Risks

- **R1 — `train_step` is NOT_SUPPORTED in production (MED / MED).** This
  mirrors SimPO's situation (FU-7.10.a). The story explicitly says
  Python `finetune-gemma.py --variant orpo` is the goal, but **AC-11.5.1
  only requires the C CLI to exit 0**, and Sprint 11 US-11.5 "Out of
  scope" excludes Python integration ("only the C vtable is wired here;
  Python integration is deferred to Sprint 12"). **Mitigation:**
  follow SimPO's precedent — wire `compute_loss` (load-bearing for the
  golden test), gate `train_step` behind `HU_IS_TEST` for the CLI mock,
  and **file a new follow-up FU-11.5.a mirroring FU-7.10.a** so the
  same gap is tracked symmetrically. **Do not** widen scope to wire
  forward-pass here — that's an explicit cross-sprint deferral and
  attempting it would balloon to a forward+backward+tokenizer integration
  that belongs in its own story.
- **R2 — `log(1 - exp(logp))` numerical hazard (MED / SMALL).** When
  `logp` is close to 0 (model nearly certain on chosen), `1 - exp(logp)`
  underflows. **Mitigation:** clamp `logp ≤ -HU_ORPO_LOG1MEXP_FLOOR`
  (e.g. `-1e-12`) before the `log1mexp`. Add a dedicated test
  `test_orpo_loss_floor_at_high_confidence` (analogous to SimPO's
  floor test — see FU-7.10.f as a reminder to make the fixture
  *physically plausible*, not artificially positive). Use `log1p(-exp(x))`
  rather than `log(1.0 - exp(x))` for precision when `logp` is very
  negative.
- **R3 — Backward compat with US-7.10 CLI behavior (LOW / MEDIUM).**
  The split of the `orpo || grpo2` branch is the riskiest line — if
  the implementer accidentally drops the `grpo2` path, AC-11.5.5
  silently breaks. **Mitigation:** AC-11.5.5 already maps to an
  existing test (`test_rl_train_unimplemented_algorithms`); do not
  modify or weaken that test. Run it after the CLI edit and before
  declaring done.
- **R4 — Fixture authoring drift (LOW / SMALL).** Hand-computed
  expected values can disagree with the implementation if the
  precedence order of operations differs. **Mitigation:** put the
  Python derivation as a comment block at the top of the fixture file
  (the precedent is `tests/fixtures/simpo_golden.json`'s Python
  comment per US-7.10 design §3.1). Use double-precision in both
  Python and C; never `float`.
- **R5 — Cross-agent regression on SimPO golden test (LOW / LARGE).**
  Adding a sibling TU that includes the same header could surface a
  latent ODR or static-vtable-name clash. **Mitigation:** all
  internal symbols in `rl_trainer_orpo.c` are `static`; vtable
  variable is `static const hu_rl_trainer_vtable_t HU_ORPO_VTABLE`
  (mirrors `HU_SIMPO_VTABLE`). The existing SimPO suite must
  continue passing under `--filter=simpo` after the change (AC-11.5.4).
- **R6 — Observability (LOW / SMALL).** Mock loss path emits
  `[rl-train] orpo test mode: loss=...` for the CLI test; production
  NOT_SUPPORTED branch must emit a clear error message naming
  FU-11.5.a so a user reading stderr knows where the gap is.
  **Mitigation:** copy SimPO's stderr line verbatim, replacing
  "simpo" with "orpo".

## 7. Sequencing

The implementation walks down the file plan top-to-bottom and is
strictly additive at each step (skeleton-first, behavior-second, CLI
last). This keeps every step reversible:

1. Header (compile only, no behavior).
2. Skeleton TU + CMake registration (link only, returns 0.0 loss).
3. Fixture + golden test that fails on the skeleton.
4. Implement loss math; golden test passes.
5. Edge tests (AC-11.5.3 diminishing-OR, SFT-only special case,
   invalid lambda, deinit-idempotent).
6. CLI wiring + `--lambda-orpo` flag + help text edit.
7. `test_orpo_train_exits_0` + re-run
   `test_rl_train_unimplemented_algorithms`.
8. Full suite + ASan + Werror.
9. `/verify`.
10. File FU-11.5.a in `sprints/sprint-11/followups.md` documenting the
    NOT_SUPPORTED-in-production gap and pointing at FU-7.10.a as
    precedent.

No cleanup of legacy code — US-7.10 left no dead branches; the orpo
branch in cli.c is the one node that splits.

## 8. Test strategy

- **Unit** — `tests/test_rl_trainer_orpo.c` is the load-bearing
  surface (5 tests). The 1e-4 tolerance is identical to SimPO; the
  hand-computable fixture keeps it deterministic.
- **CLI integration** — `tests/test_ml_cli_rl_train.c` gets one new
  test (AC-11.5.1) and the existing unimplemented-algorithms test
  remains the AC-11.5.5 guard.
- **No real model weights in CI** — `train_step` is mocked under
  `HU_IS_TEST`, matching the SimPO pattern (rl_trainer_simpo.c
  lines 80–88). Zero new fuzz harnesses; the input space is small
  doubles.
- **ASan + Werror** — covered by `cmake --preset dev`.

## 9. Open questions

1. **Should `--lambda-orpo` also be accepted as `--beta` for symmetry
   with SimPO?** The story names it `--lambda-orpo` explicitly
   (AC-11.5.1). Keep that spelling; do not add aliases. The research
   doc (sota-dpo.md line 57) calls the ORPO hyperparameter `lambda`,
   so the flag spelling is correct and unambiguous.
2. **Should this story file FU-11.5.a for the production forward-pass
   gap?** Recommend yes; it is the only honest way to keep symmetry
   with FU-7.10.a and avoid claiming a production-ready feature that
   exits NOT_SUPPORTED. Already listed in §6 R1 and §7 step 10.
3. **Is `compute_loss` allowed to accept `rejected_token_count == 0`
   as "SFT-only mode"?** AC-11.5.2 reads `{prompt, chosen}` (no
   rejected). Two interpretations: (a) the *training data schema*
   doesn't need rejected (Hong et al. §3.3 — generate rejected from
   the model itself), or (b) the in-memory `hu_pref_pair_logprobs_t`
   accepts `rejected_token_count == 0` and degrades to SFT. We
   implement (b) — it's the cheaper interpretation and the AC text
   reads naturally as "loss equals NLL + λ · OR_penalty, where
   OR_penalty == 0 when no rejected." If the product owner intended
   (a), this is a no-op extra robustness; if (b), it's the required
   behavior. Implementer should comment-cite this paragraph at the
   `if (rejected_token_count == 0)` branch.
4. **Should ORPO appear in `hu_rl_trainer_type_name`?** Already does
   (rl_trainer.c line 30). No change needed. FU-7.10.e (missing
   `default:` arm) is orthogonal; do not roll into this story.
