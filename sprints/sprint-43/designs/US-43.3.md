## Approach

Add a NEW translation unit `src/channels/imessage_courtesy.c` (do not bloat the 4444-line `imessage.c`). It exposes a **pure predicate** `hu_imessage_should_courtesy_reply` over 4 boolean inputs (matching `.claude/rules/security-predicate-extraction.md`), plus three impure helpers (dedup-log open-with-flock, record-reply, sanitize-handle). The predicate is the entire security decision; the helpers are tiny I/O wrappers. Public header: `include/human/channels/imessage_courtesy.h`.

Wire from `src/channels/imessage.c` at the inbound-message dispatch point where the existing allowlist check decides "drop". Concretely: today at `imessage.c:3905-3908` the `if (!allowed) { c->last_rowid = rowid; continue; }` branch silently drops. The new path keeps that drop for ingestion (do NOT promote the message into the agent's inbox), BUT first calls courtesy-eval and may enqueue a reply onto the side-channel ring. The sequence:

1. Check `config->courtesy_replies_enabled` (default true).
2. Acquire `flock(LOCK_EX)` on `~/.human/imessage_courtesy.log` (`O_RDWR|O_CREAT`, mode 0600).
3. Scan the log for `<handle>\t<epoch_secs>` lines; compute `hours_since_last_reply` and `aggregate_today` under the lock.
4. Call `hu_imessage_should_courtesy_reply(false, hours, aggregate_today, dedup_io_ok)`.
5. **Before unlock**, if the predicate is true: append `<handle>\t<now>\n`, `fflush`, `fsync`, then unlock. This holds the lock across the check-record window, closing the TOCTOU gap.
6. Enqueue the reply text into a `pending_courtesy` ring (separate from inbound message processing) which the agent loop drains via `hu_imessage_drain_pending_courtesy()`. This avoids re-entrancy in the polling thread.

Side-channel buffer (not inline send) because the iMessage poll thread already holds `chat.db` cursors; performing AppleScript / `osascript` send inline would block the poller and risk reentry on poll-error retry.

**Day boundary:** `aggregate_today` uses `floor(epoch_secs/86400)` in UTC. Document in tests that 50/day resets at UTC midnight (not local), which is conservative for spoof-spam (cap is more restrictive in user's TZ if they live west of UTC). Acceptance: tests assert the UTC-boundary behavior; a sliding 24h window is rejected as more expensive (full log scan vs. day-bucket counter).

**Handle sanitization:** before reply text is composed, strip handle-shaped patterns from any name. Specifically, if the inbound `sender_name` starts with `+`, contains `@`, or matches `^[0-9 ()+\-]+$`, substitute the literal string `"there"` in the template. The reply text itself NEVER contains the inbound handle.

**Operator audit surface:** No `aspect-panel` subsystem exists in this repo. The DoD substitutes a 5-perspective specialized-verifier review for this story (see DoD section below). Empirically observable side effects (the dedup log + agent-loop drain trace) serve as the operational audit trail; no new audit-log dependency on `src/security/*` (prohibited).

## Risks

- **Mass-spam outbound (HIGH/LARGE).** Predicate bug → courtesy reply storm to a spoofed handle. Mitigations: pure predicate with truth-table tests; flock TOCTOU closure; fail-CLOSED on dedup I/O error (AC-43.3.4); 50/day aggregate cap; operator opt-out flag; 5-perspective verifier review. **Second-engineer review required before merge.**
- **TOCTOU between check and record (HIGH/LARGE).** Mitigation: hold `flock(LOCK_EX)` across read-eval-write-fsync-unlock. Test pattern: race via child process gated by `HU_IS_TEST`; assert exactly one wins.
- **Dedup-file I/O ambiguity (MED/LARGE).** Code path: `open(O_RDWR|O_CREAT, 0600)` — if returns -1, set `dedup_io_ok=false`. ENOENT is impossible with `O_CREAT`; permission/IO errors fail-closed. Predicate AC-43.3.4 codifies this.
- **UTC day boundary (LOW/MED).** Rolls at 00:00 UTC; a determined spoofer hits 50 at 23:59 UTC + 50 at 00:01 UTC = 100/24h. Sliding window rejected (full-log scan per inbound, more code, more lock-time). Documented in tests.
- **Agent-loop reentry (MED/MED).** Mitigation: side-channel `pending_courtesy` ring drained ONLY by agent loop (not the poll thread).
- **Handle-shaped impersonation (MED/MED).** Mitigation: sanitizer (AC-43.3.5); test pins.
- **Config flag default (LOW/SMALL).** Default true ships courtesy replies for existing users on upgrade. Intended product behavior per US-43.3, flagged here so review notices.
