# Design for US-43.1: Homebrew formula auto-update + smoke

## Status
DESIGN — ready for implementer

## Approach (provisional)
Three scripts + two release-workflow jobs. The `Formula/human.rb` is already a stub; we mutate ONLY two fields at release time (`version` and the three per-arch `sha256` values) by reading `sha256sums.txt` from the just-uploaded GitHub release. No structural Ruby edits. The update is gated by an idempotent shell script with a strict all-or-nothing contract. A separate macOS smoke job installs `--build-from-source` against the freshly-updated tap and asserts `human --version` matches the git tag exactly. Concurrency-guarded so two release runs cannot race the tap.

We deliberately defer bottling to US-42.4 (signing). A `TODO(US-42.4)` comment is left at the `bottle do` insertion site so the next sprint can drop in pre-built bottles without re-deriving the formula shape.

## Implementation steps

1. Write `tests/test_update_formula_hashes.sh` first (10+ cases). All should fail with "script not found."
2. Write `scripts/update-formula-hashes.sh`. Contract:
   - Args: `--formula <path> --version <semver> --sha256sums <path>`
   - All three of `human-<version>-darwin-arm64.tar.gz`, `human-<version>-darwin-amd64.tar.gz`, `human-<version>-linux-x86_64.tar.gz` MUST be present in `sha256sums.txt`. Missing any → exit 1, formula unchanged.
   - Semver regex: `^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$`. Reject anything else.
   - Write to a tempfile, validate the resulting formula re-parses (`brew style` or simple `ruby -c`), then `mv` atomically.
   - Idempotent: re-running with same inputs produces byte-identical output.
3. Run tests; iterate until all 10+ pass.
4. Write `scripts/check-formula-install.sh`. Contract:
   - Args: `--tap <owner/repo> --tag <vX.Y.Z>`
   - `brew tap "$tap"`, `brew install --build-from-source <tap>/human`, then `actual=$(human --version | awk '{print $NF}')`; assert `"$actual" == "${tag#v}"` (strict). Fail loudly with both values on mismatch.
5. Add `update-tap` job to `release.yml`:
   - Depends on existing release-artifact-upload jobs.
   - `concurrency: { group: tap-update, cancel-in-progress: false }` — prior session caught a race where two releases stomped each other.
   - Checks out tap repo via PAT (env-bound), runs `scripts/update-formula-hashes.sh`, commits + pushes.
   - All `${{ ... }}` expressions bind to `env:` first (workflow-injection safety; never inline into `run:`).
6. Add `brew-install-smoke` job: `runs-on: macos-15`, `needs: update-tap`, runs `scripts/check-formula-install.sh`.
7. Drop `TODO(US-42.4)` comment in `Formula/human.rb` at the position where `bottle do … end` belongs (between `url` and `depends_on`).

## Risks

- **Tap-update race (MED/LARGE → MITIGATED)**: two concurrent release runs both `git push` to the tap. Mitigation: `concurrency.group: tap-update`, `cancel-in-progress: false` so the second waits for the first.
- **Partial `sha256sums.txt` (MED/MED → MITIGATED)**: one arch upload failed but two succeeded; naive updater would write a half-good formula. Mitigation: all-or-nothing contract; script exits 1 with formula untouched if ANY of the three required entries are missing.
- **Workflow injection via tag name (LOW/LARGE → MITIGATED)**: `github.ref_name` interpolated into `run:` could execute arbitrary code on tag push. Mitigation: bind ALL `${{ }}` to `env:` first, then reference `$ENV_VAR` in `run:`.
- **Semver drift (LOW/MED → MITIGATED)**: tag `v1.2.3-rc.1` should be accepted; `1.2.3.4` should not. Mitigation: explicit regex, test cases for both.
- **Formula re-parse failure (LOW/MED → MITIGATED)**: a SHA with weird chars or version with quote would break Ruby parsing. Mitigation: `ruby -c` on the tempfile before atomic `mv`; reject on parse failure.
- **macOS runner version drift (LOW/SMALL)**: `macos-latest` flips and breaks the smoke job. Mitigation: pin `macos-15` explicitly.
- **Tap PAT scope (LOW/LARGE)**: over-scoped token leaks. Mitigation: separate `HOMEBREW_TAP_TOKEN` secret with `contents:write` on the tap repo only; document in workflow comments.
- **Bottle deferral (LOW/SMALL)**: users may expect pre-built bottles. Mitigation: `--build-from-source` works today; `TODO(US-42.4)` marks the upgrade path.

## Test strategy

- `tests/test_update_formula_hashes.sh`: shell-driven, fixture-based. Each case sets up a tmpdir with a stub formula + a `sha256sums.txt` fixture, invokes the script, asserts both the exit code AND the resulting formula contents (or unchanged-on-failure).
- 10+ cases enumerated in step 2.
- `scripts/check-formula-install.sh` itself is the test for the smoke contract; runs only in CI on `macos-15`.
- No new C tests; this is shell + workflow.

## Workflow-injection safety contract

Every `${{ github.* }}`, `${{ inputs.* }}`, `${{ secrets.* }}` expression in the new workflow jobs MUST be bound to `env:` at the step or job level, then referenced as `$VAR` in `run:`. Inline `${{ }}` inside `run:` is forbidden. Reviewer to grep diff for `\${{` inside `run: |` blocks; zero matches required.

## Acceptance criteria mapping

- AC: formula updates atomically on release → `update-tap` job + all-or-nothing script + `ruby -c` validation
- AC: smoke install succeeds and version matches → `brew-install-smoke` job + `check-formula-install.sh` strict equality
- AC: idempotent re-runs safe → test case `idempotent_rerun_byte_identical`
- AC: partial sha256sums.txt rejected → test case `missing_one_arch_exits_nonzero_formula_unchanged`
- AC: workflow-injection safe → grep gate in PR review; documented in this doc
- AC: bottle deferred to US-42.4 → `TODO(US-42.4)` comment in `Formula/human.rb`

## Out of scope

- Bottling / signing (US-42.4)
- Non-Homebrew distros (apt, dnf, scoop) — separate stories
- Auto-bump PR to homebrew-core (we only update our own tap)
- Notarization (US-42.4)
- Rollback automation — manual `git revert` on the tap is sufficient at this stage

## Implementer pointers

- `Formula/human.rb` already exists as a stub — read it before editing; only mutate `version` and the three `sha256` lines (per-arch via `on_macos`/`on_linux` blocks or `if Hardware::CPU.arm?` — match what's already there).
- Existing `release.yml` likely already produces `sha256sums.txt` from `shasum -a 256 *.tar.gz > sha256sums.txt`; reuse that artifact, do NOT re-derive.
- For the `${{ }} → env:` discipline, mirror the pattern used in existing CI workflows in this repo.
- `set -euo pipefail` + `IFS=$'\n\t'` at the top of both new scripts.
