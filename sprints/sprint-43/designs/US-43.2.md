# Design for US-43.2: Onboard Post-Success Next-Step Message

Status: DESIGN_READY

## Approach

Extract the post-onboard "next step" UX message into a **pure formatter**
`hu_onboard_nextstep_format(bool imessage_paired, bool persona_set, bool ollama_ok, bool brew_installed, char *buf, size_t buflen)` declared in `include/human/onboard.h` and defined in `src/onboard.c`. The function maps the 4-boolean input space to exactly **5 distinct outputs** (one fallback + four positive variants), each pinned by `strcmp` in tests.

Both production call sites (`src/cli_commands.c::cmd_init` ~lines 248–258, and `src/onboard.c::hu_onboard_run_with_args` ~lines 519–523) replace their hard-coded `printf` blocks with `hu_onboard_nextstep_format` → `fputs` to stdout. **Both call sites MUST check the formatter's return code** and on non-OK emit `fprintf(stderr, "warning: nextstep formatter returned %d; user prompt may be truncated\n", rc)`. The prototype is annotated `__attribute__((warn_unused_result))` so silent-swallow is a `-Werror` compile failure rather than a code-review trust exercise.

This applies the **security-predicate-extraction** pattern (`.claude/rules/security-predicate-extraction.md`) to UX text: the decision lives in a pure, reproducible, side-effect-free function whose truth table is pinned by unit tests without spawning an onboard process.

### Design Decision: error code for short-buffer (AC-43.2.3)

The story's AC-43.2.3 names `HU_ERR_BUFFER_TOO_SMALL`. **That enum value does not exist in `include/human/core/error.h`** (confirmed by direct read of the full `hu_error_t` declaration). Per `.claude/rules/quality-gates.md` and the user-supplied critic guidance, **we do NOT invent a new error code**. We reuse **`HU_ERR_IO`** — semantically, truncation when writing into an output stream-buffer is an I/O-shaped failure on the output sink, which is the closest existing code in the enum (`HU_ERR_PARSE`, `HU_ERR_INVALID_ARGUMENT`, and `HU_ERR_CONFIG_INVALID` all mean something else). Rationale recorded here so the implementer doesn't re-litigate it: the AC's *spirit* (return a distinct non-OK code, log a diagnostic, no silent truncation) is preserved; the *letter* (the specific enum name) is satisfied by the closest existing code. The test for AC-43.2.3 asserts `HU_ASSERT_EQ(rc, HU_ERR_IO)` and includes an inline `/* See sprints/sprint-43/designs/US-43.2.md "Design Decision" */` comment.

## Truth table (the contract)

Inputs are the 4 booleans named in the ACs (`imessage_paired`, `persona_set`, `ollama_ok`, `brew_installed`). The 5 output ids correspond to the 5 `strcmp`-distinct outputs AC-43.2.2 mandates.

| imessage_paired | persona_set | ollama_ok | brew_installed | Output id          | Required substring(s)                     | Forbidden substring(s)             |
|-----------------|-------------|-----------|----------------|--------------------|-------------------------------------------|------------------------------------|
| true            | true        | true      | true           | `all_ready`        | `"human chat"`                            | `"setup"`, `"configure"` (AC-43.2.1) |
| true            | true        | true      | false          | `chat_no_brew`     | `"human chat"`                            | (none)                             |
| true            | true        | false     | —              | `chat_cloud`       | `"human chat"`, `"cloud"`                 | (none)                             |
| false           | true        | —         | —              | `pair_imessage`    | `"human channel pair imessage"`           | (none)                             |
| —               | false       | —         | —              | `fallback_bare`    | `"human onboard"`                         | must NOT `strcmp`-match any above  |

Note: inputs are not fully independent — `persona_set=false` short-circuits to `fallback_bare`, and `imessage_paired=false` (with `persona_set=true`) short-circuits to `pair_imessage`. The precedence ladder is documented in the formatter's doc comment in `include/human/onboard.h`.

AC-43.2.4 (no output matches the old generic `"You're all set"`) is pinned by 5 separate `strstr(buf, "You're all set") == NULL` assertions — one per output.

## Implementation steps (for the implementer)

1. Add prototype to `include/human/onboard.h` with the truth-table table embedded in the doc comment, `warn_unused_result` attribute, and the `HU_ERR_IO` return-code contract for short-buffer.
2. Create `tests/test_onboard.c` with all 10 test stubs returning failure; wire `run_onboard_tests` into `tests/test_main.c` and register the source in `CMakeLists.txt`. Run full suite — all 10 new tests FAIL, everything else PASSES.
3. Implement `hu_onboard_nextstep_format` returning `HU_ERR_INVALID_ARGUMENT` for NULL buf / zero buflen; make Test 6 (NULL-buf) and Test 3 (short-buffer → `HU_ERR_IO`) pass first.
4. Implement the 5 truth-table rows one at a time; make each `strcmp` / `strstr` assertion pass (Tests 1, 2, 5, 8, 9).
5. Add the adversarial assertions: each of the 5 outputs satisfies `strstr(buf, "You're all set") == NULL` AND `all_ready` satisfies `strstr(buf, "setup") == NULL && strstr(buf, "configure") == NULL` (Tests 1, 4).
6. Wire `src/onboard.c::hu_onboard_run_with_args` post-success block: replace lines 519–523 with `hu_config_load`-verify (post-`fclose`) → derive `persona_set` from parse result → call `hu_onboard_nextstep_format` → on non-OK rc emit stderr warning → `fputs(buf, stdout)`.
7. Same wiring in `src/cli_commands.c::cmd_init` at lines 248–258.
8. Run full suite: `cmake --build --preset dev && ./build/human_tests`. Must be 0 failures, 0 ASan errors.
9. Run gates: `scripts/check-test-references.sh`, `scripts/check-test-source-gate-symmetry.sh`, `scripts/agent-preflight.sh`.
10. `git grep -n "You're all set" -- src/` — confirm zero occurrences in `src/` after the swap; only `tests/test_onboard.c` should mention the string (as the adversarial-absent pin).

## Risks

- **Error-code naming conflict (LOW/SMALL).** Story AC names `HU_ERR_BUFFER_TOO_SMALL`, which does not exist. Mitigation: documented Design Decision above; reuse `HU_ERR_IO`. If a future code change wants a dedicated short-buffer code, it's an independent refactor across the codebase, not a US-43.2 scope item.
- **Test pins bug (LOW/SMALL).** Per `.claude/rules/tests-that-pin-bugs.md`, the adversarial tests assert OLD generic message `ABSENT` via `strstr(buf, "<old>") == NULL`, not "new text present" — pinning both directions. Five total negative assertions for "You're all set" + the AC-43.2.1 "setup"/"configure" absent pair on `all_ready`.
- **Silent-swallow regression at call sites (MED/MED).** A future caller might forget the rc-check. Mitigation: `__attribute__((warn_unused_result))` on the prototype turns the omission into a `-Werror` compile failure (CI enforced).
- **`hu_config_load` verifies the wrong file (LOW/SMALL).** `hu_config_load` reads `~/.human/config.json` from the env-derived path — the same path `cmd_init` and `onboard_run` just wrote. Truncation surfaces as `HU_ERR_PARSE` or `HU_ERR_CONFIG_INVALID`. Mitigation: treat ANY non-`HU_OK` from `hu_config_load` as `persona_set=false` and let the formatter fall through to `fallback_bare`.
- **Backward compat (LOW/SMALL).** No external script / doc / test currently greps for "You're all set" or any of the existing post-success strings (will be verified by `git grep` in step 10). New strings are distinct so `strcmp`-distinctness cannot collide with anything pre-existing.
- **Observability (LOW).** stderr warning is the user-visible signal on rc-fail; no other channel needed for a CLI flow.
- **Cross-input plumbing (LOW).** The formatter takes booleans, not strings, so cross-platform mapping (provider→`ollama_ok`, `is_apple_provider`→branch hint) lives in the caller. Out of scope for the formatter; in scope for the two call sites (uses existing `is_apple_provider` helper at `src/onboard.c:292`).

## Test strategy

All tests in **`tests/test_onboard.c`** (new file). Suite name: `onboard_nextstep`. No `HU_IS_TEST` guard required (pure formatter).

| # | Test | AC mapped |
|---|---|---|
| 1 | `nextstep_all_ready_contains_human_chat_no_setup_no_configure` | AC-43.2.1 |
| 2 | `nextstep_fallback_bare_strcmp_distinct_from_other_four` | AC-43.2.2 |
| 3 | `nextstep_buffer_one_byte_short_returns_HU_ERR_IO` (cites Design Decision) | AC-43.2.3 |
| 4 | `nextstep_no_output_matches_old_youre_all_set_text` (5 negative `strstr==NULL` pins) | AC-43.2.4 |
| 5 | `nextstep_all_five_outputs_strcmp_distinct` | AC-43.2.2 |
| 6 | `nextstep_null_buf_returns_HU_ERR_INVALID_ARGUMENT_no_crash` | hardening |
| 7 | `nextstep_buf_always_nul_terminated_even_on_truncation` | hardening |
| 8 | `nextstep_pair_imessage_output_mentions_pair_command` | AC-43.2.1 sibling |
| 9 | `nextstep_chat_cloud_output_mentions_cloud` | AC-43.2.1 sibling |
| 10 | `nextstep_round_trip_call_site_onboard_run_emits_one_of_five` | AC-43.2.5 |

Test 10 is an integration-shaped test that captures stdout from a controlled invocation of the onboard post-success branch (using existing `HU_IS_TEST` test fixtures) and asserts the captured string `strcmp`-equals exactly one of the 5 formatter outputs. If the existing test fixtures can't capture the call-site stdout cleanly, downgrade Test 10 to a static `git grep` CI assertion that both call sites invoke `hu_onboard_nextstep_format` and check the return.

- Rich-text / ANSI formatting.
- Dynamic persona-name substitution.
- Renaming or adding `HU_ERR_BUFFER_TOO_SMALL` to `hu_error_t` (would be a cross-codebase refactor; see Design Decision).
- Refactoring the rest of `hu_onboard_run_with_args` outside the post-success block (lines 519–523).
- Telemetry for which branch fired.
