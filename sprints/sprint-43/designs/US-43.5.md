# Design for US-43.5: chat.db Locked Diagnostic

## Approach

Add a pure formatter `hu_imessage_diag_from_poll_status(alloc, json_blob, out)` exported from `include/human/doctor.h`. It parses a poll-status JSON blob (same shape `hu_doctor_check_imessage` already reads), maps the embedded `last_error_class` string field through the existing `hu_imessage_error_class_t` enum (`include/human/channels/imessage.h`), and emits a single user-actionable string per class.

Inside `doctor.c`, replace the existing free-form lines that report iMessage errors with calls to this function. The prior session shipped without wiring the two live-SQLite branches; this design explicitly routes them through the same predicate:

- **Branch A (poll-status JSON file)** at `src/doctor.c:601` — currently formats messages from the `err_class` string read out of the status file.
- **Branch B (live `sqlite3_prepare_v2` / `sqlite3_step` error)** at `src/doctor.c:503-514` — currently emits a hardcoded "Full Disk Access likely revoked" string regardless of class.
- **Branch C (live `sqlite3_open_v2` error)** at `src/doctor.c:518-529` — currently uses a ternary that only branches on AUTH; BUSY/CANTOPEN/OTHER all collapse to "see sqlite docs".

All three must call into the new formatter (or share an internal helper that constructs a poll-status-shaped JSON synthetically from the live `cls` value, then routes through the formatter).

Per AC-43.5.5, the `--json` doctor output gains both `category` (existing) and `error_class` (new, raw enum name via `hu_imessage_error_class_name`).

Critical structural constraint per AC-43.5.5 and prior critic feedback: REUSE the existing `hu_imessage_error_class_t` enum. Do NOT introduce a parallel enum.

## Design Decision: how the formatter receives the error class

CONFIRMED gap on read of `include/human/channels/imessage.h` and `src/channels/imessage*.c`: **no `hu_imessage_error_class_from_name` helper exists today**. The header exports the forward direction (`hu_imessage_error_class_name(cls) -> const char *`) but not the inverse. The story's tagline says "ROUTES class -> user-actionable message" — it does NOT prescribe the input shape. Two viable shapes:

### Option A (RECOMMENDED): Add `hu_imessage_error_class_from_name`

Add a small pure helper to `include/human/channels/imessage.h`:

```c
/* Inverse of hu_imessage_error_class_name. Returns HU_IMESSAGE_ERR_OTHER
 * for unrecognized or NULL input. */
hu_imessage_error_class_t hu_imessage_error_class_from_name(const char *name);
```

Implementation: 6-line string-comparison switch in the same `.c` where `hu_imessage_error_class_name` lives. Reusable: any caller with a serialized class string (status file, JSON output, log line) can roundtrip through it. The formatter then takes the JSON blob, extracts `last_error_class` via the existing `doctor_imsg_status_extract_str`, calls the new helper, switches on enum.

Pros:
- Pure inverse pairs naturally with `hu_imessage_error_class_name` — same module, same testable shape.
- Symmetric for any future code that needs to deserialize the class.
- Pinable with a 5-line unit test (one per enum variant + one NULL/garbage).

Cons:
- Adds one symbol to the public iMessage header. Small surface; matches existing pattern.

### Option B: Formatter takes the enum directly

Skip the JSON parse — make the public API `hu_imessage_diag_from_class(alloc, hu_imessage_error_class_t cls, out)`. Live-SQLite call sites (Branches B & C) already have `cls` in hand. Poll-status branch (A) calls the existing `doctor_imsg_status_extract_str` then a private 6-line string-to-enum helper local to `doctor.c`.

Pros:
- No new public symbol.
- Faster code path; no re-parsing the JSON.

Cons:
- The story's task prompt names the function `hu_imessage_diag_from_poll_status(alloc, json_blob, out)` — explicitly JSON-shaped. Option B renames it.
- Inverse-class-name logic still has to live somewhere; making it a private helper in `doctor.c` is less reusable.

### Decision

**Go with Option A.** It matches the function signature in the task prompt verbatim, keeps the inverse helper reusable, and the unit-test surface is identical either way. If the implementer pushes back during execution because the public-header addition feels heavy, Option B is the documented fallback — no further design review needed.

## Implementation steps (for the implementer agent)

1. Add `hu_imessage_error_class_from_name(const char *name)` to `include/human/channels/imessage.h` and implement in the same `.c` where `hu_imessage_error_class_name` lives. Default to `HU_IMESSAGE_ERR_OTHER` for NULL or unrecognized input.
2. Declare `hu_error_t hu_imessage_diag_from_poll_status(const hu_allocator_t *alloc, const char *poll_status_json, char **out)` in `include/human/doctor.h`. Returns `hu_error_t`; `*out` is owned by caller, freed via `alloc->free`. On `HU_IMESSAGE_ERR_NONE` (or missing field) set `*out = NULL` and return `HU_OK`.
3. Implement in `src/doctor.c`. Use the existing `doctor_imsg_status_extract_str` to pull `last_error_class`, map via `hu_imessage_error_class_from_name`, switch on enum.
4. Write the 5 branch strings:
   - AUTH -> "iMessage poll denied: grant Full Disk Access to human in System Settings > Privacy & Security > Full Disk Access."
   - BUSY -> "iMessage chat.db is busy: Messages.app may be syncing. Retry in a few seconds; persistent failure indicates an iCloud sync issue."
   - CANTOPEN -> "iMessage chat.db not found at ~/Library/Messages/chat.db. Open Messages.app at least once to initialize the database."
   - NONE -> return `HU_OK` with `*out = NULL` (no diagnostic).
   - OTHER -> `"iMessage poll failed: unclassified SQLite error (class=%s)"` via `hu_imessage_error_class_name`.
5. Write `tests/test_imessage_diag.c` with the 8 assertions in Test strategy. Each test builds a small JSON literal (`"{\"last_error_class\":\"AUTH\"}"` etc.), calls the formatter, asserts on output via `strstr`.
6. Wire formatter into `hu_doctor_check_imessage`. Three call sites — REPLACE all three; do NOT leave any fall-through to old strings:
   - **Branch A** (`src/doctor.c:601-625`, poll-status JSON read): call formatter with the `blob` variable already in scope. Keep the existing circuit-breaker line; only replace the per-class diagnostic.
   - **Branch B** (`src/doctor.c:503-514`, `sqlite3_prepare_v2`/`sqlite3_step` error): synthesize a minimal JSON `{"last_error_class":"<name>"}` using `hu_imessage_error_class_name(cls)`, pass to formatter.
   - **Branch C** (`src/doctor.c:518-529`, `sqlite3_open_v2` error): same synthesis pattern.
7. Add `error_class` field to `--json` output. Locate the doctor JSON emitter; add `error_class` alongside the existing `category` key for iMessage diag items.
8. Pre-commit audit: `grep -n 'sqlite3_errmsg\|sqlite3_open\|sqlite3_prepare\|Full Disk Access\|Messages.app' src/doctor.c` — confirm only the new formatter contains those keywords (no orphan strings remain).
9. Run `./build/human_tests --suite=imessage_diag` then the full suite.

## Risks

- **Backward compat (LOW/SMALL)**: changes free-form lines users may have grepped. Doctor output is human-facing diagnostic text; the JSON field is additive.
- **Cross-contamination (HIGH/HIGH — mitigated by tests)**: AUTH/BUSY messages must not leak each other's keywords. Mitigated by `strstr == NULL` adversary tests at AC-43.5.1 and AC-43.5.2. Critic-load-bearing per prior sprint feedback.
- **Missed call sites (MEDIUM/MEDIUM — was HIGH last time)**: prior session shipped without wiring Branches B & C. Mitigated by: (a) Implementation Step 6 explicitly naming line ranges; (b) Step 8 grep audit; (c) the cross-contamination tests will fail loudly if Branch B's hardcoded "Full Disk Access likely revoked" survives on a BUSY input.
- **JSON contract (LOW/SMALL)**: `error_class` is a new field. Schema is additive.
- **Parallel enum (LOW/HIGH if it fires)**: implementer might re-declare an enum locally. Mitigated by AC-43.5.5 explicit test that calls `hu_imessage_error_class_name` from `include/human/channels/imessage.h` directly, and by Option A using the same module for `_from_name`.
- **Test gate symmetry (LOW/MEDIUM)**: `src/channels/imessage.c` is gated by `HU_ENABLE_IMESSAGE`. The new test calls `hu_imessage_error_class_from_name` from that gated source. Per `.claude/rules/test-source-gate-symmetry.md`, gate `tests/test_imessage_diag.c` registration in CMake under the same flag OR use the internal-`#ifdef`-wrap-with-stub-runner pattern. Recommend CMake-level gate for parity with `test_imessage_*.c` files already present.

## Test strategy

Unit tests in `tests/test_imessage_diag.c` (no SQLite, no filesystem, no network — pure string-in / string-out):

1. `imessage_diag_auth_contains_full_disk_access` — AC-43.5.1 positive, asserts `strstr(out, "Full Disk Access")`
2. `imessage_diag_auth_does_not_mention_syncing` — AC-43.5.1 adversary, `strstr(out, "Messages.app may be syncing") == NULL`
3. `imessage_diag_busy_contains_syncing` — AC-43.5.2 positive
4. `imessage_diag_busy_does_not_mention_full_disk_access` — AC-43.5.2 adversary, `strstr(out, "Full Disk Access") == NULL` AND `strstr(out, "permission") == NULL`
5. `imessage_diag_cantopen_contains_chat_db_and_path_hint` — AC-43.5.3, asserts `"chat.db"` and `"~/Library/Messages"`
6. `imessage_diag_none_returns_null_output` — AC-43.5.4, `*out == NULL`, return `HU_OK`
7. `imessage_diag_other_uses_class_name` — AC-43.5.5, output contains `"OTHER"` (or whatever `hu_imessage_error_class_name(HU_IMESSAGE_ERR_OTHER)` returns)
8. `imessage_diag_json_emits_category_and_error_class` — integration-light: builds a doctor JSON output via the doctor entry point, asserts both `"category"` and `"error_class"` appear in JSON
9. (bonus, single-line) `imessage_error_class_from_name_roundtrip` — pin Option A: for each enum variant, assert `hu_imessage_error_class_from_name(hu_imessage_error_class_name(v)) == v`, and `hu_imessage_error_class_from_name(NULL) == HU_IMESSAGE_ERR_OTHER`

Test references the production symbol `hu_imessage_diag_from_poll_status` from `human/doctor.h` (implied module: `doctor`), satisfying `check-test-references.sh`.

## Out of scope

- Automatic remediation (granting FDA programmatically) — explicit story non-goal.
- Linux / Windows iMessage proxies — explicit story non-goal.
- Schema versioning of the `--json` output — additive change only.
- New `hu_imessage_error_class_t` variants — story locks the existing 5 (NONE, AUTH, CANTOPEN, BUSY, OTHER).
- Modifying `hu_imessage_error_class_name` — already exists; do not duplicate.
- Re-architecting the doctor JSON emitter — only the per-iMessage-item shape changes (add `error_class` key).
