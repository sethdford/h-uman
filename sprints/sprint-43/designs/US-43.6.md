# Design for US-43.6: Website Install Drift Detector

**Story**: US-43.6 — Website install drift detector (P2, XS, LOW risk)
**Branch**: `sprint-43-distribution-mvp`
**Worktree**: `/Users/sethford/Documents/h-uman/.worktrees/sprint-43-distribution`

## Approach

The website currently risks displaying a stale install command or version
that drifts from `Formula/human.rb` (the Homebrew tap formula). A user
copying `brew install …/human@0.4.2` when the formula has moved to `0.5.0`
creates support friction and erodes credibility.

The cheapest fix is a **single source of truth JSON file** that both the
Astro component AND a drift-detection script read. The script parses
`Formula/human.rb` and asserts JSON-vs-formula equality at CI time. A
Vitest source-grep test enforces that no Astro component contains a
hard-coded semver literal — that's what would let drift creep back in.

The "verified" badge state is held in the same JSON, in a field only the
release workflow (`release.yml`, after US-43.1's `check-formula-install.sh`
succeeds) is allowed to write. CODEOWNERS guards the file so manual edits
cannot lie about verification status.

Alternatives considered:
- *Single Astro component reads formula directly*: requires Ruby parsing
  in the browser/SSG step or build-time formula scrape — uglier than JSON.
- *YAML*: no JSON.parse() free in Node ESM; JSON is cheaper.
- *Two files (data + verified)*: doubles the lock surface; one file with
  scoped CODEOWNERS rules is simpler.

## install.json shape (contract)

```json
{
  "tap": "sethford/human",
  "package": "human",
  "version": "0.4.2",
  "command": "brew install sethford/human/human",
  "verified": {
    "macos_arm64": {
      "ok": false,
      "timestamp": null
    }
  }
}
```

- `command` is derived but stored explicitly so the Astro component never
  has to template-construct it (one less place for drift).
- `verified.macos_arm64.ok` defaults `false`; only flipped by release.yml.

## Drift-detection script contract

`website/scripts/check-install-matches-formula.mjs`:

1. Read `Formula/human.rb` (path relative to repo root).
2. Regex out:
   - `class\s+Human\s+<\s+Formula` (sanity check — fail with `DRIFT class=missing-formula-class` if not found)
   - `version\s+"([^"]+)"` → `formula.version`
   - Tap from a leading comment line `# tap: ([^\s]+)` (convention — fail if missing with `DRIFT tap=missing-tap-comment`)
3. Read `website/src/data/install.json`, JSON.parse.
4. Compare and exit:
   - Match → exit 0, print `OK install.json matches Formula/human.rb`
   - Mismatch → exit 1, print `DRIFT field=<name> formula=<v1> install_json=<v2>` for each delta, one line per field
5. Field-named DRIFT line is the load-bearing contract for human + grep.

## Implementation steps (for implementer)

1. Create `website/src/data/install.json` with the contract shape above
   (set `version` to whatever `Formula/human.rb` currently declares).
2. Create `website/scripts/check-install-matches-formula.mjs` with the
   field-named DRIFT output. Make it executable (`#!/usr/bin/env node`).
3. Add shape test `install-json-shape.test.ts` (fails if required keys
   missing or types wrong).
4. Update the InstallBlock Astro component to import install.json and
   render `data.command` + `data.version`. Remove any hard-coded semver.
5. Add `install-binding.test.ts` — Vitest reads the Astro component file
   as a string, asserts `/\d+\.\d+\.\d+/.test(src) === false`.
6. Add CI job step: `node website/scripts/check-install-matches-formula.mjs`.
7. Add CODEOWNERS rule: `website/src/data/install.json @sethford` (or
   the release-bot identity) and same for the check script.
8. In `release.yml`, after the existing US-43.1 `check-formula-install.sh`
   succeeds on macos-arm64, write `verified.macos_arm64 = {ok: true,
   timestamp: <ISO8601>}` back to install.json and commit (or open PR).

## Risks

- **Backward compat (LOW/SMALL)**: install.json is new; the only existing
  consumer is whatever currently hard-codes the install command. The
  Astro component change is a swap; tests pin the binding.
- **Verified-badge integrity (LOW/MED)**: a manual edit to install.json
  could falsely claim `verified.macos_arm64.ok=true`. Mitigation:
  CODEOWNERS guards the file; PRs editing it require release-bot or
  named owner approval. Defense-in-depth: a CI check that fails if
  `verified.ok=true` is set in a PR whose head SHA is not a tagged
  release commit (out of scope for this XS story; surface as follow-up).
- **Formula parsing regex (LOW/SMALL)**: `version "X"` could appear in a
  comment. Mitigation: also assert `class Human < Formula` is present;
  use the FIRST `version "…"` after the class declaration line.
- **Astro source-grep false negative (LOW/SMALL)**: a date like "2026" in
  a comment would NOT match `\d+\.\d+\.\d+`, but a CSS calc like
  `1.5.0rem` would. Mitigation: the grep targets the component source,
  not CSS; an isolated false-positive becomes a doc-comment fix and
  surfaces in PR.
- **release.yml write race (LOW/SMALL)**: only one release runs at a time
  for a given version; write happens after success. No concurrency risk
  in practice.
- **Observability (LOW)**: drift detector failure prints field-named
  DRIFT line; CI log makes the cause obvious.

## Test strategy

- `install-json-shape.test.ts` — Vitest, pins required keys & types.
- `install-binding.test.ts` — Vitest, source-greps the Astro component
  for `\d+\.\d+\.\d+`, asserts no match (this is AC test D).
- `check-install-matches-formula.mjs` — exercised in CI; a small
  fixture-based smoke test is OPTIONAL for this XS story (defer).
- Manual: edit Formula version locally, run the script, confirm exit 1
  with field-named DRIFT line.

## Acceptance criteria mapping

- **AC-A (SoT exists)** → `website/src/data/install.json` created;
  shape test pins required fields.
- **AC-B (Astro reads from JSON, no hard-coded semver)** →
  InstallBlock.astro updated; `install-binding.test.ts` asserts no
  `\d+\.\d+\.\d+` matches.
- **AC-C (drift detector)** → `check-install-matches-formula.mjs`
  parses Formula, compares, exits 1 with field-named DRIFT.
- **AC-D (Vitest grep test)** → `install-binding.test.ts` above.
- **AC-E (Verified badge wiring)** → install.json `verified.macos_arm64`
  field; release.yml writes after US-43.1's check succeeds.
- **AC-F (CODEOWNERS guard)** → `.github/CODEOWNERS` entry for
  install.json and check script.

## Out of scope

- Verifying other arches (linux x86_64, etc.) — single arch this story.
- A signed/attested verified marker (transparency log) — future hardening.
- Auto-PR-bot for version bumps — formula updates are still manual.
- Smoke-test fixture for the parsing script — defer if cost/benefit weak.
