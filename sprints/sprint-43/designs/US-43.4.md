# Design for US-43.4: `human doctor --install` Health Check

**Story:** US-43.4 (P1, size M, risk LOW)
**Worktree:** `/Users/sethford/Documents/h-uman/.worktrees/sprint-43-distribution`
**Branch:** `sprint-43-distribution-mvp`

## Approach

Add an install-readiness gate to `human doctor` invoked via `--install`. The
four sub-checks (binary resolvable, config dir present, ≥1 channel paired,
persona present + parses) live behind a **pure predicate**
`hu_doctor_check_install` that takes an **injected state struct** —
`hu_doctor_install_state_t` — not a live filesystem. This matches the story's
explicit test-seam directive ("`hu_doctor_check_install` receives injected
state structs, no real filesystem reads in unit tests") and follows
`.claude/rules/security-predicate-extraction.md`: the decision is pure, the
I/O that PRODUCES the state lives in a separate gatherer function that is
exercised only at the CLI dispatch site.

Two-layer design:

1. **`hu_doctor_install_state_t`** — value-only struct with the four pieces of
   evidence the predicate needs (binary_path string, config_dir_exists bool,
   channel_paired bool, persona_status enum: MISSING / PRESENT_VALID /
   PRESENT_INVALID). Tests construct this directly.
2. **`hu_doctor_check_install(alloc, &state, &items, &count, &cap)`** — calls
   `doctor_push_line` four times (always all four — no short-circuit per AC),
   returns `HU_OK` always (the failure signal lives in the per-item
   `HU_DIAG_ERR` severity, per AC-43.4.2's "overall return is still HU_OK").
3. **`doctor_install_gather_state(alloc, &state)`** — the I/O layer used by
   `cmd_doctor` only. Reads `/proc/self/exe` or `_NSGetExecutablePath`, stats
   `~/.human/`, calls `hu_channel_catalog_has_any_configured`, opens the
   persona file and `hu_persona_load_json`-s it.

The aggregate "READY / NOT_READY" verdict is derived by the CLI by counting
`HU_DIAG_ERR` items in the returned array (same pattern as the existing
imessage/verifier subcommand dispatch at `src/main.c:658-666`).

## Implementation steps (for the implementer agent)

1. **Header changes** — `include/human/doctor.h`:
   - Add enum `hu_doctor_install_persona_status_t { HU_DOCTOR_PERSONA_MISSING,
     HU_DOCTOR_PERSONA_PRESENT_VALID, HU_DOCTOR_PERSONA_PRESENT_INVALID }`.
   - Add struct `hu_doctor_install_state_t { const char *binary_path;
     bool config_dir_exists; bool channel_paired;
     hu_doctor_install_persona_status_t persona_status; }`.
   - Add prototype: `hu_error_t hu_doctor_check_install(hu_allocator_t *,
     const hu_doctor_install_state_t *, hu_diag_item_t **items, size_t *count,
     size_t *cap);`
2. **Predicate implementation** — `src/doctor.c`:
   - Four `doctor_push_line` calls (always all four, no short-circuit).
   - Binary: `HU_DIAG_OK` if `binary_path != NULL && binary_path[0]`, else
     `HU_DIAG_ERR` with hint "could not resolve binary path".
   - Config dir: `HU_DIAG_OK` if true, else `HU_DIAG_ERR` with message
     containing the literal string `"human onboard"` (AC-43.4.4).
   - Channel: `HU_DIAG_OK` if true, else `HU_DIAG_ERR` with message
     containing `"human channel pair imessage"` (AC-43.4.4).
   - Persona: `HU_DIAG_OK` for `PRESENT_VALID`; `HU_DIAG_ERR` containing
     `"persona"` for `MISSING`; `HU_DIAG_ERR` containing BOTH `"persona"` and
     `"parse"` for `PRESENT_INVALID` (AC-43.4.2 mandates these substrings).
   - Return `HU_OK` in all paths (failure surfaces via item severity).
3. **CLI gatherer** — `src/main.c` (file-static, not exported):
   - `doctor_install_gather_state(alloc, hu_doctor_install_state_t *out)`:
     resolves binary path via existing `/proc/self/exe` / `_NSGetExecutablePath`
     pattern from `src/update.c:115` and `:123`; calls `hu_paths_*` to find
     `~/.human/` and stats it; loads config via `hu_config_load`; uses
     `hu_channel_catalog_has_any_configured(cfg, false)`; reads
     `cfg.agent.persona` path (when set) and calls `hu_persona_load_json` —
     map `HU_OK` → `PRESENT_VALID`, file-missing → `MISSING`, any other
     error → `PRESENT_INVALID`.
4. **CLI dispatch** — `cmd_doctor` in `src/main.c`:
   - Parse argv for `--install` and `--json` BEFORE the existing `--fix`
     check (precedence: subcommand → `--install` → `--privacy` [RESERVED slot
     left as a no-op `else if` stub commented `/* sprint-42 reserved */`] →
     `--fix` → default).
   - On `--install`: call gatherer, then predicate, then emit either the JSON
     shape `{"status": "READY"|"NOT_READY", "checks": [{severity, category,
     message}, ...]}` or the human-readable 4-line list. Free items, then free
     the gatherer's transient state.
5. **Tests** — `tests/test_doctor_install.c` (NEW; see test strategy below):
   - The file MUST reference `hu_doctor_check_install` per
     `.claude/rules/test-references-production-symbol.md`.
   - All 7 tests call the predicate directly with synthesized state structs.
   - No filesystem I/O in tests (story-mandated).
6. **Wire test** — append source path in `CMakeLists.txt` and add forward
   declaration + call to `tests/test_main.c`. Source is unconditional
   (no `HU_ENABLE_*` gate); test follows suit per
   `.claude/rules/test-source-gate-symmetry.md`.
7. Run `./build/human_tests --filter=doctor_install` then full suite.
   Commit with conventional message `feat(doctor): --install gate (US-43.4)`.

## Risks

- **Backward compat (LOW/SMALL):** `cmd_doctor` argv loop currently dispatches
  on subcommand and `--fix`. Adding `--install` ahead of `--fix` is additive
  and the legacy default path is preserved. Mitigation: smoke test that
  `human doctor` with no flags still runs the legacy full report.
- **`--privacy` reserved slot (LOW/SMALL):** Story is explicit that sprint-42
  owns `--privacy` and the precedence position must be reserved. Mitigation:
  add a commented `else if` stub with a TODO and link to sprint-42 in the
  comment; no behavior, just slot reservation. Verified at design time: no
  `--privacy` handler exists yet in `cmd_doctor` (grepped `src/main.c`).
- **AC-43.4.4 string-match fragility (LOW/SMALL):** ACs pin specific
  remediation strings (`"human onboard"`, `"human channel pair imessage"`).
  Mitigation: define them as `static const char` in `src/doctor.c` so future
  rewording requires touching the constant; pin both via tests 4 and 5.
- **Persona file lookup ambiguity (MED/SMALL):** `cfg.agent.persona` may be a
  bare name resolved against `~/.human/personas/`, an absolute path, or NULL.
  Mitigation: in the gatherer, follow the existing resolution rule used by
  `hu_persona_load` (verify before implementation); when NULL, treat as
  `MISSING`. Predicate-layer tests don't care — they take the enum.
- **AC-43.4.5 ASan (LOW/SMALL):** Each `doctor_push_line` `hu_strdup`s
  category + message; predicate caller already owns the free loop pattern
  (lines 718-724 in main.c). Mitigation: reuse it verbatim in the `--install`
  branch; do NOT introduce a new ownership convention.
- **Persona parse via `hu_persona_load_json` (LOW/MED):** Calling the full
  loader for a parse check pays for fields we don't need. Mitigation:
  acceptable cost; reusing the canonical loader avoids drift between "doctor
  thinks it parses" and "agent fails to load it" (the bug class the gate
  exists to prevent). NO custom JSON-tolerance shortcut.

## Test strategy

7 tests in `tests/test_doctor_install.c`. All call the predicate directly
with stack-allocated `hu_doctor_install_state_t`; none touch the filesystem.

1. `test_doctor_install_all_green_returns_ok_with_four_ok_items` — all four
   state fields set to the happy values, expect 4 items all `HU_DIAG_OK`,
   predicate returns `HU_OK`. (AC-43.4.1)
2. `test_doctor_install_missing_binary_path_reports_err` — `binary_path=NULL`,
   others happy; expect item[0] is `HU_DIAG_ERR`, items 1-3 are `HU_DIAG_OK`,
   and the array length is 4 (no short-circuit).
3. `test_doctor_install_missing_config_dir_reports_err_with_human_onboard_hint`
   — `config_dir_exists=false`; assert item[1] severity is `HU_DIAG_ERR` and
   `strstr(item[1].message, "human onboard") != NULL`. (AC-43.4.4)
4. `test_doctor_install_no_channel_paired_reports_err_with_pair_imessage_hint`
   — `channel_paired=false`; assert item[2] is `HU_DIAG_ERR` and message
   contains `"human channel pair imessage"`. (AC-43.4.4)
5. `test_doctor_install_persona_missing_reports_err_containing_persona` —
   `persona_status=HU_DOCTOR_PERSONA_MISSING`; item[3] is `HU_DIAG_ERR`,
   message contains `"persona"`.
6. `test_doctor_install_persona_invalid_reports_err_containing_persona_and_parse`
   — `persona_status=HU_DOCTOR_PERSONA_PRESENT_INVALID`; item[3] is
   `HU_DIAG_ERR`, message contains BOTH `"persona"` AND `"parse"`.
   Predicate return is still `HU_OK`. (AC-43.4.2 — both substrings + return)
7. `test_doctor_install_all_red_still_emits_exactly_four_items` —
   binary=NULL, config_dir=false, channel=false, persona=MISSING; assert
   `item_count == 4` (no short-circuit on red, AC-43.4.1's "exactly 4"
   contract holds inverted on the failure side too).

Red-path assertions use the story-directive form `HU_ASSERT_NE` where
appropriate, but predicate return is `HU_OK` per AC-43.4.2 — so the
**item severity** carries the failure signal. (The "NE" form applies to the
CLI-level aggregate return, which is exercised via the existing
`err_n > 0 ? HU_ERR_INTERNAL : HU_OK` pattern in `cmd_doctor` and is not
unit-tested in this story per the no-FS-I/O constraint.)

## Acceptance criteria mapping

- **AC-43.4.1** (all green → `HU_OK` + 4 `HU_DIAG_OK` items) → test 1
- **AC-43.4.2** (malformed persona → `HU_DIAG_ERR` containing `"persona"`
  AND `"parse"`; overall return still `HU_OK`) → test 6
- **AC-43.4.3** (precedence subcommand → `--install` → `--privacy`(reserved)
  → `--fix` → default) → `cmd_doctor` dispatch order + commented reservation
  slot; not unit-tested per no-FS-I/O constraint, validated by code review of
  the dispatch order against the AC. Smoke test optional via shell during
  implementation.
- **AC-43.4.4** (remediation hints `"human onboard"` + `"human channel pair
  imessage"`) → tests 3 and 4
- **AC-43.4.5** (ASan clean) → full `./build/human_tests` run under the
  default `dev` preset which enables ASan

## Out of scope

- `--privacy` flag implementation (sprint-42 owns; we only reserve the
  precedence position with a commented stub).
- Auto-remediation in install mode (`--fix` stays a separate flag per
  precedence).
- Windows binary-path resolution (story out-of-scope, darwin + linux only).
- Telemetry / analytics on which sub-check failed most often.
- Unit-testing the gatherer (`doctor_install_gather_state`) — story
  explicitly mandates no FS I/O in unit tests; the gatherer is exercised
  end-to-end during manual sprint validation.
