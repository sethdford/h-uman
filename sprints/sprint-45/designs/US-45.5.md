# Design for US-45.5: macOS First-Run OnboardingSheet

## Approach

A SwiftUI `.sheet` presented from the root `WindowGroup`'s `DashboardView` when the local daemon binary is absent and the user has not yet completed onboarding. State is owned by `OnboardingState: ObservableObject` (a `@MainActor` class) which exposes a `shouldShow: Bool` computed from three inputs: (a) daemon detection (`ProcessManager.humanPath()` returning nil), (b) a persisted `UserDefaults` boolean `humanOnboardingComplete`, and (c) a DEBUG-only launch-argument override `-uitestSkipOnboarding`.

URLs are constants in a dedicated file. There is NO user-input path constructing URLs at runtime, satisfying the prior critic finding against `URL(string: userInput)`. We use a `URL(staticString:)` initializer (trapping at init time on a malformed literal) instead of `URL(string:)!` force-unwraps. AC-45.5.3 additionally requires a CI grep assertion: no onboarding URL string literals may appear anywhere in `apps/macos/Sources/HumanApp/` except in `OnboardingURLs.swift`.

CTAs open URLs via the async `NSWorkspace.shared.open(_:configuration:completionHandler:)` overload. Per AC-45.5.2, `markCompleted()` fires **only** when the completion handler receives a **non-nil `NSRunningApplication`** — neither a nil app NOR a non-nil error will satisfy the gate. The sheet uses `.interactiveDismissDisabled(true)` so Escape and click-outside cannot bypass completion. The Skip CTA exists, has accessibility identifier `onboarding.skip`, and calls `markCompleted()` directly on tap. The Install CTA has identifier `onboarding.install`.

Why this and not alternatives:
- A separate `NSWindow` instead of `.sheet` would lose SwiftUI dismiss-gesture semantics and require manual modal-window plumbing; `.sheet` + `.interactiveDismissDisabled(true)` is the idiomatic macOS-14 path.
- async/await wrapping of `NSWorkspace.open` is gratuitous — the completion-handler API is what AC-45.5.2 names, and rewriting it muddles the contract.
- Folding the `completed` flag into `@AppStorage` on the view would inline persistence into UI code; an explicit `OnboardingState` keeps the read/write contract testable from XCUITest and from unit tests of `shouldShow`.
- `humanPath()` already lives on `ProcessManager` (see `apps/macos/Sources/HumanApp/ProcessManager.swift:24`). `OnboardingState` takes a `daemonPresent: () -> Bool` closure injected at construction so XCUITest can also inject a fake (and so the dependency direction is one-way).

## Implementation steps (for the implementer agent)

1. Add `URL+StaticString.swift` with `extension URL { init(staticString: StaticString) }` — uses `URL(string: "\(staticString)")!` internally with a `preconditionFailure` on nil; the `StaticString` type prevents non-literal callers.
2. Add `OnboardingURLs.swift` exposing at minimum `static let install: URL`, `static let docs: URL`, `static let support: URL` using `URL(staticString:)`.
3. Add `OnboardingState.swift`:
   - `@MainActor final class OnboardingState: ObservableObject`
   - `init(daemonPresent: @escaping () -> Bool, defaults: UserDefaults = .standard, args: [String] = ProcessInfo.processInfo.arguments)`
   - `@Published private(set) var completed: Bool` initialized from `defaults.bool(forKey: "humanOnboardingComplete")`
   - `var shouldShow: Bool { !daemonPresent() && !completed && !skipLaunchArg }`
   - `private var skipLaunchArg: Bool` — wrapped in `#if DEBUG` returning `args.contains("-uitestSkipOnboarding")`, `#else return false`
   - `func markCompleted()` writes `defaults.set(true, forKey: "humanOnboardingComplete")` then sets `completed = true`
   - Binding helper: `var isPresented: Binding<Bool>` for the `.sheet` modifier (read = `shouldShow`, set = no-op or assert-debug since `.interactiveDismissDisabled(true)` prevents dismiss-by-gesture)
4. Add `OnboardingSheet.swift`:
   - Body: VStack with title, copy, Install CTA (primary), Skip CTA (secondary)
   - Install CTA calls `NSWorkspace.shared.open(OnboardingURLs.install, configuration: NSWorkspace.OpenConfiguration()) { app, error in if let _ = app, error == nil { Task { @MainActor in state.markCompleted() } } }`
   - Skip CTA: `Button("Skip") { state.markCompleted() }.accessibilityIdentifier("onboarding.skip")`
   - Install CTA: `.accessibilityIdentifier("onboarding.install")`
5. Edit `HumanApp.swift`:
   - `@StateObject private var onboarding = OnboardingState(daemonPresent: { status.processManager.humanPath() != nil })` (wire to existing ProcessManager via StatusViewModel — confirm the access path; if private, add a `var hasHumanBinary: Bool` accessor on StatusViewModel)
   - Attach `.sheet(isPresented: onboarding.isPresented) { OnboardingSheet(state: onboarding) }.interactiveDismissDisabled(true)` on `DashboardView()`
6. Add `OnboardingUITests.swift`:
   - `test_pre_seeded_completed_flag_hides_sheet_on_first_frame` (AC-45.5.5 READ): launch with `-AppleLanguages` plus `-humanOnboardingComplete YES` (NSUserDefaults launch-arg form), assert `XCUIApplication().sheets["..."].exists == false` or the install identifier is not present.
   - `test_skip_persists_across_relaunch` (AC-45.5.5 WRITE): launch with reset args (`-humanOnboardingComplete NO`), assert sheet present, tap `onboarding.skip`, terminate, relaunch WITHOUT reset arg, assert sheet absent.
   - `test_debug_launch_arg_suppresses_sheet`: launch with `-uitestSkipOnboarding`, assert sheet absent (only runs against DEBUG builds — XCUITest scheme defaults to Debug config).
   - `test_install_and_skip_have_accessibility_identifiers`: first launch, assert both `onboarding.install` and `onboarding.skip` exist and are hittable.
7. Add CI grep assertion (AC-45.5.3) in `macos-app-archive` job:
   ```bash
   ! grep -RnE 'URL\(string: ?"https?://' apps/macos/Sources/HumanApp/ \
     --include='*.swift' | grep -v OnboardingURLs.swift
   ```
   Exit non-zero if any onboarding URL literal lives outside `OnboardingURLs.swift`. (Note: `HumanApp.swift` line ~85 has `URL(string: "http://localhost:3000")` — not an onboarding URL, but the grep should target https:// onboarding hosts specifically OR be scoped to known onboarding domains.)
8. `/verify` — run XCUITest scheme on macOS-14 runner.

## Risks

- **Completion-handler thread (HIGH/MED)**: `NSWorkspace.open` completion runs on an arbitrary queue. `markCompleted()` mutates `@Published` and writes UserDefaults; both must happen on MainActor or SwiftUI emits a runtime warning and tests may flake. **Mitigation**: wrap the callback body in `Task { @MainActor in ... }`; the `@MainActor` annotation on `OnboardingState` makes the compiler enforce the rest.
- **AC-45.5.2 completion-handler gate misread (MED/LARGE)**: it is tempting to gate on `error == nil` alone; the AC requires gating on **non-nil `NSRunningApplication`**. A successful URL handoff to LaunchServices may return `app == nil` (no running-app representation) in edge cases; that would correctly NOT mark complete. **Mitigation**: explicit `if let _ = app, error == nil` check; unit test if `NSWorkspace.OpenConfiguration` is mockable, otherwise pin via code review.
- **Launch-arg leak to release (MED/LARGE)**: AC-45.5.4 mandates `#if DEBUG`, NOT a runtime check. If the implementer uses `targetEnvironment(simulator)` (irrelevant on macOS) or `#if !RELEASE`, release builds may honor the bypass. **Mitigation**: explicit `#if DEBUG` directive with `#else return false`; CI scheme used by archive build is Release config, which the existing `macos-app-archive` job from US-45.1 already covers.
- **URL-literal grep scope (LOW/MED)**: the existing `HumanApp.swift` already contains `URL(string: "http://localhost:3000")` (line ~85). If the AC-45.5.3 grep is too broad it will flag this. **Mitigation**: scope the grep to https:// onboarding-domain literals OR exclude `localhost`/loopback URLs; document the exact regex in the CI step alongside the AC reference.
- **`shouldShow` is recomputed eagerly (LOW/SMALL)**: `daemonPresent` is a closure called every render. If `humanPath()` walks PATH each time, this is a small filesystem stat tax per render. **Mitigation**: cache the result inside `OnboardingState` after first call OR rely on the fact that the sheet only renders once per app launch.
- **AC-45.5.5 first-frame absence (MED/MED)**: XCUITest reads the accessibility hierarchy after launch; SwiftUI's `.sheet` may briefly attach then detach if `shouldShow` flips after init. **Mitigation**: initialize `completed` from UserDefaults synchronously in `init`, NOT in `.onAppear`; `shouldShow` is then stable on first frame.
- **Concurrency on UserDefaults (LOW/SMALL)**: `UserDefaults.standard` is thread-safe for primitive writes. `@MainActor` on the state object means all reads/writes happen on main; no race.

## Test strategy

XCUITest in `apps/macos/UITests/OnboardingUITests.swift` — four cases above. Each test scrubs UserDefaults via launch args (`-humanOnboardingComplete <BOOL>`) so cases are independent and order-free.

Why not unit tests of `OnboardingState`?  We could add a sibling `OnboardingStateTests.swift` covering the `shouldShow` truth table with an injected `daemonPresent` closure — it's cheap and the predicate is the security-relevant decision. **Add it as a fifth test file** (~40 LOC) — covers all 8 combinations of (daemonPresent × completed × skipArg) deterministically without launching the app. Aligned with `~/.claude/rules/security-predicate-extraction.md`: the `shouldShow` predicate is the gating decision and deserves direct test coverage.

The Install CTA's browser-launch behavior is NOT tested end-to-end (would require mocking NSWorkspace); we test the IDENTIFIER + presence and rely on code review for the completion-handler gate. This is acceptable because AC-45.5.2 is structural (call shape) — a CI grep for the call pattern is a future hardening option.

## Acceptance criteria mapping

| AC | Covered by |
|---|---|
| AC-45.5.1 (`.interactiveDismissDisabled(true)` on the sheet) | Code review + `test_pre_seeded_completed_flag_hides_sheet_on_first_frame` indirectly proves the modifier didn't break presentation |
| AC-45.5.2 (markCompleted only on non-nil `NSRunningApplication`) | Code review of the completion handler; structurally enforced by call shape |
| AC-45.5.3 (no onboarding URL literals outside `OnboardingURLs.swift`) | CI grep step added to `macos-app-archive` job |
| AC-45.5.4 (`#if DEBUG` guard on launch-arg, not runtime) | Code review + `test_debug_launch_arg_suppresses_sheet` (Debug only); release build's grep for `-uitestSkipOnboarding` outside `#if DEBUG` blocks is a useful additional CI guard |
| AC-45.5.5 (XCUITest READ + WRITE) | `test_pre_seeded_completed_flag_hides_sheet_on_first_frame` + `test_skip_persists_across_relaunch` |
| Critic: skip CTA accessibility identifier pinned | `test_install_and_skip_have_accessibility_identifiers` |
| Critic: dismiss-by-Escape disabled | `.interactiveDismissDisabled(true)` (compile-time enforcement) |
| Critic: no `URL(string:)!` force-unwraps | `URL(staticString:)` initializer; force-unwrap is internal to that extension and traps at app start if a literal is malformed |

## Out of scope

- iOS onboarding surface (separate story).
- Analytics events for onboarding completion.
- A/B variants of onboarding copy.
- Localization of strings.
- An in-sheet daemon-install progress UI (current scope hands off to browser).
- SwiftLint rule banning `URL(string:)!` repo-wide (a useful follow-up; not required by ACs).
- Fixing the pre-existing `URL(string: "http://localhost:3000")` in `HumanApp.swift` (orthogonal to onboarding; AC-45.5.3 grep should be scoped to avoid flagging it).
