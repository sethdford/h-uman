# Design for US-45.1: macOS Archive + Dev-Cert Codesign

## Approach

Today `apps/macos/` is **SwiftPM-only** (`Package.swift` building an
executable target `Human` against `apps/shared/HumanKit/`), and CI does
`swift build` + `swift build -c release` via the `macos-app-build` job in
`native-apps-fleet.yml`. SwiftPM cannot produce a codesigned `.xcarchive`,
so we introduce **XcodeGen** to materialize an `.xcodeproj` on demand from
a small declarative `apps/macos/project.yml`. The same approach is already
in use for `apps/ios/` (`.github/actions/ios-uitest` consumes
`apps/ios/project.yml`), so the operating pattern is established.

The new CI job `macos-app-archive` runs in four phases and fails closed:

1. **Generate** — `brew install xcodegen` (cached), `xcodegen generate`
   inside `apps/macos/`. Generated `.xcodeproj` is git-ignored.
2. **Sign-gate** — if `secrets.MACOS_CERT_P12` is set, `scripts/ci/
   import-macos-cert.sh` decodes the base64 P12 into an **ephemeral**
   keychain (NOT `login.keychain`). An `EXIT` trap shreds both the
   decoded `.p12` and the temp keychain on every exit path.
3. **Archive + verify** — `xcodebuild archive` with
   `CODE_SIGN_IDENTITY="Apple Development"` (identity by NAME, not
   SHA-1). Then `codesign --verify --deep --strict <archive>.app`.
   `--deep` is passed ONLY on `--verify`, never on the archive
   invocation itself (AC-45.1.3 makes this explicit).
4. **Unsigned fallback** — when `secrets.MACOS_CERT_P12 == ''`, the same
   job step path falls back to `swift build -c release` and exits 0
   (AC-45.1.4 — note this is `swift build`, NOT `xcodebuild build`).
   The gate condition is an explicit `secrets.MACOS_CERT_P12 == ''`
   check; we do NOT key off `outcome != 'success'` of the signed step,
   which would mask real cert-import infra failures (prior critic
   catch).

For `fleet-sota-gate`, `macos-app-archive` is added to the `needs:` list
and to the green-gate environment so it becomes a required check
alongside the existing `macos-app-build` (AC-45.1.5).

## Implementation steps (for the implementer agent)

1. **`.gitignore`** — add `apps/macos/Human.xcodeproj/` FIRST so any
   local accidental generation never gets committed. Verify with
   `git status` after a sample `xcodegen generate`.

2. **`apps/macos/project.yml`** — minimal XcodeGen spec mirroring
   `apps/ios/project.yml`'s shape:
   ```yaml
   name: Human
   options:
     bundleIdPrefix: ai.human
     deploymentTarget:
       macOS: "14.0"
     createIntermediateGroups: true
   settings:
     base:
       SWIFT_VERSION: "5.9"
       MARKETING_VERSION: "1.1.0"
   packages:
     HumanKit:
       path: ../shared/HumanKit
   targets:
     Human:
       type: application
       platform: macOS
       sources:
         - path: Sources/HumanApp
       dependencies:
         - package: HumanKit
           product: HumanClient
         - package: HumanKit
           product: HumanChatUI
         - package: HumanKit
           product: HumanOnDevice
         - package: HumanKit
           product: HumanOnDeviceServer
       settings:
         base:
           PRODUCT_BUNDLE_IDENTIFIER: ai.human.macos
           CODE_SIGN_STYLE: Manual
           CODE_SIGN_IDENTITY: "Apple Development"
           DEVELOPMENT_TEAM: ""  # supplied by CI env or US-45.6 lane
   ```
   Match the SwiftPM `Package.swift` product list exactly so the
   archive uses the same module graph as `swift build`.

3. **`apps/macos/README.md`** — three short sections: why XcodeGen,
   `brew install xcodegen`, `xcodegen generate` inside `apps/macos/`.
   Note that the generated `.xcodeproj` is git-ignored and must be
   regenerated locally before opening in Xcode.

4. **`scripts/ci/import-macos-cert.sh`** — first non-comment line must
   be `set -euo pipefail` (AC-45.1.2). Skeleton:
   - Required env: `MACOS_CERT_P12` (base64), `MACOS_CERT_PASSWORD`,
     optional `KEYCHAIN_PASSWORD` (random if unset).
   - `WORKDIR=$(mktemp -d)`; `P12_PATH="$WORKDIR/cert.p12"`;
     `KEYCHAIN="$WORKDIR/human-ci-$$.keychain-db"`.
   - **EXIT trap** registered before any sensitive op:
     ```bash
     cleanup() {
       security delete-keychain "$KEYCHAIN" 2>/dev/null || true
       if [ -f "$P12_PATH" ]; then
         # rm -P is the macOS equivalent of shred -u
         rm -P "$P12_PATH" 2>/dev/null || rm -f "$P12_PATH"
       fi
       rm -rf "$WORKDIR"
     }
     trap cleanup EXIT
     ```
   - Decode: `printf '%s' "$MACOS_CERT_P12" | base64 -d > "$P12_PATH"`
     (use `set +x` around this line to avoid logging the cert bytes).
   - `security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"`
   - `security set-keychain-settings -lut 21600 "$KEYCHAIN"`
   - `security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"`
   - `security import "$P12_PATH" -k "$KEYCHAIN" -P
     "$MACOS_CERT_PASSWORD" -T /usr/bin/codesign -T /usr/bin/security`
   - `security set-key-partition-list -S apple-tool:,apple:,codesign:
     -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN"`
   - **Search-list update** (handle spaces in paths — prior critic):
     ```bash
     # Read existing list into a bash array (preserves spaces).
     mapfile -t ORIGINAL_LIST < <(security list-keychains -d user \
       | sed -e 's/^[[:space:]]*//' -e 's/"//g')
     security list-keychains -d user -s "$KEYCHAIN" "${ORIGINAL_LIST[@]}"
     ```
   - Echo the imported identity name for downstream `CODE_SIGN_IDENTITY`
     reference (but never echo the SHA-1).
   - Note: This script is **sourced or executed**; either way the EXIT
     trap fires when the calling shell ends. CI invokes it as a step
     with `bash scripts/ci/import-macos-cert.sh` so the trap runs at
     step-end, and the keychain is recreated per-job.

5. **`macos-app-archive` job** in `native-apps-fleet.yml`:
   ```yaml
   macos-app-archive:
     name: macOS app · Archive + codesign
     runs-on: macos-latest
     timeout-minutes: 25
     steps:
       - uses: actions/checkout@v6
       - name: Cache Homebrew (XcodeGen)
         uses: actions/cache@v5
         with:
           path: ~/Library/Caches/Homebrew
           key: ${{ runner.os }}-brew-${{ hashFiles('.github/workflows/native-apps-fleet.yml') }}
       - name: Install XcodeGen
         run: brew install xcodegen
       - name: Generate Xcode project
         run: cd apps/macos && xcodegen generate
       - name: Import signing certificate
         if: ${{ secrets.MACOS_CERT_P12 != '' }}
         env:
           MACOS_CERT_P12: ${{ secrets.MACOS_CERT_P12 }}
           MACOS_CERT_PASSWORD: ${{ secrets.MACOS_CERT_PASSWORD }}
         run: bash scripts/ci/import-macos-cert.sh
       - name: Archive (signed)
         if: ${{ secrets.MACOS_CERT_P12 != '' }}
         run: |
           cd apps/macos
           xcodebuild archive \
             -project Human.xcodeproj \
             -scheme Human \
             -configuration Release \
             -archivePath build/Human.xcarchive \
             CODE_SIGN_IDENTITY="Apple Development" \
             CODE_SIGN_STYLE=Manual
       - name: Verify codesign
         if: ${{ secrets.MACOS_CERT_P12 != '' }}
         run: |
           cd apps/macos
           codesign --verify --deep --strict \
             build/Human.xcarchive/Products/Applications/Human.app
       - name: Unsigned fallback (no secrets)
         if: ${{ secrets.MACOS_CERT_P12 == '' }}
         run: cd apps/macos && swift build -c release
   ```
   Key gates per critic feedback:
   - The signed steps gate on `secrets.MACOS_CERT_P12 != ''`.
   - The unsigned fallback gates on `secrets.MACOS_CERT_P12 == ''`,
     NOT on the signed step's `outcome`. Two mutually exclusive
     branches, one of which always runs.

6. **`fleet-sota-gate` integration** (AC-45.1.5):
   - Add `macos-app-archive` to `needs:` list.
   - Add `MAC_ARCHIVE: ${{ needs.macos-app-archive.result }}` to env.
   - Extend the green check:
     `if [ "$HK" != success ] || ... || [ "$MAC_ARCHIVE" != success ]; then`
   - Add a row to the summary table.

7. **Local verification** before merge: on a mac with a valid Apple Dev
   cert in `login.keychain`, run `brew install xcodegen && cd apps/macos
   && xcodegen generate && xcodebuild archive -project Human.xcodeproj
   -scheme Human -configuration Release -archivePath /tmp/Human.xcarchive
   CODE_SIGN_IDENTITY="Apple Development"`. Verify
   `codesign --verify --deep --strict /tmp/Human.xcarchive/Products/
   Applications/Human.app` exits 0.

## Risks

- **Keychain search-list quoting (MEDIUM/MEDIUM)** — `security
  list-keychains -s` takes multiple positional args; naive
  `"$ORIGINAL_LIST"` collapses them into a single arg. If any user
  keychain path contains spaces, signing silently fails when looking up
  the identity. **Mitigation**: bash array via `mapfile -t` +
  `"${ORIGINAL_LIST[@]}"` expansion. Pinned by the CI run; if a future
  runner has a spaced keychain path, the archive step fails loudly with
  "no identity found".

- **`--deep` on the wrong invocation (MEDIUM/LARGE)** —
  `xcodebuild archive ... --deep` (or `OTHER_CODE_SIGN_FLAGS="--deep"`)
  re-signs every nested framework with our identity, which is wrong for
  vendored signed binaries (HumanKit's transitive deps, system
  frameworks). **Mitigation**: AC-45.1.3 explicitly forbids `--deep` on
  archive. The job uses `--deep` ONLY on the verify step. We do not set
  `OTHER_CODE_SIGN_FLAGS`. A grep-CI lint could enforce this; defer
  unless it recurs.

- **Outcome-based fallback masking (HIGH/MEDIUM)** — prior critic catch.
  Using `if: needs.archive.outcome != 'success'` for the unsigned smoke
  would silently green-wash a broken cert import. **Mitigation**:
  explicit `secrets.MACOS_CERT_P12 == ''` gate. Both branches always
  evaluate against the same boolean and one always runs.

- **Cert leakage in logs (LOW/LARGE)** — base64 string is sensitive.
  **Mitigation**: `set +x` around the `base64 -d` line; never `echo`
  the secret; GitHub already masks the secret value if logged. EXIT
  trap removes plaintext `.p12` from disk on every code path.

- **Generated `.xcodeproj` accidentally committed (LOW/SMALL)** —
  someone runs `xcodegen generate` then `git add -A`. **Mitigation**:
  `.gitignore` entry added FIRST, before the first generation.

- **Fork-PR secret behaviour (LOW/SMALL)** — `pull_request` events from
  forks do NOT receive secrets, so `secrets.MACOS_CERT_P12 == ''`
  evaluates true and the unsigned fallback runs. This is the desired
  AC-45.1.4 behavior. We do NOT use `pull_request_target` (which would
  expose secrets to untrusted code).

- **XcodeGen version drift (LOW/SMALL)** — unpinned `brew install
  xcodegen` could change generated output across runs. **Mitigation**:
  brew's homebrew-core revision is pinned by the runner image; we
  accept that floor. If reproducibility becomes a problem we pin via
  `brew install xcodegen@<version>` in a follow-up.

- **HumanKit deployment-target alignment (LOW/SMALL)** — `project.yml`
  declares `macOS 14.0`; HumanKit's `Package.swift` must match.
  US-45.4 owns HumanKit `@available` annotations; if 45.1 lands first,
  the archive still builds because `Package.swift` already targets
  `.macOS(.v14)`.

- **Backward compat — `macos-app-build` (LOW/SMALL)** — the existing
  `swift build` job stays. The new `macos-app-archive` runs in parallel;
  no caller breaks.

## Test strategy

- **CI is the contract.** No unit tests are added.
- **Pre-merge local check**: implementer runs `xcodegen generate` +
  `xcodebuild archive` on a mac to confirm `project.yml` is well-formed
  before pushing.
- **Smoke after merge**: `workflow_dispatch` of the fleet on `main`
  with secrets present → confirm signed path success. Same workflow on
  a fork-PR → confirm unsigned fallback success.
- **Negative test**: temporarily setting `MACOS_CERT_P12` to a garbage
  base64 string in a draft PR — the import step must fail loudly (not
  silently fall through). This is the canary for risk #3 above.

## Acceptance criteria mapping

- **AC-45.1.1** (XcodeGen produces ignored `.xcodeproj`) →
  `.gitignore` entry + `xcodegen generate` step. Verified by
  `git status` showing clean tree after the generate step in CI.
- **AC-45.1.2** (`set -euo pipefail` first line + EXIT trap shreds
  keychain) → `scripts/ci/import-macos-cert.sh` structure above.
  Verified by `head -3` grep in a CI lint or pre-commit.
- **AC-45.1.3** (`xcodebuild archive` with `CODE_SIGN_IDENTITY="Apple
  Development"` exits 0; `codesign --verify --deep --strict` exits 0;
  `--deep` NOT on archive) → signed-path steps above. Verified by
  CI green + a `grep -n -- '--deep' .github/workflows/native-apps-
  fleet.yml` lint that asserts `--deep` appears only on the verify
  line.
- **AC-45.1.4** (no secrets → unsigned `swift build -c release` exits
  0; job does not fail or skip) → unsigned-fallback step gated on
  `secrets.MACOS_CERT_P12 == ''`. Both branches are real steps inside
  the same job, so the job always runs and exits 0 on either path.
- **AC-45.1.5** (`fleet-sota-gate` requires `macos-app-archive`) →
  `needs:` + env + gate-condition extension to the existing summary
  step.
