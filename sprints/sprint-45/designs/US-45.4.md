# Design for US-45.4: HumanKit @available + Swift 6 Concurrency

## Approach

Move HumanKit to Swift 6 by (a) bumping `swift-tools-version` from
`5.9` to `6.0` in `apps/shared/HumanKit/Package.swift` and (b)
setting `swiftLanguageMode: .v6` on every non-test target.
Explicitly NOT via `unsafeFlags(["-strict-concurrency=complete"])`:
prior critic finding — those flags are silently stripped when
HumanKit is consumed as a SwiftPM dependency from an Xcode project
(`apps/ios/HumaniOS.xcodeproj` consumes via `packages.HumanKit`),
so the concurrency check only fires from the package root and
masks consumer-side races. `swiftLanguageMode: .v6` is preserved
across the package boundary.

Annotate every top-level public type (29 enumerated across
HumanProtocol / HumanClient / HumanChatUI / HumanOnDevice /
HumanOnDeviceServer) with `@available(macOS 14.0, iOS 17.0, *)`,
and ensure every public symbol — top-level AND nested
(DesignTokens constants, Methods constants, ControlFrame
properties) — carries a `///` doc comment. Use
`grep -E '^[[:space:]]*///'` for verification (NOT `^///` —
indented nested public symbols matter).

Surface real concurrency races; do NOT silence them with
`@unchecked Sendable`. Two pre-identified sites:

- `HumanConnection.swift:34` — `public static var
  requestTimeoutSeconds: TimeInterval = 10` (the prompt said line
  44; actual is 34). Fix: `nonisolated(unsafe)` + serial
  `DispatchQueue` accessor pair OR convert to an `actor`-isolated
  store. `@unchecked Sendable` is forbidden by AC-45.4.1.
- `IntentHandler.swift:41-58` — `HumanGatewayClient.request(method:
  params:completion:)` takes `completion: @escaping
  (Result<Any, Error>) -> Void` and invokes it inside a `Task`
  closure after `await`. Two real issues: (1) the closure isn't
  `@Sendable`, (2) the `Result<Any, Error>` payload's `Any` is
  not `Sendable`. Fix: change the completion signature to
  `@Sendable @escaping (Result<[String: any Sendable], Error>) -> Void`
  (or a typed `RequestResponse` struct that IS `Sendable`), and
  hop to `@MainActor` before invoking it.

Five existing `@unchecked Sendable` declarations are in tree —
`HumanGatewayClient`, `HumanConnection`, `OnDeviceRouter`,
`HTTPServer`, `OnDeviceChatAdapter`. Story AC-45.4.1 forbids
INTRODUCING new ones AND forbids `@unchecked Sendable` appearing
in the diff this story produces. Strategy: remove the
`@unchecked Sendable` from the two HumanClient classes
(HumanConnection becomes properly `Sendable` via the queue +
nonisolated(unsafe) discipline; HumanGatewayClient becomes a
proper `Sendable` actor or holds its mutable state behind a
`Mutex`/queue). The three HumanOnDevice* `@unchecked Sendable`s
are deferred to a follow-up story IF Swift 6 mode does not
surface a fresh diagnostic on them; if it does, they must be
fixed here (because the diff would otherwise show
`@unchecked Sendable` retained, violating AC-45.4.1's "must not
appear in any diff" clause — interpret narrowly as "must not be
ADDED" but flag for product-owner if compiler forces the issue).

## Implementation steps (for the implementer agent)

1. **Baseline diagnostic sweep.** Bump `Package.swift` to
   `swift-tools-version: 6.0` and add
   `swiftLanguageMode: .v6` to all 5 non-test targets. Run
   `cd apps/shared/HumanKit && swift build 2>&1 | tee /tmp/us-45.4-diag.txt`.
   The list of warnings/errors IS the work plan. Do NOT start
   editing yet.
2. **Triage diagnostics.** Bucket each diagnostic:
   - (a) `Sendable` conformance on a value-type / class →
     fixable via proper `Sendable` or actor isolation.
   - (b) `@available` missing → trivially fixable per step 3.
   - (c) cross-actor mutable state (the two pre-identified
     races) → real fix per steps 5-6.
   - (d) anything that pushes toward `@unchecked Sendable` →
     STOP and surface to tech-lead.
3. **@available + doc comments.** Add
   `@available(macOS 14.0, iOS 17.0, *)` to every top-level
   `public struct|class|enum|actor|protocol|extension|final class`
   (29 sites enumerated). Add `///` doc comments to every public
   symbol that lacks one (top-level + nested constants in
   DesignTokens / Methods). Validate:
   ```sh
   grep -rEn '^public (struct|class|enum|actor|protocol|extension|final class) ' \
     apps/shared/HumanKit/Sources/ \
     | while read -r line; do
         file=$(echo "$line" | cut -d: -f1)
         lno=$(echo "$line" | cut -d: -f2)
         prev=$((lno - 1))
         sed -n "${prev}p" "$file" | grep -q '@available' || echo "MISS: $line"
       done
   ```
   Must produce zero `MISS:` lines.
4. **Rebuild.** `swift build`. Diagnostics from buckets (b) above
   should disappear; (a) and (c) remain — those are the real
   work.
5. **Fix `HumanConnection.requestTimeoutSeconds`.** Approach:
   - Remove `@unchecked Sendable` from `HumanConnection`.
   - Make the static var:
     `nonisolated(unsafe) public static var requestTimeoutSeconds: TimeInterval = 10`
   - Introduce a file-private serial queue
     `requestTimeoutQueue` (or reuse a static
     `DispatchQueue(label: "com.human.connection.config")`).
   - Wrap reads and writes in `queue.sync { ... }`. Public API
     stays `var`-shaped via property accessors:
     `public static var requestTimeoutSeconds: TimeInterval {
       get { queue.sync { _requestTimeoutSeconds } }
       set { queue.sync { _requestTimeoutSeconds = newValue } } }`
     where `_requestTimeoutSeconds` is the
     `nonisolated(unsafe)` storage.
   - If the rest of `HumanConnection`'s state can be made
     `Sendable` without queue gymnastics, do so; if it still
     needs the existing `pendingLock` / `queue` discipline,
     conform to `Sendable` via an actor wrapper OR keep the
     class but ensure all mutable storage is `nonisolated(unsafe)`
     + guarded. NO `@unchecked Sendable`.
   - Add `HumanConnectionConcurrencyTests` (see Test strategy).
6. **Fix `HumanGatewayClient.request(...)`.** Approach:
   - Remove `@unchecked Sendable` from `HumanGatewayClient`.
   - Introduce a `Sendable` payload type, e.g.
     ```swift
     public struct GatewayResponse: Sendable {
         public let payload: [String: AnyCodable]
     }
     ```
     (`AnyCodable` must itself be `Sendable`; if not, that's
     bucket-(a) work and may bubble into HumanProtocol scope.)
   - Change `completion` to
     `@Sendable @escaping (Result<GatewayResponse, Error>) -> Void`.
   - Inside the `Task { ... }`, hop to `@MainActor` before
     invoking: `await MainActor.run { completion(.success(...)) }`.
   - Make `_connection` access safe: either an `actor` wrapper
     OR keep the `NSLock` discipline but mark stored properties
     `nonisolated(unsafe)`.
   - Update the `sendMessage(_:channel:)` extension's
     `withCheckedThrowingContinuation` adapter to the new payload
     type.
   - Add `IntentHandlerConcurrencyTests` (see Test strategy).
7. **Consumer builds.** Run from worktree root:
   ```sh
   cd apps/macos && swift build
   cd apps/ios && xcodebuild -project HumaniOS.xcodeproj \
     -scheme HumaniOS -destination 'generic/platform=iOS' \
     build CODE_SIGNING_ALLOWED=NO
   ```
   Both must succeed with no new `unsafeFlags`. If a consumer
   breaks because a now-`@MainActor` method needs `await`,
   update the call site — this is in scope (the consumer
   compile is part of AC-45.4.4).
8. **Final verification.** Run `swift test` in HumanKit. Then
   `/verify`. Then the diff grep gates:
   ```sh
   git diff origin/main... -- apps/shared/HumanKit/ \
     | grep -E '^\+.*@unchecked Sendable' && exit 1 || true
   git diff origin/main... | grep -E 'strict-concurrency=complete' \
     && exit 1 || true
   ```
   Both must exit 0 (no matches).
9. **Commit.** One commit. Subject:
   `feat(humankit): Swift 6 language mode + @available coverage`.

## Risks

- **Hidden race count (MEDIUM / MEDIUM)**: 2 races pre-identified;
  Swift 6 may surface 3-15 more across 5 targets (especially
  HumanOnDeviceServer's HTTPServer which is currently
  `@unchecked Sendable` and likely real-race-positive). Mitigation:
  step 1's diagnostic sweep is the gate. If non-trivial fixes
  exceed ~6 sites OR any single fix is >50 LOC, STOP and surface
  to product-owner to split into US-45.4a (Package.swift +
  @available + docs) and US-45.4b (race remediation per target).
- **`@unchecked Sendable` regression (LOW / LARGE)**: implementer
  under time pressure may add `@unchecked` to silence a warning.
  Mitigation: step 8's diff grep gate is the hard fail.
  AC-45.4.1 makes this a release-blocker.
- **`Any` in completion (MEDIUM / MEDIUM)**: the current
  `Result<Any, Error>` API leaks across the Sendable boundary.
  Changing it to a typed payload is a SOURCE-BREAKING change for
  consumers (`apps/macos`, `apps/ios`, possibly App Intents).
  Mitigation: step 7 builds both consumers; any breakage gets
  fixed in the same commit. If the call-site count exceeds ~5
  external sites, surface to product-owner — may justify keeping
  a deprecated `Any` overload for one release.
- **Consumer Xcode project build (MEDIUM / LARGE)**: the iOS
  consumer is `HumaniOS.xcodeproj` (XcodeGen-generated from
  `project.yml`). xcodebuild may behave differently than `swift
  build`; the CI `human-kit-swift` job is the source of truth.
  Mitigation: don't claim done without the actual CI job
  passing on a PR push; local xcodebuild is a smoke check, not
  the contract.
- **AvailabilityError vs warning (LOW / SMALL)**: AC-45.4.2
  demands `error:` not `warning:` for a consumer targeting
  macOS 13 / iOS 16. Mitigation: this is the Swift compiler's
  default behavior for `@available(macOS 14.0, *)` when a
  caller's `-target` is below the floor; verify once during
  step 3 by temporarily building a tiny consumer target with
  `.macOS(.v13)` and confirming `error:` in the output.
- **`AnyCodable` Sendability (LOW / MEDIUM)**: if `AnyCodable`
  (used in `HumanProtocol`) is not `Sendable`, then the
  `request(...)` payload typing in step 6 ripples into
  HumanProtocol. Mitigation: if so, mark `AnyCodable: Sendable`
  in the same commit (it should be — it wraps `Any` but the
  wrapper itself is a value type; mark `@unchecked Sendable`
  ONLY IF... NO. The contract forbids it. Use a real Sendable
  conformance: AnyCodable's stored `value: Any` is the
  unsoundness; introducing
  `extension AnyCodable: @unchecked Sendable` would violate the
  AC. Real fix: make `AnyCodable`'s `value` type-erase to
  `any Sendable & Codable`, OR document that `AnyCodable` is
  not Sendable and route HumanGatewayClient via a different
  serialized payload type). Surface to tech-lead if this
  ripples.
- **Observability (LOW)**: log on the queue-guarded
  `requestTimeoutSeconds` setter so prod can detect unexpected
  mutations; assists post-hoc debugging if the race was real
  in deployed clients.

## Test strategy

Two NEW XCTestCase files in
`apps/shared/HumanKit/Tests/HumanClientTests/`:

### HumanConnectionConcurrencyTests
- `test_requestTimeoutSeconds_concurrent_writes_does_not_crash`:
  - 1000 concurrent `Task`s split half-readers / half-writers.
  - After `await`-ing all, assert no crash, current value is one
    of the written values, and the read tasks observed a value
    each time.
- `test_requestTimeoutSeconds_isolated_set_visible_on_next_read`:
  - Set value, read value on a different thread, assert equal.

### IntentHandlerConcurrencyTests
- `test_request_completion_dispatched_on_main_actor`:
  - From a `Task.detached` (background), call
    `HumanGatewayClient.shared.request(method:..., completion:)`.
  - In the completion, assert
    `dispatchPrecondition(condition: .onQueue(.main))`.
  - Use an `XCTestExpectation` to fulfill on completion.
  - Use a stubbed connection or an unreachable URL so the
    completion fires within reasonable test time with
    `.failure(.notConnected)`.
- `test_request_completion_is_sendable_across_isolation`:
  - Compile-time: pass a `@Sendable` closure literal — if the
    parameter type wasn't `@Sendable`, this would warn.

Build-level: AC-45.4.1, AC-45.4.2, AC-45.4.4 are validated by
`swift build` itself + the two grep gates in step 8. No new
integration tests needed for the @available / doc-comment work
— the compiler IS the test.

## Acceptance criteria mapping

- **AC-45.4.1** (Package.swift v6 mode + zero Sendable warnings
  + no `@unchecked Sendable` in diff) →
  - `swift build` exits 0 with zero warnings.
  - `git diff origin/main... | grep '^\+.*@unchecked Sendable'`
    returns empty (step 8 gate).
- **AC-45.4.2** (top-level public types annotated; consumer
  targeting macOS 13 sees compile error) →
  - Step 3 grep loop returns zero `MISS:` lines.
  - Manual one-time check with a `.macOS(.v13)` consumer
    confirms `error:` not `warning:`.
- **AC-45.4.3** (real races fixed via structured concurrency,
  with a new XCTestCase exercising the path) →
  - `HumanConnectionConcurrencyTests` ships and is green.
  - `IntentHandlerConcurrencyTests` ships and is green.
  - No `@unchecked Sendable` introduced (step 8 gate).
- **AC-45.4.4** (consumer build clean, no `unsafeFlags`) →
  - `apps/macos && swift build` exits 0.
  - iOS xcodebuild succeeds; CI `human-kit-swift` job green.
  - `git diff | grep 'strict-concurrency=complete'` returns
    empty (step 8 gate).

## Out of scope

- The three existing `@unchecked Sendable` declarations in
  `HumanOnDevice*` (`OnDeviceRouter`, `HTTPServer`,
  `OnDeviceChatAdapter`) — IF Swift 6 mode does not surface new
  diagnostics on them. If it does, scope-renegotiate (see Risks).
- Objective-C interop annotations (`@objc`, NSCopying, etc.).
- watchOS / tvOS availability macros.
- Migrating `apps/macos` or `apps/ios` app-layer Swift sources
  to Swift 6 mode. Only the HumanKit package boundary is in
  scope; the consumers compile against a Swift 6 dependency
  while themselves remaining on Swift 5 mode.
- Renaming or restructuring HumanProtocol / HumanClient APIs.
  Only annotation + concurrency-safety changes.
- Test-target migration to Swift 6. Test targets stay on the
  current mode unless `swift build` itself forces otherwise.
