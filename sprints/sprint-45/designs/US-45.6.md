# Design for US-45.6: Entitlements + Fastfile + Bundle ID

> Risk tier: MEDIUM-HIGH (sandbox / signing surface; aspect-panel mandatory at merge)
> Story: `sprints/sprint-45/stories.md` lines 239-292
> Sequence: ordered after US-45.1 (project.yml), before US-45.2 (notarize) + US-45.3 (iOS IPA)

## Approach

US-45.6 lands the **declarative artefacts** that downstream signing stories
depend on. Three deliverables:

1. **macOS app entitlements plist** at `apps/macos/Human.entitlements` — three
   keys only (`app-sandbox=YES`, `network.client=YES`, `network.server=NO`).
   This plist is disjoint from the daemon's `resources/human.entitlements`;
   DO NOT touch the daemon file.
2. **Wiring** — US-45.1's freshly-created `apps/macos/project.yml` declares
   `CODE_SIGN_ENTITLEMENTS: Human.entitlements` and confirms bundle id
   `ai.human.mac`. iOS bundle id `ai.human.ios` already lives in
   `apps/ios/project.yml:34` (verified). Fastlane `apps/fastlane/Appfile`
   uses per-platform `for_platform` blocks (NOT top-level array form —
   prior critic finding: array silently picks first element).
3. **Fastfile lanes** at `apps/Fastfile` — `mac_archive` and `ios_archive`,
   pure delegators to scripts owned by US-45.2 / US-45.3
   (`scripts/notarize-mac.sh`, `scripts/ios-archive-export.sh`). Both
   currently absent; lanes raise `UI.user_error!` when the delegate is
   missing. `mac_archive` accepts `skip_codesign:true` per AC-45.6.4.
4. **CI gate** — `entitlements-check` job (new step in
   `.github/workflows/native-apps-fleet.yml`): `plutil -lint` + negative
   grep over an EXTENDED block-list. **No `continue-on-error: true`.**

Boring options chosen everywhere. No new abstractions. The lanes are 3-5
lines apiece; the Appfile is 8 lines; the plist is 12 lines.

## Implementation steps (for the implementer agent)

1. **Write the entitlements plist.** `apps/macos/Human.entitlements` —
   plist DTD, three keys, no others. Validate locally with `plutil -lint`.
2. **Update `apps/macos/project.yml`** (assumed already created by US-45.1):
   - Under the macOS target's `settings.base`, add
     `CODE_SIGN_ENTITLEMENTS: Human.entitlements`.
   - Confirm `PRODUCT_BUNDLE_IDENTIFIER: ai.human.mac` is present.
   - Add a YAML comment: `# Path is resolved relative to SRCROOT after XcodeGen materialises the project.`
3. **Write `apps/fastlane/Appfile`** with two `for_platform` blocks —
   `:mac → "ai.human.mac"`, `:ios → "ai.human.ios"`. NOT a top-level
   array literal (prior critic).
4. **Write `apps/Fastfile`**:
   - `default_platform(:mac)`.
   - `platform :mac do … lane :mac_archive do |options| … end end`.
   - Lane body: if `scripts/notarize-mac.sh` not executable, `UI.user_error!`.
     Otherwise `sh("../scripts/notarize-mac.sh", *args)` where
     `skip_codesign:true` short-circuits to `xcodebuild archive` per
     AC-45.6.4 and the absence of the cert-import step.
   - Same shape for `:ios → ios_archive` calling
     `scripts/ios-archive-export.sh`.
   - Comment block accurately describes the failure mode (prior critic:
     comment must match code).
5. **Add `entitlements-check` job** to `.github/workflows/native-apps-fleet.yml`:
   - Triggers when paths under `apps/macos/**` change.
   - Step 1: `plutil -lint apps/macos/Human.entitlements`.
   - Step 2: Bash `grep -E` over the block-list (below). NON-ZERO if any
     hit; `set -euo pipefail`; NO `continue-on-error`.
   - Step 3: positive grep — confirm `app-sandbox` is present.
   - Step 4: `cd apps && fastlane lanes` exits 0 (AC-45.6.3).
6. **Smoke verify locally**:
   - `xcodegen generate --spec apps/macos/project.yml` (after US-45.1 lands)
   - `codesign -d --entitlements - path/to/Human.app` matches the plist
   - `cd apps && bundle exec fastlane lanes` shows `mac_archive` and
     `ios_archive` without parse error.

## Block-list (extended; surface in CI step verbatim)

```
com.apple.security.cs.disable-library-validation
com.apple.security.cs.allow-unsigned-executable-memory
com.apple.security.cs.disable-executable-page-protection
com.apple.security.cs.allow-dyld-environment-variables
com.apple.security.cs.allow-jit
com.apple.security.cs.debugger
com.apple.security.temporary-exception        # PREFIX MATCH — block entire namespace
```

The temporary-exception entry must be a **prefix match** (e.g.
`grep -E 'com\.apple\.security\.temporary-exception(\.|$)'`) so that
namespace expansions like
`com.apple.security.temporary-exception.files.absolute-path.read-only`
are also caught.

## Risks

- **Entitlement drift in later stories (MED probability / LARGE impact).**
  A future PR adds a "small" entitlement (JIT, library-validation off) to
  unblock something and the binary silently fails hardened-runtime
  notarization in US-45.2. Mitigation: the CI block-list grep is the
  structural guard; it runs on every PR touching `apps/macos/**`; **no
  `continue-on-error: true`**.
- **Block-list bypass via `temporary-exception.*` (MED / LARGE).** Apple's
  temporary-exception namespace has many children. Mitigation: prefix
  match (above), pinned by a CI fixture that asserts the grep catches at
  least one synthetic child key.
- **Appfile array-form footgun (MED / MED).** `app_identifier
  ["ai.human.mac", "ai.human.ios"]` parses successfully but silently uses
  only the first element, so iOS lanes sign as the macOS app. Mitigation:
  per-platform `for_platform` blocks; AC-45.6.3 asserts string scalars,
  not arrays.
- **Comment-vs-code drift in Fastfile (LOW / MED).** Prior critic round
  found a Fastfile comment describing behavior the code didn't implement.
  Mitigation: each lane is 3-5 lines, comment block summarises the exact
  failure mode (`UI.user_error!` on missing delegate).
- **Daemon entitlements collateral damage (LOW / LARGE if violated).**
  `resources/human.entitlements` is the *daemon* sandbox plist with
  different rules. Touching it would change the daemon's runtime posture.
  Mitigation: design explicitly forbids; file is in a different directory.
- **XcodeGen path resolution (LOW / MED).** `CODE_SIGN_ENTITLEMENTS`
  resolves relative to SRCROOT after generation, not relative to
  `project.yml`. Mitigation: file lives at `apps/macos/Human.entitlements`,
  project at `apps/macos/project.yml`, so bare filename works; YAML
  comment documents this.
- **Bundle-ID drift (LOW / SMALL).** Mac id in `project.yml` must equal
  Appfile mac `app_identifier`. Both pinned to `ai.human.mac` in the same
  story; AC-45.6.5 grep proves it.
- **Dependence on US-45.1 ordering (LOW / SMALL).** `apps/macos/project.yml`
  is created by US-45.1; if 45.6 lands first, the project.yml edit
  becomes a creation. Mitigation: story dependency stated; implementer
  rebases onto US-45.1 before starting.

## Test strategy

- **CI gate `entitlements-check`** (AC-45.6.2): `plutil -lint` + negative
  grep + positive grep + `fastlane lanes` syntax check. NO
  `continue-on-error`.
- **CI fixture for prefix match** (small): a tiny synthetic plist in
  `tests/fixtures/entitlements-blocklist-probe.plist` containing
  `com.apple.security.temporary-exception.files.absolute-path.read-only`;
  a CI step asserts the block-list grep flags it. Pins the prefix match.
- **Local smoke**: XcodeGen regenerates without error and the generated
  `.xcodeproj` references `Human.entitlements` in the target's build
  settings (`grep -r 'Human.entitlements' apps/macos/*.xcodeproj/`).
- **`fastlane lanes` parse smoke** (AC-45.6.3): runs in CI; exits 0.
- **`codesign -d --entitlements -` on the archived `.app`** is exercised
  by US-45.1 (archive) + US-45.2 (notarize). 45.6 doesn't ship a signing
  smoke itself; the entitlements bytes are the contract.

## Out of scope

- Actual signing identity / Developer ID / provisioning profile config (US-45.2, US-45.3)
- `scripts/notarize-mac.sh` body (US-45.2)
- `scripts/ios-archive-export.sh` body (US-45.3)
- iOS Info.plist edits (US-45.3 territory)
- Daemon sandbox plist (`resources/human.entitlements`) — disjoint, do not touch
- Any new entitlement key beyond the three minimal ones — **mandates aspect-panel review**
- App Store Connect API key management, push entitlements, iCloud entitlements (per story line 290-292)

## ASPECT-PANEL trigger

Per story risk tier (MEDIUM-HIGH): **aspect-panel mandatory before merge**
(story line 282). If the implementer needs to add ANY new entitlement
beyond the three minimal keys, the change requires panel approval before
merge. The CI block-list does not enumerate every dangerous entitlement
category (e.g. `personal-information.*`, `device.usb`); the panel is the
safety net.
