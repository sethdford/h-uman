# Design for US-42.2: Persona encryption-at-rest

**Story:** Encrypt persona JSON at rest with libsodium secretbox.
Key in macOS Keychain (darwin) or 0600 keyfile (linux).
**Risk:** HIGH — key bugs cause permanent persona data loss.

## Approach

Two new files form the persona-crypto layer:

- `include/human/persona/crypto.h` — public surface
- `src/persona/persona_crypt.c` — implementation

The boundary is a **pure classifier predicate** (`hu_persona_classify_bytes`)
that inspects the first 4 bytes of any file read off disk and returns one of
`PLAINTEXT | ENCRYPTED | MIGRATION_PENDING | INVALID`. `load_encrypted` and
`load_legacy` both call this predicate — single source of truth, isolated from
the I/O boundary per `security-predicate-extraction.md`.

On darwin we wire the existing `keychain_available=false` stub in
`src/security/keystore.c:536` to Security.framework
(`SecItemCopyMatching` / `SecItemAdd` with service `"hu.persona.key"`,
account `"persona-secretbox"`). On linux we drop the key as a 0600 file at
`~/.human/.persona_key` (mode is **asserted** at open-time via `fstat`, error
if widened). Linux key creation uses a **bounded `O_CREAT | O_EXCL`
retry loop (≤3 attempts)** — never recurse on `EEXIST`.

Migration is the critical path. The on-disk shred MUST call
`shred_and_unlink()` after the encrypted artifact is fsync'd into place.
Sequence:

1. read plaintext into a libsodium-locked buffer (`sodium_mlock`)
2. write `<persona>.json.tmp` with sentinel + nonce + ciphertext + MAC
3. `fsync` tmp; `rename` tmp → `<persona>.json` (atomic)
4. `fsync` containing directory
5. write `<persona>.json.migration_done` sentinel
6. **call `shred_and_unlink(<plaintext_backup_path>)`** — zero-overwrite the
   `.legacy` snapshot we created in step 0, fsync, then `unlink`
7. clear in-memory plaintext via `sodium_memzero`

The prior session zeroed memory but skipped step 6. This design names the
call site explicitly: **`persona_crypt.c::hu_persona_migrate_to_encrypted`,
immediately after the `.migration_done` write and before returning HU_OK.**

We default to libsodium `crypto_secretbox_xsalsa20poly1305`. If libsodium is
unavailable at build time, fall back to existing
`include/human/crypto.h` ChaCha20+HMAC-SHA256; the header documents both
paths and which compiled in via `HU_PERSONA_CRYPTO_BACKEND`.

## Public surface (header sketch)

```c
typedef enum {
    HU_PERSONA_BYTES_PLAINTEXT,
    HU_PERSONA_BYTES_ENCRYPTED,
    HU_PERSONA_BYTES_MIGRATION_PENDING,
    HU_PERSONA_BYTES_INVALID
} hu_persona_byte_class_t;

/* Pure predicate — no I/O, no allocation. Single source of truth used by
 * BOTH load_encrypted and load_legacy. Inspects first 4 bytes for sentinel
 * "hupe" (0x68 0x75 0x70 0x65) and checks for adjacent .migration_done file
 * via the caller-supplied bool. */
hu_persona_byte_class_t hu_persona_classify_bytes(
    const uint8_t *buf, size_t len, bool migration_done_present);

hu_error_t hu_persona_save_encrypted(const hu_persona_t *p, const char *path);
hu_error_t hu_persona_load_encrypted(hu_persona_t **out, const char *path);
hu_error_t hu_persona_load_legacy(hu_persona_t **out, const char *path);
hu_error_t hu_persona_migrate_to_encrypted(const char *path);
```

## Implementation steps (for the implementer agent)

1. **Skeleton + error codes.** Add the 4 error codes; add the header with
   types and prototypes; add empty `persona_crypt.c` with stubs returning
   `HU_ERR_NOT_SUPPORTED`. Wire CMake. Confirm compiles + links.
2. **Pure classifier.** Implement `hu_persona_classify_bytes`. Pin with 8
   tests (each byte-class × migration_done flag, plus truncated buffer,
   empty buffer, NULL).
3. **Keystore — linux keyfile.** Implement bounded `O_CREAT|O_EXCL` retry
   (≤3 attempts, `usleep(50ms)` between, fail with `HU_ERR_IO_BUSY` on
   exhaustion). Implement mode-assertion on open (`fstat`, fail if
   `st_mode & 077`). Pin with 4 tests: happy path, mode-too-wide rejection,
   EEXIST-once-then-success, EEXIST-exhausted.
4. **Keystore — darwin Keychain.** Replace `keychain_available = false` at
   `keystore.c:536`. New file `keystore_darwin.c` with `SecItemAdd` /
   `SecItemCopyMatching`. Pin with 2 tests (skipped on non-darwin via
   `#ifdef __APPLE__`).
5. **Encrypt + Decrypt round-trip.** Implement `save_encrypted` and
   `load_encrypted`. Wire-format: `[4 byte sentinel][24 byte nonce][N byte
   ciphertext+16 byte MAC]`. Test: AC-42.2.1 (sentinel + json_parse fails),
   AC-42.2.2 (round-trip equality field-by-field).
6. **Legacy refusal predicate.** `load_legacy` returns
   `HU_ERR_LEGACY_REFUSED` if `.migration_done` sentinel is present in the
   same directory. Pin with 1 test (AC-42.2.3 final clause).
7. **Migration with shred.** Implement `migrate_to_encrypted`. **The
   shred_and_unlink call site lives at the end of the function, after
   `.migration_done` is written and fsync'd.** Pin with 3 tests:
   AC-42.2.3 (shred actually zeros the bytes — re-open file and verify
   zero), AC-42.2.5 (truncated-tmp recovery), and an ASan-verified
   in-memory zero check.
8. **Integration in `persona.c`.** Gate on `HU_PERSONA_ENCRYPT=1` config
   key. Pin with 1 end-to-end test (save → reload via `hu_persona_load`).
9. **doctor_fix surface.** Add encrypted-personas check. Pin with 1 test.
10. **Run full suite + ASan. Run `/verify`.**

## Risks

- **Data loss in migration (HIGH/LARGE).** A bug in migrate ordering can
  delete plaintext before encrypted is durably on disk. Mitigation:
  fsync(tmp) → rename → fsync(dir) → write `.migration_done` → fsync(dir)
  → THEN shred. Tested via AC-42.2.5. Recovery path keys off
  `.migration_done` sentinel presence.
- **shred_and_unlink not called (MED/LARGE).** Prior session caught
  exactly this. Mitigation: explicit call site named in design; a test
  re-opens the post-migration `.legacy` backup path and asserts every byte
  is zero. Test fails if shred is skipped.
- **EEXIST infinite recursion (MED/MEDIUM).** Prior session had recursive
  retry. Mitigation: bounded loop, max 3 attempts, returns `HU_ERR_IO_BUSY`
  on exhaustion. Pinned by `persona_crypto_eexist_race_terminates_after_3_attempts`.
- **Key leak in memory (MED/LARGE).** libsodium keys live in process
  memory. Mitigation: `sodium_mlock` on key buffers, `sodium_memzero` in
  cleanup, ASan-verified.
- **Darwin Keychain prompt UX (LOW/MED).** SecItemAdd may prompt on first
  use. Mitigation: use `kSecAttrAccessible = kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`
  so it's silent after first unlock and not iCloud-synced.
- **Substring classifier (LOW/SMALL).** Per
  `substring-classifier-pitfalls.md`: classifier predicate uses
  byte-exact 4-byte match, not substring. Safe.
- **Backward compatibility (MED/MEDIUM).** Existing plaintext personas in
  the wild. Mitigation: `hu_persona_load` dispatches to
  load_encrypted on sentinel, load_legacy otherwise; load_legacy migrates
  on success. After migration, load_legacy on the same path is refused.
- **Test pinning the bug (LOW/SMALL).** Per `tests-that-pin-bugs.md`:
  every adversarial test asserts the **dangerous case is blocked** —
  `HU_ASSERT_EQ(result, HU_ERR_LEGACY_REFUSED)`,
  `HU_ASSERT_EQ(bytes[i], 0)` — not `HU_ASSERT_TRUE(file_exists)`.

## Test strategy

- Unit: `tests/test_persona_crypto.c`, 18–22 tests. Both targeted
  (`--filter=persona_crypto`) and full-suite runs required before close
  (`quality-gates.md`).
- ASan: full suite under dev preset (the default). Specifically:
  sodium_mlock'd buffers must not leak; `sodium_memzero` paths must
  execute on all return branches.
- Gate symmetry: source `src/persona/persona_crypt.c` is gated
  `if(HU_ENABLE_PERSONA_CRYPTO)`. Test file uses **internal-#ifdef-wrap-
  with-stub-runner** pattern per `.claude/rules/test-source-gate-symmetry.md`
  so the runner symbol resolves in minimal/no-sqlite variants.
- Production-symbol reference (per
  `.claude/rules/test-references-production-symbol.md`): test file
  includes `human/persona/crypto.h` and calls `hu_persona_save_encrypted`
  / `hu_persona_load_encrypted` etc. — never re-implements them.
- Cross-language boundary: N/A (pure C).
- /verify after step 10.

## Out of scope

- Touch ID / biometric unlock (called out in story).
- SQLite personal-model encryption (separate path, separate sprint).
- Re-encrypting key material on hostname/UID change.
- Key rotation primitives (`hu_persona_key_rotate`) — design only,
  no implementation this sprint.
- iCloud Keychain sync (explicitly disabled via
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`).
- Changing `src/persona/persona.c` core JSON serialization. We add
  encrypt-on-save and decrypt-on-load wrappers; the JSON format itself
  does not change.
