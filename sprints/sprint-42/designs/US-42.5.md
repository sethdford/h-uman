# Design for US-42.5: Privacy posture command — `human doctor --privacy`

## Approach

Thin aggregator. New `src/doctor_privacy.c` exposes
`hu_doctor_check_privacy(const hu_doctor_privacy_opts_t *, hu_doctor_privacy_result_t *)`,
which runs four sub-checks. Each sub-check delegates to the production predicate
already defined by US-42.1 / 42.2 / 42.3 / 42.4 — it does **not** re-implement
the logic. Result is rendered as plain text or JSON.

Every sub-check reads PRIMARY evidence on each invocation (no module-level
caches, no global flags):

- **DP-ε**: load most recent accountant state via the US-42.1 reader
  (`hu_dp_accountant_load_latest()` returning `~/.human/dp/accountant.json`
  contents). If no run recorded, sub-check is `ok=true` with sentinel
  message — absence is not a failure (AC-42.5.3).
- **persona-encrypted**: enumerate `~/.human/personas/*.json` and call
  `hu_persona_classify_bytes()` (US-42.2) on each. ALL must classify as
  encrypted; the first unencrypted file is the evidence_path.
- **build-reproducible**: read compile-time constant `HU_BUILD_REPRODUCIBLE`
  defined by US-42.3 CMake flag. `#ifndef HU_BUILD_REPRODUCIBLE #error` so
  the build fails loudly if US-42.3 hasn't shipped.
- **signature-verified**: resolve the running binary's path via
  US-42.4's `hu_artifact_self_path()` helper, then call
  `hu_artifact_sign_verify()` (US-42.4). Map outcomes per US-42.4 design:
  `HU_OK` → YES, `HU_ERR_NOT_FOUND` → `NO (NOT_FOUND)`,
  `HU_ERR_SECURITY_DENIED` → `NO (TAMPERED)`.

### Dispatch wiring

`cmd_doctor` lives in **`src/main.c`** (line 616, not `src/doctor.c`).
Existing precedence inside `cmd_doctor` is: subcommand (`imessage`/`verifier`/
`scheduler`/`responses`) → `--fix` → default. Insert `--privacy` between
subcommand-detection and the existing `--fix` scan. New order, hard-coded:

1. subcommand (`imessage`/`verifier`/`scheduler`/`responses`)
2. `--install` (sprint-43 reserved — no-op stub returns `HU_ERR_NOT_SUPPORTED`
   with a "reserved for sprint-43" message so the precedence test compiles
   today and the flag is owned)
3. `--privacy`
4. `--fix`
5. default report

Pinned by a precedence test: `human doctor --privacy --fix` exits via the
`--privacy` path; bare `--fix` continues to use the existing path; bare
`doctor` is unchanged.

### Doctor-lies defense

A posture command that returns false-positives is worse than no command —
the dominant risk. Each sub-check returns
`{bool ok; const char *message; char evidence_path[PATH_MAX];}`. The
aggregator refuses to emit `ok=true` for any sub-check whose `evidence_path`
is empty: this catches a stub or mock that returned YES without reading
primary evidence. Test injects each predicate via `HU_IS_TEST`-gated function
pointers (same pattern as `src/agent/m3.c`) to return YES with empty
evidence and asserts the doctor command refuses the claim.

## Implementation steps

1. **Skeleton (no behavior)**: header + empty .c that returns
   `HU_ERR_NOT_SUPPORTED`. Wire CMake + test_main.c with an empty
   `run_doctor_privacy_tests`. Confirms the test/source gate-symmetry
   rule is satisfied before any logic lands.
2. **Lie-detector tests first** (must fail): assert that when a sub-check
   reports YES, `evidence_path` is non-empty and points to a readable
   file. The stub fails all five — good baseline.
3. **Sub-check 1: dp-epsilon** — call US-42.1 reader, evidence_path =
   accountant file path. Implement AC-42.5.3 no-run → ok=true.
4. **Sub-check 2: persona-encrypted** — opendir/readdir
   `~/.human/personas`, call `hu_persona_classify_bytes()` per file.
   Evidence_path = first unencrypted file, or "<no personas>" sentinel
   (vacuously true when no personas exist).
5. **Sub-check 3: build-reproducible** — read compile-time macro;
   evidence_path = `<compile-time:HU_BUILD_REPRODUCIBLE=1>` sentinel.
6. **Sub-check 4: signature-verified** — call US-42.4 self-path helper
   + `hu_artifact_sign_verify`. Map error codes per AC-42.5.4.
7. **Text emitter** — four lines per AC-42.5.1; remediation hint to
   stderr per AC-42.5.2.
8. **JSON emitter** — emit BOTH flat top-level keys
   (`persona_encrypted`, `build_reproducible`, `signature_verified`,
   `dp_epsilon`, `ok`) per AC-42.5.5 AND a `checks[]` array with
   `{name, ok, message, evidence_path}` per the brief.
9. **Wire `--privacy` and `--install` stub** in `cmd_doctor`
   (`src/main.c:616`) with documented precedence order.
10. **Lie-detector wiring**: aggregator refuses to emit ok=true when
    evidence_path is empty, even if the sub-check returned ok=true.
    Tests inject each predicate to return YES-with-empty-evidence and
    assert command exits non-zero.

## Risks

- **Doctor lies (HIGH/LARGE)** — a sub-check returns YES without
  verifying primary evidence. Mitigation: `evidence_path` required on
  every YES; aggregator gates on non-empty; lie-detector tests inject
  each predicate.
- **Cached state drift (MED/MED)** — sub-checks cache results across
  invocations and miss a regression. Mitigation: no module-level
  statics in `doctor_privacy.c`; test mutates a persona file between
  two calls and asserts the second call sees the new state.
- **Self-binary path resolution (LOW/MED)** — `/proc/self/exe` vs
  `_NSGetExecutablePath` portability. Mitigation: delegate to
  US-42.4's `hu_artifact_self_path()`; if absent, BLOCK and add to
  US-42.4 scope (escalate via critic; do not roll our own).
- **Sibling-story dependency lag (MED/MED)** — US-42.1/2/3/4
  predicates may not all be landed when this story is implemented.
  Mitigation: implement sub-checks behind `#ifdef HU_HAVE_<feature>`
  guards; missing dependency → sub-check reports `INCONCLUSIVE`
  (ok=false, message="dependency US-42.X not built") rather than
  crashing. Pinned by a build-variant test.
- **`--privacy` vs `--fix` precedence (LOW/SMALL)** — existing
  `doctor --fix` path must not break. Mitigation: explicit precedence
  test exercises both flags; bare `--fix` unchanged; default report
  unchanged.
- **JSON shape mismatch (MED/SMALL)** — AC-42.5.5 wants flat keys;
  brief wants per-check `{name, ok, message, evidence_path}`.
  Mitigation: emit both shapes. Test pins both with `jq`.
- **Observability (LOW/SMALL)** — user must know which check failed.
  Mitigation: all four lines / four keys always emitted; no early
  return.

## Test strategy

`tests/test_doctor_privacy.c` (~420 LOC, ~20 tests):

- 5 AC mapping tests (one per AC)
- 5 lie-detector tests (one per sub-check + aggregate)
- 1 cache-freshness test (mutate file between calls)
- 1 precedence test (`--privacy --fix` → `--privacy` wins)
- 1 JSON shape test (flat keys + `checks[]` both present;
  `jq .ok` correct)
- 1 self-binary path resolution test (delegates to US-42.4)
- 1 empty-persona-dir edge test (vacuously YES)
- 1 build-reproducible-undefined compile-time test (negative compile)
- 1 dependency-missing INCONCLUSIVE test (sibling story not landed)

Predicate injection seam: `HU_IS_TEST`-gated function pointers in
`doctor_privacy.c`'s file scope for each of the four sub-check
predicates (mirrors `src/agent/m3.c`).

## Acceptance criteria mapping

- **AC-42.5.1** → `test_privacy_all_yes_emits_four_lines_exits_zero`
- **AC-42.5.2** → `test_privacy_persona_unencrypted_exits_one_stderr_hint`
- **AC-42.5.3** → `test_privacy_no_training_run_dp_epsilon_na_exits_zero`
- **AC-42.5.4** → `test_privacy_signature_not_found_reports_NOT_FOUND_exits_one`
  + `test_privacy_signature_denied_reports_TAMPERED_exits_one`
- **AC-42.5.5** → `test_privacy_json_flat_keys_validate_with_jq`

Plus the five lie-detector tests covering the HIGH-risk fail-open mode.

## Out of scope

- Automated remediation (read-only posture command).
- New `--install` flag behavior (sprint-43; stub only here so dispatch
  precedence test compiles and the flag is owned).
- Compliance dashboards, SBOM emission, external attestation.
- Changes to `doctor --fix` behavior or the existing subcommand
  branches.
- New sub-checks beyond the four named in the story.
