# Design for US-42.4: Ed25519-Signed Release Artifacts (Fail-Closed)

## Approach

Add a self-contained signature module that verifies the running binary against
an **appended** Ed25519 signature block, using a public key **embedded at
compile time** in `include/human/security/release_pubkey.h`. Verification is
exposed as a small C API:

```c
/* include/human/security/signature.h */
hu_error_t hu_artifact_verify_signature(hu_allocator_t *alloc,
                                        const char *binary_path,
                                        char *err, size_t err_len);

bool hu_artifact_sign_must_reject(hu_error_t rc);  /* pure predicate */
```

The security decision is **factored into a pure predicate**
`hu_artifact_sign_must_reject(hu_error_t rc)` per
`.claude/rules/security-predicate-extraction.md`. Its truth table is trivial,
exhaustive, and testable without I/O:

| rc                          | must_reject |
|-----------------------------|-------------|
| `HU_OK`                     | `false`     |
| `HU_ERR_NOT_FOUND`          | `true`      |
| `HU_ERR_SECURITY_DENIED`    | `true`      |
| (anything else)             | `true`      |

The verifier (`hu_artifact_verify_signature`) uses **fail-closed init**:

```c
hu_error_t rc = HU_ERR_SECURITY_DENIED;   /* baseline DENY */
/* ... checks ... */
if (crypto_sign_verify_detached(...) == 0 && key_sane) {
    rc = HU_OK;                            /* only happy path overwrites */
}
return rc;
```

Every early return, every `goto cleanup`, every error branch preserves the
denied default. There is no path that overwrites `rc` to `HU_OK` except the
single successful libsodium call site.

The signature is **appended** to the binary as a fixed-size footer (per
AC-42.4.2 "bit-flipped at offset +3" — implying a structured trailing block):

```
[ ELF/Mach-O binary ][ SIGNATURE BLOCK 80 bytes ]
                                                 ^EOF
SIGNATURE BLOCK:
  bytes  0..3   magic "HUSG"
  bytes  4..7   version (uint32 LE) = 1
  bytes  8..15  signed-length (uint64 LE) = size of binary BEFORE this block
  bytes 16..79  64 bytes of Ed25519 detached signature
```

Verifier reads the file, checks the trailing 80 bytes for the magic. Magic
mismatch (or file shorter than 80 bytes) → `HU_ERR_NOT_FOUND`. Magic present,
verify fails → `HU_ERR_SECURITY_DENIED`. Verify succeeds AND embedded pubkey
is non-zero → `HU_OK`.

Three-outcome contract maps to `human doctor --privacy` (consumed by US-42.5):
- `HU_OK` → `signature-verified: YES`
- `HU_ERR_NOT_FOUND` → `signature-verified: NO (NOT_FOUND)`
- `HU_ERR_SECURITY_DENIED` → `signature-verified: NO (TAMPERED)`

Startup integration (AC-42.4.4): a single entry point
`hu_artifact_enforce_at_startup()` runs at the **top** of `human init` and
daemon-start, before any config read, network init, or user data touch. On
any non-`HU_OK`, it writes
`artifact signature: DENIED (code=%d)\n` to stderr and calls `exit(1)`.

CI signing lives in `.github/workflows/release.yml` as a new `sign-artifacts`
step that reads `secrets.RELEASE_SIGNING_KEY` (32-byte Ed25519 seed in
base64). The private key never lands on a developer machine; the signing
script (`scripts/sign-release-artifacts.sh`) reads the seed from env,
appends the signature block, and never writes the key to disk.

No fixture binaries on disk — the test suite generates its own keypair from a
fixed seed via `crypto_sign_seed_keypair`, signs an in-memory test artifact,
and writes it to a tmp file inside the test. This avoids the
fixture-regeneration coupling between the embedded production pubkey and the
test artifacts (which would otherwise force fixture-rebuilds whenever the
release key rotates).

To wire the test to a non-production pubkey without leaking a back door into
the release binary, the test reaches into a separate verifier entry point:

```c
/* Internal — test seam ONLY, never exposed in signature.h */
hu_error_t hu_artifact_verify_signature_with_pubkey(hu_allocator_t *alloc,
                                                    const char *binary_path,
                                                    const uint8_t pubkey[32],
                                                    char *err, size_t err_len);
```

`hu_artifact_verify_signature` is a one-line wrapper that passes
`HU_RELEASE_PUBKEY` to the test-seam version. The test seam is declared in
`src/security/artifact_sign_internal.h` (NOT in the public header) and is
called by both production code and tests. This matches the
`security-predicate-extraction.md` discipline: the decision is in a function
the test can call without subprocesses.

## Implementation steps (for the implementer agent)
1. Add `HU_ENABLE_LIBSODIUM` is already in CMake (line 91). US-42.4 turns
   ON. Gate source+test together per `.claude/rules/test-source-gate-symmetry.md`:
   register `src/security/artifact_sign.c` AND `tests/test_artifact_sign.c`
   in the same `if(HU_ENABLE_LIBSODIUM AND HU_LIBSODIUM_FOUND)` block; wrap
   forward decl + call site in `tests/test_main.c` with the matching
   `#ifdef`.
2. Generate the production keypair off-machine. Upload seed to GH secrets as
   `RELEASE_SIGNING_KEY`. Commit `include/human/security/release_pubkey.h`
   containing the public half as a 32-byte literal.
3. Write `signature.h` (public) + `artifact_sign_internal.h` (test seam).
4. Implement `hu_artifact_sign_must_reject(hu_error_t rc)` first — pure,
   one-line function:
   ```c
   bool hu_artifact_sign_must_reject(hu_error_t rc) { return rc != HU_OK; }
   ```
5. Write the predicate truth-table test (4 rows: `HU_OK`, `HU_ERR_NOT_FOUND`,
   `HU_ERR_SECURITY_DENIED`, `HU_ERR_INVALID_ARGUMENT`).
6. Implement `hu_artifact_verify_signature_with_pubkey` with fail-closed init:
   - `hu_error_t rc = HU_ERR_SECURITY_DENIED;`
   - `fopen` + `fseek/ftell` to get size; if size < 80 → `rc = HU_ERR_NOT_FOUND; goto cleanup;`
   - read trailing 80 bytes; check magic "HUSG" → if not present → `HU_ERR_NOT_FOUND`
   - check version == 1; if not → keep `HU_ERR_SECURITY_DENIED`
   - read signed_length from block; if signed_length != file_size - 80 → keep DENIED
   - allocate signed_length bytes; rewind; read; if short read → keep DENIED
   - defensive: if `pubkey` is all-zero → keep DENIED (covered by predicate's
     "must_reject is true unless rc == HU_OK"; the predicate alone is not
     enough — we also defend at the verifier so a corrupt embedded key can
     never reach libsodium)
   - call `crypto_sign_verify_detached(sig, body, signed_length, pubkey)`
   - if 0 returned AND pubkey is non-zero → `rc = HU_OK;`
   - cleanup: free buffer, fclose, return `rc`
7. `hu_artifact_verify_signature` = one-line wrapper passing `HU_RELEASE_PUBKEY`.
8. Implement `hu_artifact_enforce_at_startup`:
   - call verifier on `argv[0]` (resolve via `/proc/self/exe` on Linux,
     `_NSGetExecutablePath` on macOS — both exist in libc/sys, no new dep)
   - on non-`HU_OK`: `fprintf(stderr, "artifact signature: DENIED (code=%d)\n", rc); exit(1);`
9. Write end-to-end verifier tests using deterministic seed (AC-42.4.3):
   ```c
   uint8_t seed[32] = {0x42, 0x42, ...};
   uint8_t pk[32], sk[64];
   crypto_sign_seed_keypair(pk, sk, seed);
   ```
   - **happy path** (AC-42.4.3): sign tmp binary, verify with same pk → `HU_ASSERT_EQ(rc, HU_OK)`
   - **bit-flip at offset +3 of signature block** (AC-42.4.2): flip one bit, verify → `HU_ASSERT_EQ(rc, HU_ERR_SECURITY_DENIED)`
   - **no signature block at all** (AC-42.4.1): use unsigned tmp binary → `HU_ASSERT_EQ(rc, HU_ERR_NOT_FOUND)`
   - **wrong key**: sign with seed A, verify with pk from seed B → `HU_ASSERT_EQ(rc, HU_ERR_SECURITY_DENIED)`
   - **all-zero pubkey defensive**: even with valid sig, all-zero pubkey → `HU_ASSERT_EQ(rc, HU_ERR_SECURITY_DENIED)`
   - **predicate truth table** (AC-42.4.2 last sentence): all 4 rows tested explicitly.
   - **Assertions MUST be `HU_ASSERT_EQ(rc, HU_ERR_SECURITY_DENIED)`** — never
     weak `HU_ASSERT_TRUE(rc != HU_OK)` per
     `.claude/rules/tests-that-pin-bugs.md`.
10. Add the `human doctor --privacy` consumer (delegated detail to US-42.5,
    but the seam must work): map rc → exact strings per AC-42.4.5.
    NB: doctor must NOT re-implement verification — it calls the same entry
    point. Verified by `.claude/rules/test-references-production-symbol.md`
    (test must reference `hu_artifact_verify_signature`).
11. Write `scripts/sign-release-artifacts.sh`:
    ```bash
    set -euo pipefail
    set +x   # never echo the secret
    seed=$(printf '%s' "$RELEASE_SIGNING_KEY" | base64 -d)
    # Append 80-byte HUSG block; build signature over file bytes [0..size]
    python3 scripts/_sign_helper.py "$ARTIFACT" "$seed"
    ```
    Set `+x` is critical — accidentally echoing the seed would land in GH
    Actions logs forever.
12. Wire the workflow step:
    ```yaml
    - name: Sign release artifacts
      env:
        RELEASE_SIGNING_KEY: ${{ secrets.RELEASE_SIGNING_KEY }}
      run: scripts/sign-release-artifacts.sh build/human
    ```
13. Run `./build/human_tests --filter=artifact_sign` then full suite per
    `.claude/rules/quality-gates.md` (the startup change touches `human init`;
    targeted run is not enough).

## Risks
- **Embedded-key corruption / all-zero (LOW/LARGE)**: an all-zero
  `HU_RELEASE_PUBKEY` would still verify some inputs in libsodium (no — it
  fails, but defense-in-depth matters). **Mitigation**: defensive check in
  the verifier; unit test pins the all-zero-pubkey behavior to DENIED.
- **Bypass via `argv[0]` spoofing (MED/LARGE)**: if the binary verifies
  whatever path `argv[0]` points to, an attacker could symlink a signed
  binary while running an unsigned one. **Mitigation**: use
  `/proc/self/exe` (Linux) and `_NSGetExecutablePath` (macOS), never
  `argv[0]`. Documented in the implementation step.
- **Key rotation (MED/MED)**: rotating requires recompiling the binary;
  existing installs cannot verify new releases. **Mitigation**: documented
  out-of-scope (story explicitly excludes "binary update verification");
  rotation runbook will be added with the first rotation. Multi-key support
  deferred.
- **Secret leakage in CI (LOW/CATASTROPHIC)**: `RELEASE_SIGNING_KEY` is a
  GH secret; a stray `set -x` or `echo $RELEASE_SIGNING_KEY` would land it
  in immutable logs. **Mitigation**: signing script has `set +x` before
  reading; helper Python reads from env; no command-line argument carries
  the key. Reviewer must flag any change to the signing script.
- **Reproducibility coupling (HIGH/HIGH)**: US-42.3 (reproducible build)
  is a stated dependency. If the binary's bytes vary between identical
  source revisions, the signature can't be over the same bytes the user
  receives. **Mitigation**: blocked-by note in DoD; do NOT implement
  US-42.4 signing in `release.yml` until US-42.3 lands SOURCE_DATE_EPOCH
  enforcement.
- **Test/Source gate mismatch (MED/MED)**: if libsodium-disabled CI
  variants build the test but not the source (or vice versa), link errors
  appear in 5+ jobs (per `.claude/rules/ci-queue-triage.md` pattern).
  **Mitigation**: both source and test gated together by
  `HU_ENABLE_LIBSODIUM AND HU_LIBSODIUM_FOUND`; test_main.c call site
  `#ifdef`-wrapped. Pre-commit hook
  (`scripts/check-test-source-gate-symmetry.sh`) catches this before push.
- **Tests pinning fail-open (MED/CATASTROPHIC)**: a test that asserts
  `HU_ASSERT_TRUE(rc != HU_OK)` for a tampered binary would PASS even if
  the verifier returned `HU_ERR_INVALID_ARGUMENT` instead of the required
  `HU_ERR_SECURITY_DENIED`. **Mitigation**: all DENIED-path assertions
  must be `HU_ASSERT_EQ(rc, HU_ERR_SECURITY_DENIED)`; explicit in
  implementation step 9. Critic pass should grep `rc != HU_OK` in
  `tests/test_artifact_sign.c` and reject any match.
- **`exit(1)` in startup blocks test mode (MED/SMALL)**: tests can't
  unit-test startup if it calls `exit()`. **Mitigation**: enforcer is a
  thin wrapper; the predicate + verifier are tested directly; startup
  integration is covered by a separate end-to-end test that runs the
  binary as a subprocess (HU_IS_TEST guard skips the enforcer in the test
  binary itself).

## Test strategy
- **Predicate truth table** (4 cases, no I/O): every `hu_error_t` row.
- **Deterministic-seed end-to-end tests** (5 cases, libsodium): happy path,
  bit-flip at offset +3 (AC-42.4.2 exact), no signature block (AC-42.4.1
  exact), wrong key, all-zero pubkey defensive case.
- **Startup-enforcer subprocess test**: spawn `./build/human` (test binary
  with `HU_IS_TEST`=0) twice — once with sig, once without — assert exit
  codes and stderr lines.
- **Doctor seam test** (`tests/test_doctor_privacy.c`): asserts doctor
  surfaces YES / NO (NOT_FOUND) / NO (TAMPERED) by INJECTING the rc
  through the same `hu_artifact_verify_signature` entry point — no
  re-implementation (AC-42.4.5).
- **Full suite + ASan**: per `.claude/rules/quality-gates.md`. The
  startup-path change is high-risk; full suite required before close.

## Acceptance criteria mapping
- **AC-42.4.1** (unsigned binary → `HU_ERR_NOT_FOUND` + predicate true) →
  `tests/test_artifact_sign.c::artifact_sign_unsigned_returns_not_found` +
  `artifact_sign_predicate_not_found_must_reject_returns_true`
- **AC-42.4.2** (bit-flip at offset +3 → `HU_ERR_SECURITY_DENIED` +
  predicate true on DENIED, false on OK) →
  `artifact_sign_bitflip_at_offset_3_returns_security_denied` +
  `artifact_sign_predicate_full_truth_table` (4 rows)
- **AC-42.4.3** (deterministic test keypair → `HU_OK`) →
  `artifact_sign_happy_path_with_seed_returns_ok`
- **AC-42.4.4** (non-`HU_OK` at startup → process exits non-zero, stderr
  log BEFORE network/data) → `tests/test_artifact_sign_startup.c::*` (subprocess
  test) + code review of the call-site placement in `src/init.c`
- **AC-42.4.5** (doctor uses production rc, does not re-implement) →
  `tests/test_doctor_privacy.c::doctor_privacy_signature_check_references_production_symbol`
  (grep-style) + `doctor_privacy_signature_strings_match_three_outcomes`

## Out of scope
- HSM signing infrastructure (story explicit).
- Certificate transparency, TUF, Sigstore (story explicit).
- Automatic binary update verification (`HU_ENABLE_UPDATE` is a separate
  flag — story explicit).
- Multi-key support / rotation tooling (single embedded key; rotation =
  new binary release).
- Counter-signing, threshold signatures.
- Signing artifacts other than the release binary (UI bundle, docs site,
  etc.).
- SBOM generation (non-goal at sprint level, line 322 of stories.md).
- `human doctor --privacy` command implementation itself (that's US-42.5);
  this story provides ONLY the seam that doctor consumes.
