# Design for US-42.1: Real DP-SGD with per-sample gradient clipping and RDP accountant

**Risk:** HIGH — false privacy guarantees ship if RDP math is wrong.
**Estimate:** L
**Branch:** `sprint-42-verifiable-privacy`
**Worktree:** `/Users/sethford/Documents/h-uman/.worktrees/sprint-42-privacy`

## Approach

Carve a canonical DP-SGD translation unit `src/ml/dp_sgd.c` exporting three
pure-predicate-style functions:

1. `hu_dp_sgd_noise_sigma()` — derives effective Gaussian sigma from
   `clip_norm` and `noise_multiplier`. Pure math; pure inputs.
2. `hu_dp_rdp_epsilon_from_sigma()` — Mironov-Talwar-Zhang 2019 Theorem 4
   closed-form RDP for the subsampled Gaussian mechanism over a published
   alpha grid; then Canonne-Kamath-Steinke 2020 Proposition 12 conversion
   to `(epsilon, delta)`. Pure; reproducible; deterministic.
3. `hu_dp_sgd_step()` — per-sample-clip + sum + add Gaussian noise + average,
   given a batch of pre-computed per-sample gradients. Takes a deterministic
   `hu_rng_t *` for test reproducibility.

All three backends (cpu, ggml, mlx) call `hu_dp_sgd_step()`. The ad-hoc
noise paths in `learner_ggml.c:312` and `learner_mlx.c:307` are removed.

The accountant becomes a tiny stateful wrapper on top of (2): per call it
records `(noise_multiplier, sampling_rate, steps)`, and at query time it
re-runs the closed-form across the alpha grid against the **cumulative**
steps. Composition is done in RDP space (additive across calls with the
same `(sigma, q)`) then converted to `(epsilon, delta)` at query time.
This matches Opacus 1.5.x semantics and avoids the AC-42.1.3 race (the
budget check is on the value the next step WOULD produce).

The choice is "cheapest correct": no Moments Accountant table; closed-form
RDP for subsampled Gaussian is a one-page formula and is what Opacus uses
under the hood for the `RDPAccountant` class.

### Alpha grid

`{2, 4, 8, 16, 32, 64, 128, 256}` — 8 orders. Justification:

- Opacus default grid is `[1+1e-10, 1.25, 1.5, ..., 64]` (62 orders) for
  generality. Our budget is tighter (small `delta`, fewer steps), and the
  optimum alpha is typically in `[8, 64]` for `delta=1e-5`. The wider grid
  upper bound (256) is needed because **prior session evidence showed
  alpha=64 saturated for tight budgets** — the monotonicity break in the
  per-alpha epsilon curve occurred at the grid edge, meaning the true
  optimum lay beyond. Extending to 256 closes that.
- Sparse (powers of 2) keeps the loop trivial without sacrificing the
  envelope minimum more than ~0.02 epsilon vs the dense Opacus grid
  (validated against the oracle fixture in AC-42.1.2).

### Per-sample clipping

`hu_dp_sgd_step()` accepts `const hu_dp_per_sample_grad_t *grads, size_t
n_samples` — a flat row-major buffer plus stride/dim metadata. The CPU
backend already produces per-sample gradients; ggml and mlx must be
updated to surface them rather than reducing in-place. For ggml this is
a loop over the batch (acceptable on the CPU path — DP-SGD is opt-in and
not throughput-critical). For mlx, vmap is the right primitive but out
of scope for this story; the design accepts a synchronous per-sample
loop on mlx for the first cut and chips a follow-up for vmap.

### Adversarial AC

The fixture row marked `unclipped: true` in `tests/fixtures/dp_accountant_oracle.json`
exercises the contract that `hu_dp_sgd_step()` MUST reject any input where
the caller bypassed clipping (e.g. passes `clip_norm <= 0` or a grad row
whose pre-computed norm-bound metadata exceeds `clip_norm`). Assertion:
`HU_ASSERT_EQ(rc, HU_ERR_INVALID_ARGUMENT)`. This pins the security
predicate per `security-predicate-extraction.md`.

### Opacus oracle generation (one-time, off-tree)

Generate the fixture once via a Python helper (NOT shipped):

```python
from opacus.accountants import RDPAccountant
a = RDPAccountant()
for _ in range(1000): a.step(noise_multiplier=1.1, sample_rate=0.01)
eps, alpha = a.get_privacy_spent(delta=1e-5)  # alphas default grid
```

Pin `eps`, the `noise_multiplier`, `sample_rate`, `steps`, `delta`, and
the resulting `alpha*` per row. Test asserts `|our_eps - opacus_eps| <= 0.05`.

## Risks

- **R-CURRENT-IS-PER-BATCH (HIGH/LARGE) — CRITICAL FORCING CONSTRAINT:**
  Investigation of `src/ml/learner_cpu.c:320-343` reveals that the existing
  "per-sample" clipping path is in fact **per-BATCH**: it computes ONE summed
  gradient across all samples (loss accumulated into a single `grad_norm_sq`),
  clips that ONE vector to `clip_norm`, then adds noise. True DP-SGD requires
  each sample's gradient to be clipped INDEPENDENTLY to `C` BEFORE summation,
  so any single sample's contribution to the released sum is bounded by `C`.
  The current code's sensitivity is unbounded — one outlier sample can drive
  the batch gradient norm well past `C` and clipping after summation does
  NOT recover the per-sample bound. **The advertised privacy guarantee in the
  current code is mathematically void.** The ggml backend at L306-315 is
  documented "approximate / post-hoc noise on the adapter file" — also void.
  The mlx backend at L306-311 same shape — also void.

  **Forcing constraint on the implementer:** `hu_dp_sgd_step()` MUST accept
  per-sample gradients as separate rows (`hu_dp_per_sample_grad_t *grads,
  size_t n_samples`) and clip EACH ROW to `clip_norm` BEFORE the sum-and-noise.
  Single summed-gradient call shapes MUST be rejected at the API. The CPU
  backend must be REWRITTEN to produce per-sample gradients (one per signal
  in the batch), not the current single accumulated diff vector. The AC-42.1.1
  fixture must include a batch where one row's pre-clip norm is 10×C and
  assert that AFTER `hu_dp_sgd_step()`, the contribution of that row to the
  output is bounded as if its norm were exactly C — not the batch's norm.

  **Source-of-truth contract:** `src/ml/dp_sgd.c` is the SOLE implementation
  of clip+noise. The three backends `learner_cpu.c` / `learner_ggml.c` /
  `learner_mlx.c` MUST delegate to `hu_dp_sgd_step()` and MUST NOT contain
  any in-file `grad_norm` / `noise_sigma` / `prng_normal` arithmetic for
  the DP path. This is enforceable by grep at review time and is pinned by
  the AC-42.1.4 call-counter test (every backend with `dp_enabled=true`
  bumps the canonical counter > 0; if a backend re-implements DP locally,
  the counter stays at 0 and the test fails).

- **Math correctness (HIGH/LARGE):** wrong RDP formula ships false privacy.
  Mitigation: oracle fixture with 4+ Opacus reference points spanning
  small/large `q`, small/large `steps`, tight/loose `delta`. Cross-check
  against the published MTZ 2019 worked example (Table 1 row 1) as a
  fifth independent reference.
- **Alpha grid saturation (MED/MED):** if the optimum alpha exceeds 256,
  the reported epsilon under-estimates the truth (UNSAFE direction).
  Mitigation: emit a `HU_LOG_WARN` when the argmin alpha is at the grid
  boundary (256), so the user sees a "may need wider grid" signal. Pin
  via a test fixture that forces a boundary hit.
- **Numerical overflow (MED/MED):** `log(M_alpha)` for large alpha can
  overflow double for sparse subsampling. Mitigation: compute everything
  in log-space; use `logsumexp` for the RDP-of-subsampled-gaussian sum.
  Pin a test with `q=1e-4, steps=10000, alpha=256`.
- **Backend regression (MED/MED):** changing ggml/mlx noise path could
  break existing learner tests. Mitigation: AC-42.1.5 explicitly asserts
  call-count is 0 when `dp_enabled=false`, so the existing path is
  provably untouched. Run full ML test suite after each backend migration.
- **CMake gate symmetry (LOW/MEDIUM):** new test under `HU_ENABLE_ML`
  could break minimal variant. Mitigation: follow `test-source-gate-symmetry.md`
  — use the internal-`#ifdef`-wrap-with-stub-runner pattern so
  `tests/test_dp_sgd.c` compiles to a no-op when `HU_ENABLE_ML` is off.
  CI variant matrix catches the rest.
- **Concurrency (LOW/SMALL):** accountant is mutated per training step.
  Single-writer (the trainer); read-only at budget check on the same
  thread. No locks needed; comment the invariant.
- **Observability (LOW/SMALL):** at each step the accountant should emit
  a debug-level log of `(cum_steps, epsilon@delta, argmin_alpha)`. Useful
  for posture command (US-42.5).

## Out of scope

- MLX `vmap`-vectorized per-sample gradients (chip a follow-up; CPU loop
  is correct, just slow).
- Federated / cross-device privacy composition (US-42.x non-goals).
- Moments Accountant table (closed-form RDP is what Opacus uses anyway).
- Subsampling models other than Poisson (matches the Opacus fixture
  contract).
- Privacy posture surface — US-42.5 consumes the accountant.
