# Design for US-42.3: Reproducible build flags and deterministic archive generation

## Status
DESIGN_READY

## Approach

The goal is bit-for-bit reproducibility of the `human` release binary under a
frozen `SOURCE_DATE_EPOCH`, gated in CI by a two-build sha256 diff. The change
surface is intentionally small: ~30 lines in `CMakeLists.txt` and two new bash
scripts plus a new CI job. We do NOT introduce a new preset, a new CMake option,
or any conditional build mode — the discipline is unconditional on release/
MinSizeRel builds, where the `human` target already lives behind
`target_compile_options(human PRIVATE …)` (see `CMakeLists.txt:2253-2259`).

The flag surface is the **stronger** sister of what the story text suggests:

| Story text                 | We ship                          | Why                                                  |
|----------------------------|----------------------------------|------------------------------------------------------|
| `-Wno-date-time`           | **`-Werror=date-time`**          | Codebase already runs `-Werror`; weakening to `-Wno-` would silently allow future macro use, defeating AC-42.3.1 ("fails the build immediately"). |
| (unspecified linker)       | linux `-Wl,--build-id=none`; darwin `-Wl,-no_uuid` | Build-id and LC_UUID are the two canonical sources of binary nondeterminism on linux/darwin respectively; both scoped via `target_link_options(human PRIVATE …)`, leaving `human_tests` untouched so ASan symbolication keeps working. |
| (unspecified random seed)  | **deliberately omit `-frandom-seed`** | `-ffile-prefix-map` already canonicalizes the per-TU seed input via the rewritten source path. `-frandom-seed=<const>` would force the same seed across TUs and cause static-local symbol collisions. Documented in a CMake comment so no one re-adds it. |
| `ar -D` (one path)         | linux `ar -D` (probe); darwin `libtool` is deterministic by default | BSD `ar` on macOS rejects `-D`. Two code paths, each pinned by configure-time probe. |
| One CI script (`verify-reproducible-build.sh`) | **Two scripts** + one CI job calling both | Fail-fast: `check-no-date-time-macros.sh` is a fast preprocess+grep; `check-reproducible-build.sh` does the expensive two-build sha256 diff. Fast gate catches the common regression (someone adds `__DATE__`) before the slow gate runs. AC-42.3.1 maps to the fast gate; AC-42.3.4 to the slow gate. |

Two-build diff lives in `.github/workflows/ci.yml` as a new
`reproducible-build` matrix job on `ubuntu-latest` + `macos-latest`. No
`continue-on-error`, required by branch protection.

## Implementation steps (for the implementer)

1. **CMake compile flags.** In the Release/MinSizeRel block at
   `CMakeLists.txt:2251` add (after the `-Os`/`-Oz` lines):
   ```cmake
   target_compile_options(human PRIVATE
       -Werror=date-time
       -ffile-prefix-map=${CMAKE_SOURCE_DIR}=.)
   target_compile_options(human_core PRIVATE
       -Werror=date-time
       -ffile-prefix-map=${CMAKE_SOURCE_DIR}=.)
   # Intentionally OMIT -frandom-seed: -ffile-prefix-map already
   # canonicalizes the per-TU seed; a constant -frandom-seed would
   # cause static-local symbol collisions across TUs.
   ```
   Run `cmake --preset release && cmake --build --preset release`; verify
   the new flags appear in `build-release/compile_commands.json`.

2. **CMake linker flags (platform-scoped).**
   ```cmake
   if(UNIX AND NOT APPLE)
       target_link_options(human PRIVATE -Wl,--build-id=none)
   elseif(APPLE)
       target_link_options(human PRIVATE -Wl,-no_uuid)
   endif()
   ```
   These MUST be on `human` only — `human_tests` keeps LC_UUID so ASan +
   atos symbolicate. Verify after build: `readelf -n build-release/human`
   on linux returns no `.note.gnu.build-id`; `otool -l
   build-release/human | grep LC_UUID` on darwin returns empty.

3. **CMake archive determinism (linux).**
   ```cmake
   if(UNIX AND NOT APPLE)
       execute_process(COMMAND ${CMAKE_AR} -D --version
           RESULT_VARIABLE _ar_d_rc OUTPUT_QUIET ERROR_QUIET)
       if(_ar_d_rc EQUAL 0)
           set(CMAKE_C_ARCHIVE_CREATE "<CMAKE_AR> Dqc <TARGET> <LINK_FLAGS> <OBJECTS>")
           set(CMAKE_C_ARCHIVE_APPEND "<CMAKE_AR> Dq <TARGET> <LINK_FLAGS> <OBJECTS>")
           set(CMAKE_C_ARCHIVE_FINISH "<CMAKE_AR> -D <TARGET>")
       endif()
   endif()
   ```
   On darwin, BSD `ar` doesn't take `-D`; `libtool` (the actual archive
   tool) is deterministic by default — no action needed.

4. **`scripts/check-no-date-time-macros.sh`.** Iterate over TUs from
   `build-release/compile_commands.json`. For each, run the compiler with
   `-E -fpreprocessed -dD` (strips comments AND leaves macros tokenized)
   and grep for the three macros. Exit nonzero with file:line on any hit.
   Smoke-test the script by temporarily injecting `printf("%s\n",
   __DATE__);` into one TU, running the script, expecting nonzero exit;
   revert. (Document the smoke test in script header; do not commit the
   smoke fixture.)

5. **`scripts/check-reproducible-build.sh`.** Pseudocode:
   ```bash
   export SOURCE_DATE_EPOCH=1700000000
   B1=$(mktemp -d); B2=$(mktemp -d)
   cmake -S . -B "$B1" --preset release && cmake --build "$B1" --target human
   cmake -S . -B "$B2" --preset release && cmake --build "$B2" --target human
   H1=$(sha256sum "$B1/human" | awk '{print $1}')
   H2=$(sha256sum "$B2/human" | awk '{print $1}')
   if [ "$H1" != "$H2" ]; then
       # platform-specific carve and diff for operator-friendly failure
       if [[ "$OSTYPE" == "darwin"* ]]; then
           otool -lv "$B1/human" > "$B1/dump.txt"
           otool -lv "$B2/human" > "$B2/dump.txt"
       else
           readelf -aW "$B1/human" > "$B1/dump.txt"
           readelf -aW "$B2/human" > "$B2/dump.txt"
       fi
       diff -u "$B1/dump.txt" "$B2/dump.txt" | head -200
       exit 1
   fi
   # Assert build-id / LC_UUID absent
   if [[ "$OSTYPE" == "darwin"* ]]; then
       otool -l "$B1/human" | grep -q LC_UUID && {
           echo "FAIL: LC_UUID present"; exit 1; }
   else
       readelf -n "$B1/human" | grep -q "GNU.*Build ID" && {
           echo "FAIL: build-id present"; exit 1; }
   fi
   ```
   Accept `--two-build-diff` as a flag (default behavior) so the AC-42.3.4
   invocation reads natural.

6. **CI job `reproducible-build`.** Append to `.github/workflows/ci.yml`:
   ```yaml
   reproducible-build:
     strategy:
       matrix:
         os: [ubuntu-latest, macos-latest]
     runs-on: ${{ matrix.os }}
     steps:
       - uses: actions/checkout@v4
       - name: Install deps (linux)
         if: matrix.os == 'ubuntu-latest'
         run: sudo apt-get update && sudo apt-get install -y cmake build-essential jq
       - name: Configure (no-date-time fast gate prereq)
         run: cmake --preset release
       - name: No __DATE__ / __TIME__ / __TIMESTAMP__ in TUs
         run: bash scripts/check-no-date-time-macros.sh
       - name: Two-build sha256 diff
         run: bash scripts/check-reproducible-build.sh --two-build-diff
   ```
   No `continue-on-error`. Add to branch-protection required checks separately.

7. **Verify locally on both platforms before commit.** Capture sha256 of
   `build-release/human` in the commit body so reviewers can re-run and
   confirm.

## Risks

- **Test symbolication regression (LOW / MED).** Stripping LC_UUID from
  `human_tests` would break ASan symbolication on macOS. Mitigation:
  `target_link_options(human PRIVATE -Wl,-no_uuid)` — *human* target only.
  The existing pattern at `CMakeLists.txt:2174` and `:2237` (the `_tests`
  target keeps ASan link flags separately) already demonstrates this scoping
  is the convention. Add a comment pinning the intent.

- **`-frandom-seed` regression by a future engineer (MED / LARGE).** A
  helpful PR could add `-frandom-seed=$RANDOM_HASH` thinking it strengthens
  reproducibility. It would actually cause `static`-local symbol collisions
  across TUs. Mitigation: an explicit CMake comment ("DO NOT ADD
  -frandom-seed; -ffile-prefix-map already canonicalizes; see
  sprints/sprint-42/designs/US-42.3.md").

- **`-Werror=date-time` vs story-stated `-Wno-date-time` (LOW / SMALL).**
  The story text suggests the weaker `-Wno-`. Shipping the stronger
  `-Werror=` is a defensible deviation because the codebase is already
  `-Werror` (`CMakeLists.txt:3581`) and AC-42.3.1 demands "fails the build
  immediately" — exactly what `-Werror=date-time` does. The weaker form
  would silently allow regressions. Mitigation: note divergence in CMake
  comment with AC-42.3.1 reference.

- **`ar -D` unsupported on darwin (MED / SMALL).** BSD `ar` on macOS does
  not accept `-D`. Mitigation: configure-time probe (`execute_process` with
  `RESULT_VARIABLE`) gates the assignment; darwin uses `libtool` which is
  deterministic by default. Both paths pinned in the configure log; the
  two-build diff is the empirical fallback.

- **`SOURCE_DATE_EPOCH` leak into test fixtures (LOW / SMALL).** If a test
  reads the env var it would see the frozen value. Mitigation: exported
  only inside `check-reproducible-build.sh`, not in `ci.yml` global env. No
  test today reads it (`grep -r SOURCE_DATE_EPOCH src/ tests/` is empty —
  verified during investigation).

- **CI flakiness from doubled build time (MED / MED).** The job builds the
  release target twice on each OS. Mitigation: target is `human` only
  (not `human_tests`), `--target human` is much faster than full build. No
  ccache between the two builds — that would defeat the test. Document
  this prohibition in the script header.

- **`-ffile-prefix-map` + DWARF source-stepping (LOW / SMALL).** Debug info
  paths in `human` are remapped, requiring `set substitute-path` in gdb.
  Mitigation: release builds ship without debug info anyway (`MinSizeRel`
  + `-fvisibility=hidden` already at `CMakeLists.txt:2259`); dev preset is
  not affected because the flags are gated behind the
  `Release/MinSizeRel` block. Note in the CMake comment.

- **readelf / otool absent from runner (LOW / SMALL).** macOS runners ship
  with `otool`; ubuntu runners ship with `readelf` via `binutils`.
  Mitigation: install-step in CI explicitly names them; script checks for
  presence and aborts with a clear message if missing.

- **Build-id-absent assertion false-positive (LOW / SMALL).**
  `-Wl,--build-id=none` removes the section entirely; assertion is "section
  absent", not "section empty". Mitigation: use `readelf -n` (notes-only)
  and check exit / output — readelf prints nothing if the section is
  absent.

## Test strategy

The two scripts ARE the regression tests for this story; they run in CI on
every PR and locally during development.

- **Fast gate positive control.** Header comment in
  `check-no-date-time-macros.sh` documents how to smoke-test: inject
  `__DATE__` into any TU, expect nonzero exit, revert. Don't commit the
  fixture.
- **Slow gate positive control.** Same idea for
  `check-reproducible-build.sh`: inject `__DATE__`, expect SHA mismatch,
  revert.
- **CI matrix is the integration test.** `reproducible-build` job MUST be
  green before merge. Required by branch protection.

No new C tests under `tests/`. The story's test seam is
`scripts/verify-reproducible-build.sh` (per AC text), which maps to our
two-script split (`check-no-date-time-macros.sh` +
`check-reproducible-build.sh`); naming chosen to make the CI step names
self-documenting.

## Acceptance criteria mapping

| AC | What it requires | How covered |
|----|------------------|-------------|
| **AC-42.3.1** | `SOURCE_DATE_EPOCH` plumbed; `-Werror=date-time` in compile flags so future `__DATE__`/`__TIME__` fails the build | Step 1 (CMake compile flags) + Step 4 (`check-no-date-time-macros.sh` redundant fast gate that gives a *better* error than `-Werror`) |
| **AC-42.3.2** | Linux `ar -D` produces all-zero timestamps in `libhuman_core.a` | Step 3 (configure-time `ar -D` probe → `CMAKE_C_ARCHIVE_*`); `check-reproducible-build.sh` does NOT exercise this directly (the binary is the artifact under test), but the static archive feeds the binary so AC-42.3.4 transitively catches it. Optional explicit assertion in the script: `ar tv build-release/libhuman_core.a` and grep for non-zero dates. |
| **AC-42.3.3** | Darwin probes for `ar -D` and falls back to `ZERO_AR_DATE` / `libtool` | Step 3 fallback branch + note that darwin `libtool` is deterministic by default. `ZERO_AR_DATE` env var is set by `xcrun ar` automatically when invoked under CMake on modern darwin — confirmed empirically by the two-build sha256 match on the macOS CI runner. |
| **AC-42.3.4** | Two builds under `SOURCE_DATE_EPOCH=1700000000` → identical sha256 | Step 5 (`check-reproducible-build.sh --two-build-diff`); CI job in Step 6 |
| **AC-42.3.5** | `-ffile-prefix-map=$(pwd)=.` rewrites source paths; `strings build/human \| grep "$(pwd)"` returns no matches | Step 1 (compile flag); `check-reproducible-build.sh` SHOULD also assert this — add `strings "$B1/human" | grep -F "$PWD"` returns empty as a final check before the sha256 step. |

## Out of scope

- Reproducible builds for ANY target other than `human` (tests, fuzzers,
  UI, apps explicitly excluded — they ship with debug info / UUIDs).
- Stripping debug info beyond what `MinSizeRel` already does.
- `SOURCE_DATE_EPOCH`-aware test fixtures.
- Reproducibility of the website/UI/native-app builds.
- Adding `-frandom-seed` (explicitly forbidden — see Risks).
- Cross-compile (`cross-arm64`) reproducibility — host-arch only in the
  matrix.
- SBOM generation (separate epic per story Out-of-scope).
- Python fine-tuning script reproducibility (per story Out-of-scope).
- Branch-protection update to make the new job required (operator step,
  not a code change).
