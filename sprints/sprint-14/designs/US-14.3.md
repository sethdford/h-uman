# Design for US-14.3: iOS TestFlight-buildable archive

## Approach

The story requires a reproducible Release-configuration archive of the `HumaniOS`
scheme that exports to a valid App Store-method `.ipa`, with bundle ID and version
verifiable via `plutil`. The cheapest design is a single CI step that runs the two
`xcodebuild` invocations against the existing `apps/ios` project (XcodeGen-generated)
plus an `ExportOptions.plist` that declares `method: app-store` and a placeholder
provisioning-profile mapping. Actual TestFlight upload is explicitly out of scope —
that is an operator step (`xcrun altool` / Transporter) which requires interactive
2FA and is not a CI concern for this story.

Provisioning is the highest-risk axis. We refuse to commit a real provisioning-profile
UUID into the repo; instead, `ExportOptions.plist` ships with a literal placeholder
token (e.g. `__HU_IOS_PROVISIONING_PROFILE_UUID__`) and the CI workflow performs a
`sed`-substitution at archive time using a `secrets.IOS_PROVISIONING_PROFILE_UUID`.
This keeps the repo free of identifiers tied to a specific Apple developer team while
still giving the archive a deterministic shape.

We follow the existing `apps/ios` xcodegen-based layout — no new build system, no new
scheme. `/aspect-panel` is mandatory for this story (per scrum spec), so the design
includes the panel checkpoint as a non-skippable gate.

## Implementation steps (for the implementer agent)

1. **Skeleton ExportOptions.plist** — write `apps/ios/ExportOptions.plist` containing
   `<key>method</key><string>app-store</string>`, `<key>teamID</key><string>__HU_IOS_TEAM_ID__</string>`,
   `<key>provisioningProfiles</key><dict><key>com.h-uman.HumaniOS</key><string>__HU_IOS_PROVISIONING_PROFILE_UUID__</string></dict>`,
   plus `signingStyle: manual`, `stripSwiftSymbols: true`, `uploadSymbols: false`.
   Verify with `plutil -lint apps/ios/ExportOptions.plist`.
2. **Wrapper script** — `scripts/ios-archive-export.sh`:
   - `set -euo pipefail`
   - `sed -i.bak "s/__HU_IOS_PROVISIONING_PROFILE_UUID__/${IOS_PROVISIONING_PROFILE_UUID:-PLACEHOLDER}/g; s/__HU_IOS_TEAM_ID__/${IOS_TEAM_ID:-PLACEHOLDER}/g" apps/ios/ExportOptions.plist`
   - `xcodebuild -scheme HumaniOS -configuration Release -destination 'generic/platform=iOS' -archivePath /tmp/HumaniOS.xcarchive archive`
   - `xcodebuild -exportArchive -archivePath /tmp/HumaniOS.xcarchive -exportOptionsPlist apps/ios/ExportOptions.plist -exportPath /tmp/export`
   - Assert `/tmp/export/HumaniOS.ipa` exists.
   - `plutil -p /tmp/HumaniOS.xcarchive/Info.plist | grep -q 'com.h-uman.HumaniOS'` (bundle ID assertion)
   - `plutil -p /tmp/HumaniOS.xcarchive/Info.plist | grep -E 'CFBundleShortVersionString|CFBundleVersion'` (version assertion)
   - On exit, restore ExportOptions.plist from `.bak` so the repo stays clean.
3. **CI wiring** — add a `ios-archive` job (or step within existing native-apps-fleet
   matrix) to `.github/workflows/native-apps-fleet.yml` that runs only on a `macos-14`
   runner, calls `scripts/ios-archive-export.sh`, and uploads `/tmp/export/HumaniOS.ipa`
   as an artifact. The job uses `if:` guards so it runs on apps-path changes, schedule,
   and manual dispatch — matching the existing fleet pattern.
4. **README** — document the local-developer workflow:
   `IOS_TEAM_ID=XXXX IOS_PROVISIONING_PROFILE_UUID=YYYY ./scripts/ios-archive-export.sh`,
   and the operator upload step:
   `xcrun altool --upload-app -f /tmp/export/HumaniOS.ipa -t ios -u APPLE_ID -p APP_SPECIFIC_PASSWORD`.
5. **Aspect panel** — fill in `/aspect-panel` deliverable at
   `sprints/sprint-14/aspect-panel/US-14.3.md` covering Identity, Risk, Reversibility,
   Verification, Cost.
6. **/verify** — verifier runs the script in CI dry-run mode (with placeholder secrets
   that cause export to FAIL with a known signing-error string) and confirms the
   archive step succeeds + the plutil assertions fire. We do NOT require a green
   end-to-end export in CI without real secrets, but the archive itself must succeed
   and the plutil assertions on the `.xcarchive/Info.plist` must pass.

## Risks

- **Backward compat (LOW / SMALL)**: New file + new script + new CI step. No existing
  iOS build path is removed. The XcodeGen-generated project is unchanged.
- **Secret leakage (MED / LARGE)**: Provisioning-profile UUID and team ID are not
  secrets per se, but tying them to a specific Apple developer team in the repo
  creates a footgun. **Mitigation:** placeholder-token + CI `sed` substitution, with
  `.bak` restore step so a contributor running the script locally never accidentally
  commits a real UUID. A pre-commit grep for `__HU_IOS_PROVISIONING_PROFILE_UUID__`
  presence (must be present) is a cheap belt-and-braces check.
- **CI cost (MED / SMALL)**: macOS runners are expensive (~10x Linux). **Mitigation:**
  archive job runs only on apps-path changes, schedule, and dispatch — same gating as
  the existing native-apps-fleet workflow. Not on every PR.
- **Signing failure in CI without real secrets (HIGH / SMALL)**: The `-exportArchive`
  step requires a real provisioning profile installed on the runner. **Mitigation:**
  split the CI step in two — `archive` always runs (no signing needed for archive
  step in Release? actually it does, see below) — and `export` runs only when
  `secrets.IOS_PROVISIONING_PROFILE_UUID` is non-empty. When the secret is absent,
  CI logs a skip reason and still uploads the `.xcarchive` artifact for inspection.
  Operators with the secret can manually re-run.
- **Archive itself requires code-signing identity (MED / MED)**: `xcodebuild archive`
  on Release will fail without a signing identity in the keychain. **Mitigation:** in
  CI, install the signing cert from `secrets.IOS_SIGNING_CERTIFICATE_P12` +
  `secrets.IOS_SIGNING_CERTIFICATE_PASSWORD` into a temporary keychain
  (`security create-keychain` + `security import`). Document this in README so a
  local developer with their own Apple Developer account can substitute their own
  cert. For the first PR landing US-14.3, the CI step can run with
  `CODE_SIGNING_ALLOWED=NO` against the archive step to validate the project compiles
  and links for `generic/platform=iOS`, deferring true signing to a follow-up once
  secrets are provisioned (track as `DEBT-ios-signing-secrets`).
- **Observability (LOW)**: Log the archive path, export path, IPA size, and the
  output of `plutil -p` against `Info.plist`. On failure, upload the
  `~/Library/Logs/DeveloperTools` directory as a CI artifact.

## Test strategy

- **Unit-level**: `plutil -lint apps/ios/ExportOptions.plist` — verifies syntactic
  validity of the plist. Cheap. Runs on every PR, even Linux ones, via `plistlib`
  in Python as a Linux-compatible fallback.
- **Integration (macOS CI only)**: `scripts/ios-archive-export.sh` end-to-end with
  test/placeholder secrets that exercise the archive path. Assertions:
  - `/tmp/HumaniOS.xcarchive` directory exists post-archive
  - `plutil -p /tmp/HumaniOS.xcarchive/Info.plist | grep -q 'com.h-uman.HumaniOS'`
  - `plutil -p /tmp/HumaniOS.xcarchive/Info.plist | grep -E 'CFBundleShortVersionString'`
  - When secrets are present: `/tmp/export/HumaniOS.ipa` exists and is non-zero size
- **No fake tests pinning bugs**: per `.claude/rules/tests-that-pin-bugs.md`, our
  plutil assertions must FAIL if the bundle ID drifts (so we deliberately test the
  negative path locally before landing — change bundle ID in a scratch branch,
  confirm the script exits non-zero).

## Acceptance criteria mapping

- **AC: ExportOptions.plist declares method: app-store + provisioningProfiles dict**
  → covered by `apps/ios/ExportOptions.plist` + `plutil -lint` check in CI.
- **AC: xcodebuild archive succeeds for HumaniOS scheme, Release, generic/iOS**
  → covered by step 1 of `scripts/ios-archive-export.sh` + CI artifact upload.
- **AC: xcodebuild -exportArchive produces HumaniOS.ipa**
  → covered by step 2 of the script + filesystem assertion.
- **AC: plutil -p confirms bundle ID and version match expected**
  → covered by the plutil grep assertions in the script.
- **AC: Provisioning UUID NOT committed to repo**
  → covered by placeholder token + CI sed substitution + `.bak` restore +
  pre-commit grep guard for the placeholder presence.
- **AC: /aspect-panel deliverable present**
  → covered by `sprints/sprint-14/aspect-panel/US-14.3.md`.
- **AC: Out-of-scope items documented**
  → README explicitly notes TestFlight upload (`xcrun altool` / Transporter) is
  operator-only, not CI.

## /aspect-panel (mandatory)

- **Identity**: Adds reproducible iOS archive + IPA export. Does NOT add upload.
- **Risk**: MED — touches signing surface; mitigated by placeholder tokens + secret
  gating.
- **Reversibility**: HIGH — pure additive (new files + new CI step). Revert = delete
  three files + one workflow stanza.
- **Verification**: CI archive job + plutil assertions + IPA artifact upload + local
  developer dry-run instructions in README.
- **Cost**: ~200 LOC + ~5 min CI macOS runtime per invocation (gated, not per-PR).

## Out of scope (do not implement in this story)

- TestFlight upload via `xcrun altool` or Transporter (operator step).
- App Store Connect API key management (separate story; needs secrets infra).
- Multi-environment ExportOptions variants (dev/staging/prod) — single app-store
  variant for this sprint.
- Automatic version bump (`agvtool`) — version comes from XcodeGen project.yml.
