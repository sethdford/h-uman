# Design for US-14.2: Notarized DMG via notarytool + stapler

**Sprint:** 14
**Priority:** P0
**Size:** M
**Risk:** HIGH (credential handling + Apple-side signing path)
**Depends on:** US-14.1 (archive landing the signed `.app`)

## Approach

The smallest design that satisfies the AC: a single bash script
(`scripts/notarize-mac.sh`) that takes a path to a signed `.app`,
packages it into a UDZO DMG with `hdiutil`, submits the DMG to Apple
via `xcrun notarytool submit --wait`, and on success staples the
notarization ticket onto the DMG with `xcrun stapler staple`. The
script is the single source of truth for the notarization recipe;
both local operators and CI invoke it the same way.

The choice between notarizing the `.app` directly versus notarizing
the DMG: we notarize the DMG because (a) it is the artifact we ship,
(b) `stapler` works on DMGs, and (c) it lets `spctl --assess` validate
the as-downloaded path on a fresh machine without internet. The
`.app` inside must already be signed with a Developer ID (US-14.1's
job); notarization is the second step that authenticates *us* to
Gatekeeper.

A `--dry-run` flag short-circuits the network submission and instead
prints the exact `notarytool` invocation that would have been issued,
including which keychain profile / credential source would be used.
This is the only test seam the audit harness needs:
`scripts/test-notarize-dryrun.sh` runs the dry-run path against a
fixture `.app` and asserts no `notarytool submit` line ever executed
(by stubbing `xcrun` on PATH to a recording shim that fails loud on
any submit/staple call).

For CI, we add one job to `.github/workflows/native-apps-fleet.yml`
gated on `github.event_name == 'release' && startsWith(github.ref, 'refs/tags/v')`.
The credential (`APP_STORE_CONNECT_API_KEY` + `_KEY_ID` + `_ISSUER_ID`)
comes from repo secrets and is written to a tmp file with `umask 077`
inside a trap that unlinks on EXIT. Never echoed; `set -x` is
explicitly off in the credential-handling block.

## Implementation steps (for the implementer agent)

1. Create fixture `.app` under `tests/fixtures/notarize/Human.app/`
   with a minimal `Info.plist` (CFBundleIdentifier=`com.human.test`,
   CFBundleExecutable=`Human`) and an empty `MacOS/Human` exec.
2. Write `scripts/notarize-mac.sh` skeleton with:
   - `set -euo pipefail`
   - Top-of-file `trap cleanup EXIT` that hdiutil-detaches any mounted
     volume and `rm -f` any tmp credential files (tracked in a
     `CLEANUP_PATHS` array).
   - `usage()` printing `--app PATH --version X --dry-run`.
   - Arg parsing.
3. Implement DMG creation block:
   ```
   hdiutil create -volname Human \
     -srcfolder "$APP" -ov -format UDZO \
     "Human-${VERSION}.dmg"
   ```
4. Implement credential-loading block (CI path only):
   - Read `APP_STORE_CONNECT_API_KEY` from env (base64 PEM).
   - Decode into `${TMPDIR:-/tmp}/asc_key_$$.p8` with `umask 077`.
   - Register path in `CLEANUP_PATHS`.
5. Implement submission block:
   - If `--dry-run`: echo `[DRY-RUN] xcrun notarytool submit ...`
     with redacted key path, exit 0.
   - Else: `xcrun notarytool submit "$DMG" --key "$KEY" --key-id "$KID" --issuer "$IID" --wait --output-format json`
   - Capture submission ID; on non-`Accepted` status, fetch log via
     `xcrun notarytool log <id> --key ... -` and print to stderr;
     exit 1.
6. Implement staple block:
   - `xcrun stapler staple "$DMG"`
   - `xcrun stapler validate "$DMG"` (sanity check).
7. Implement assess block (acceptance check):
   - Mount DMG read-only, run `spctl --assess --type execute --verbose <mounted>/Human.app`.
   - Detach. Exit 0 only if spctl exits 0.
8. Write `scripts/test-notarize-dryrun.sh`:
   - Create temp dir, put a stub `xcrun` on PATH that:
     - Allows `xcrun notarytool --version` (returns fake version).
     - LOUDLY fails (exit 99 + stderr message) on any `submit`,
       `staple`, or `log` subcommand.
     - Allows `hdiutil` operations (passes through to real binary).
   - Invoke `scripts/notarize-mac.sh --app tests/fixtures/notarize/Human.app --version 0.0.0-test --dry-run`.
   - Assert exit 0, no `submit/staple/log` was hit by stub.
9. Add `notarize-dmg` job to `native-apps-fleet.yml`:
   - `if: github.event_name == 'release' && startsWith(github.ref, 'refs/tags/v')`
   - `runs-on: macos-14`
   - Steps: checkout → download `.app` artifact from US-14.1 →
     `scripts/notarize-mac.sh --app ./Human.app --version ${{ github.ref_name }}`.
   - Secrets: `APP_STORE_CONNECT_API_KEY`, `APP_STORE_CONNECT_KEY_ID`,
     `APP_STORE_CONNECT_ISSUER_ID`. All via `env:`; never in `run:` strings.
10. Add a dry-run smoke job that runs `test-notarize-dryrun.sh` on
    every PR (no secrets needed). This is what guards regressions in
    the script itself.
11. Run `/verify` confirming both the dry-run test passes and the CI
    job is gated correctly (lint workflow YAML).

## Risks

- **Credential leak (HIGH probability, LARGE impact)**: any `echo`,
  `set -x`, or `cat` of the API key file leaks it to logs forever.
  Mitigation:
  (a) credential decode block runs with `set +x` explicitly bracketed;
  (b) decoded `.p8` lives in `umask 077` tmpfile, EXIT-trap unlinks;
  (c) we pass `--key <path>` to notarytool, never the key bytes
  inline;
  (d) `notarytool submit --output-format json` returns IDs only, not
  secrets — safe to print;
  (e) the dry-run path prints `[REDACTED]` instead of the key path
  to avoid accidental local exposure during demos.

- **Trap cleanup race (LOW probability, MEDIUM impact)**: hdiutil
  mount that survives the script (e.g., on SIGKILL) leaves stale
  `/Volumes/Human` entries. Mitigation: `trap cleanup EXIT INT TERM`
  + a pre-flight `hdiutil detach /Volumes/Human || true` at start.

- **CI gating misfire (MEDIUM probability, LARGE impact)**: running
  notarization on every PR exhausts notarytool quota and exposes
  secrets to fork PRs. Mitigation: hard gate on
  `event_name == 'release' && refs/tags/v*`. Verify by lint:
  `actionlint .github/workflows/native-apps-fleet.yml` and
  `gh workflow view` after merge. Add a comment in the workflow
  pointing at this risk so future edits don't relax the gate.

- **Apple-side flakiness (MEDIUM probability, MEDIUM impact)**:
  notarytool can take 1–30 min, occasionally hangs. Mitigation:
  `--wait` blocks but we set a job-level `timeout-minutes: 45`. On
  timeout, log fetch is attempted in an `if: failure()` step.

- **Stapler offline failure (LOW probability, SMALL impact)**:
  `stapler staple` needs Apple servers; the staple is offline-
  verifiable thereafter. If staple fails post-success, retry once
  before erroring (notarytool says accepted but CDN propagation
  lags).

- **Backward compat (LOW)**: new script + new CI job; no callers
  exist. No migration risk.

- **Test-pins-bug risk (LOW)**: `test-notarize-dryrun.sh` asserts
  the dry-run path takes NO network. The assertion must be phrased
  as "stub `xcrun submit` was NOT invoked" (negative), not "submit
  was invoked with X args" (positive). See
  `.claude/rules/tests-that-pin-bugs.md`.

- **Observability (MEDIUM)**: failure mode is opaque without the
  notarytool log. Mitigation: on non-Accepted status, automatically
  invoke `xcrun notarytool log <id>` and print full JSON to stderr.
  Exit code distinguishes "submission failed" (2) from "staple
  failed" (3) from "spctl assess failed" (4).

## Test strategy

- **Unit / dry-run**: `scripts/test-notarize-dryrun.sh` exercises
  the full arg-parse + DMG-build + dry-run-submit path with a
  fixture `.app`. Stub `xcrun` rejects any submit/staple/log.
  Asserted: exit 0, no real network call, `Human-0.0.0-test.dmg`
  was created and is a valid UDZO DMG (`hdiutil imageinfo` on it
  exits 0).
- **CI integration**: the dry-run smoke job runs on every PR. The
  real notarization job runs only on `refs/tags/v*` and is
  observable via the release workflow run.
- **Manual operator test (out of band)**: on first real tag, run
  `spctl --assess --type execute --verbose Human.app` on a fresh
  macOS VM with the DMG downloaded via Safari. Must exit 0 and
  print `source=Notarized Developer ID`.

## Acceptance criteria mapping

- **AC: `notarize-mac.sh` accepts `.app`, builds DMG, submits via notarytool, staples on success** → `scripts/notarize-mac.sh` implements DMG → submit → staple sequence; verified by code review + dry-run test confirming arg flow.
- **AC: `--dry-run` skips submission, prints intended action** → dry-run branch in script; verified by `test-notarize-dryrun.sh`.
- **AC: `spctl --assess --type execute --verbose Human.app` exits 0** → Step 7 in implementation; gated as final check in `notarize-mac.sh` (real-mode) before exit 0.
- **AC: credentials from CI secret, never echoed** → `set +x` bracketed credential block + `umask 077` tmp key + EXIT trap unlink; reviewed by `/aspect-panel`.
- **AC: workflow only runs on release tag, not PRs** → `if: github.event_name == 'release' && startsWith(github.ref, 'refs/tags/v')` on the `notarize-dmg` job.
- **AC: failure prints notarytool log** → on non-Accepted, script calls `xcrun notarytool log <id>` to stderr and exits non-zero with distinct code (2).
- **AC: dry-run test asserts no network** → stub `xcrun` fails on submit/staple/log; positive assertion is "stub was never tripped".

## /aspect-panel checklist (MANDATORY — HIGH risk story)

Before implementation merges:
- [ ] Security reviewer confirms credential file lifecycle (umask, trap, no echo).
- [ ] CI reviewer confirms tag gate cannot be triggered from fork PRs.
- [ ] Operator-handoff reviewer confirms script exit codes are documented and runbook-linked.
- [ ] Test reviewer confirms dry-run test asserts the NEGATIVE (no network), per `tests-that-pin-bugs.md`.

## Out of scope

- Provisioning the Developer ID signing identity itself (operator
  action, predates this story).
- Stapling the `.app` (we ship the DMG; the inner `.app` carries
  the embedded notarization once Apple records the hash, no
  separate staple needed).
- Sparkle/auto-update integration (separate story).
- Universal binary handling (US-14.1's concern; we accept whatever
  `.app` we're handed).
