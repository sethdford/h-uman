# Design for US-14.5: macOS first-run OnboardingSheet

**Sprint**: 14 | **Priority**: P2 | **Size**: M | **Risk**: MEDIUM
**Story**: macOS native app shows an OnboardingSheet on first launch when the
`human` daemon binary is not on `PATH`, guiding the user to install it via
Homebrew or a documented installer URL.

## Approach

The macOS app already has a `ProcessManager` helper that resolves the `human`
daemon binary by probing `which human` / common install paths. On cold launch
the app checks `ProcessManager.humanPath()`; if it returns `nil` AND
`UserDefaults.standard.bool(forKey: "humanInstallationCompleted")` is `false`,
the root `ContentView` presents a SwiftUI `.sheet(...)` bound to a
`@State private var showOnboarding: Bool` value. The sheet itself is a small
`OnboardingSheet: View` struct in `apps/macos/Human/Onboarding/OnboardingSheet.swift`
with two primary CTAs and a "Skip for now" affordance.

We pick a SwiftUI sheet (not a separate `Window` or modal `NSAlert`) for three
reasons: (1) state binding is trivial — the sheet is dismissed by flipping a
`@State` Bool; (2) it composes with the existing `WindowGroup` and inherits
the app's design tokens; (3) UI test affordance is consistent with the
`-uitestSkipOnboarding` precedent already documented in
`apps/ios/CLAUDE.md` — XCUITest can launch with that flag and skip the sheet.

External URL handling is the only non-trivial risk surface. We use
`NSWorkspace.shared.open(URL)` with **hard-coded URL constants** declared in
the same file (`OnboardingURLs.install = URL(string: "https://gettheconsultant.com/install")!`).
No URL components come from user input, environment, or runtime config.
Operator preference between "open install page" vs "open Terminal with brew
command" is a build-time choice that defaults to **install page** (safer; no
process spawning from a freshly-launched app); the Terminal path is gated
behind a feature flag `OnboardingFeature.openTerminalCTA` (compile-time
constant `false` in this story; switching it to `true` is out of scope).

The `humanInstallationCompleted` flag is set to `true` when either CTA is
tapped AND on every subsequent launch where `ProcessManager.humanPath()`
returns non-nil (self-healing — the sheet stops appearing once the binary
is detected, even if the user installed it manually).

## Implementation steps (for the implementer agent)

1. **Add launch-argument constant.** Mirror the iOS pattern from
   `apps/ios/CLAUDE.md`: add `"-uitestSkipOnboarding"` to a shared
   `LaunchArguments` enum/struct in `HumanUITests/Helpers/`.
2. **Create `OnboardingURLs.swift`** with two `static let` URL constants
   built from string literals. Force-unwrap is acceptable here because the
   strings are compile-time constants under test; add a unit-test-style
   `#if DEBUG` assertion at file scope or rely on the XCUITest to catch a
   crash on launch.
3. **Create `OnboardingState.swift`.** Public surface:
   - `var shouldShow: Bool` — computed from `ProcessManager.humanPath() == nil`
     AND `!completed` AND launch arg `-uitestSkipOnboarding` absent.
   - `func markCompleted()` — sets UserDefaults key `humanInstallationCompleted = true`.
   - `func openInstallPage()` — `NSWorkspace.shared.open(OnboardingURLs.install)`
     then `markCompleted()`.
   - `func openTerminalWithBrewCommand()` — gated behind compile-time
     `OnboardingFeature.openTerminalCTA`; in this story this method exists
     but the CTA button is not rendered. (Keeps US-14.5 scope tight while
     leaving a documented seam for a follow-up story.)
4. **Create `OnboardingSheet.swift`** — a `View` with:
   - Headline ("Install the human daemon to continue")
   - Body copy explaining the one-line brew command, rendered in a
     selectable, copyable `Text` so users can paste it into their own
     Terminal.
   - Primary CTA: "Open install page" → `state.openInstallPage()` + dismiss.
   - Secondary CTA: "Skip for now" → `state.markCompleted()` + dismiss.
   - Accessibility identifiers on every interactive element
     (`onboarding.cta.install`, `onboarding.cta.skip`, `onboarding.sheet.root`).
5. **Wire into `ContentView`/`HumanApp`.** On `.onAppear`, read
   `state.shouldShow` and bind to `@State var showOnboarding`. Use
   `.sheet(isPresented: $showOnboarding) { OnboardingSheet(...) }`. Re-check
   `shouldShow` on `Scene.phase == .active` so the sheet self-heals after a
   manual install.
6. **Write `HumanUITests/OnboardingTests.swift`** with these cases:
   - `testOnboardingSheetAppearsOnColdLaunchWhenDaemonMissing` — launch with
     a temp `$PATH` that excludes `human`; assert
     `app.otherElements["onboarding.sheet.root"].waitForExistence(timeout: 3)`.
   - `testSkipButtonDismissesAndPersistsFlag` — tap skip, relaunch app,
     assert sheet does NOT appear.
   - `testLaunchArgSkipsOnboardingForUITests` — launch with
     `-uitestSkipOnboarding`; assert sheet absent within 1s.
7. Run `xcodebuild test -scheme Human -destination 'platform=macOS'`.
   Run the full C test suite (`./build/human_tests`) to confirm no
   regression in any shared library.

## Risks

- **External URL opening (MEDIUM probability / MEDIUM impact)**: opening an
  attacker-controlled URL could lead to phishing or scheme-handler abuse
  (e.g. `x-apple-helpd://`). **Mitigation**: URLs are hard-coded
  `static let` constants in `OnboardingURLs.swift`, never sourced from
  config, environment, defaults, or runtime input. The XCUITest asserts
  the literal URL string is `https://gettheconsultant.com/install`.
  `NSWorkspace.shared.open(_:)` (not `open(_:configuration:completionHandler:)`)
  is used so we get the OS's default-browser handoff with no custom scheme
  bypass.
- **UserDefaults race on first launch (LOW / SMALL)**: if the user
  double-clicks the app icon, two scenes could each evaluate `shouldShow`
  simultaneously. Both reads return the same value and the only write
  (`markCompleted`) is idempotent. **Mitigation**: no lock needed; document
  in the file header that `markCompleted()` is idempotent.
- **`ProcessManager.humanPath()` false-negative (LOW / MEDIUM)**: if the
  user installs via a non-PATH location (e.g. `~/.local/bin` not on
  `launchctl`'s PATH), the sheet keeps reappearing. **Mitigation**:
  documented in CTA copy — "If you've already installed it, click Skip."
  Skip persists the flag and stops the loop. Long-term fix is out of scope
  for US-14.5 (would belong in a follow-up "ProcessManager path discovery"
  story).
- **Test seam drift from iOS (LOW / SMALL)**: iOS uses
  `-uitestSkipOnboarding`; macOS must use the same literal string for
  consistency. **Mitigation**: shared `LaunchArguments` struct + an
  XCUITest that asserts the constant matches the literal.
- **Sheet shown on every launch in dev when daemon path differs (LOW / SMALL)**:
  developer machines may launch the app from Xcode with a sanitized PATH.
  **Mitigation**: dev workflow uses `-uitestSkipOnboarding` (also documented
  for non-test Xcode launches) OR sets `humanInstallationCompleted = true`
  in defaults. Documented in `apps/macos/CLAUDE.md` (out of scope for the
  story itself).
- **Backward compat with existing macOS app users (LOW / SMALL)**:
  existing installs do not have the UserDefaults key set; on first launch
  after upgrade they will see the sheet IF `human` is not detected. That's
  the desired behavior — anyone whose daemon binary is gone needs the
  guidance. No migration needed.

## Test strategy

- **XCUITest (primary)**: `OnboardingTests.swift` covers the three
  observable behaviors (presents, persists, skips). XCUITest is the
  correct level — `NSWorkspace.open` is hard to unit-test, but the user-
  visible "sheet appears / doesn't appear" outcome is straightforward to
  assert.
- **Unit test (secondary)**: a single SwiftPM test on
  `OnboardingState.shouldShow` logic with injected
  `ProcessManager` stub + injected UserDefaults suite — covers the truth
  table (path-nil × flag-true × launch-arg-present, 2^3 = 8 cases).
- **No integration test for `NSWorkspace.open`** — the OS contract is
  trusted. Asserting the literal URL string in the XCUITest is sufficient.
- **Run `./build/human_tests`** to confirm no regression in shared C code
  (this story touches no C, but per project rules the full suite must pass
  before commit).

## Dependencies

- **Sprint-9 Homebrew tap**: `gettheconsultant.com/install` must serve the
  documented `brew install humanlabs/human/human` command. This is a
  marketing-site / DNS dependency, not a code dependency in this worktree.
  If the URL 404s at story-completion time, the CTA still works (opens
  browser); the failure is visible to the user, not silent. **Pre-flight
  check for the implementer**: `curl -sI https://gettheconsultant.com/install`
  before writing the XCUITest assertion that hits the live page (the test
  itself should NOT hit the live page — it asserts the URL string only).

## Out of scope (deferred to follow-up stories)

- Auto-spawning Terminal with the brew command (compile-time flag stays off)
- Detecting partial installs (binary present but daemon not registered)
- "Re-run onboarding" menu item for users who skipped prematurely
- Localizing CTA copy (string keys exist; translation is a separate sprint)
