# Design for US-14.6: Entitlements + Fastfile lanes

**Story:** US-14.6 (P2, S, MEDIUM) — Sprint 14
**Status:** v1 (skeleton)

## Approach

Two small artifacts, no behavior changes to existing code:

1. **`apps/macos/Human.entitlements`** — a hardened-runtime / App Sandbox
   plist that grants the minimum entitlements the macOS app needs to
   talk to a locally-paired daemon and to outbound provider HTTP
   endpoints. Network server is explicitly **NO**. No sandbox-escape
   entitlements (no `disable-library-validation`,
   no `allow-unsigned-executable-memory`, no `cs.allow-jit` unless
   later proven necessary by a runtime crash on a real device).

2. **`apps/Fastfile`** — a fastlane configuration file with two lanes,
   `mac_archive` and `ios_archive`. Each lane is a thin wrapper that
   delegates to the per-platform archive logic landing in US-14.1
   (mac) and US-14.3 (ios). Because those stories are siblings in the
   same sprint and may not have landed yet, the lanes are written
   defensively: if the per-platform helper script is absent, the lane
   fails fast with a clear `UI.user_error!` rather than producing a
   bogus archive.

Why this and not alternatives:
- **Why not inline the archive logic in the Fastfile?** US-14.1/3 own
  the archive contract (signing identity, output path, dSYM upload).
  Duplicating it here creates two sources of truth for the build.
- **Why not split into two Fastfiles (one per platform)?** Fastlane
  natively supports multi-platform `platform :mac do … end` blocks;
  one file keeps the lane discovery trivial (`fastlane lanes` finds
  both) and matches fastlane idioms.
- **Why entitlements as plist, not generated at build time?** Xcode
  resolves the entitlements file at build time from a path in the
  project; a committed plist is auditable in `git diff` and reviewed
  the same way as code. Generating it would hide security-relevant
  changes from PR review.

## Entitlements contract

`apps/macos/Human.entitlements` (committed v1):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.app-sandbox</key>
    <true/>
    <key>com.apple.security.network.client</key>
    <true/>
    <key>com.apple.security.network.server</key>
    <false/>
</dict>
</plist>
```

Explicit non-entitlements (must NOT appear in the file):

| Key | Why excluded |
|---|---|
| `com.apple.security.cs.disable-library-validation` | sandbox escape; allows loading unsigned dylibs |
| `com.apple.security.cs.allow-unsigned-executable-memory` | sandbox escape; allows JIT into unsigned pages |
| `com.apple.security.cs.disable-executable-page-protection` | sandbox escape |
| `com.apple.security.cs.allow-dyld-environment-variables` | bypass DYLD hardening |
| `com.apple.security.network.server` | no inbound; daemon is local IPC, not network |
| `com.apple.security.files.user-selected.read-write` | not needed for v1; add via separate story if a file picker lands |
| `com.apple.security.device.audio-input` | not in v1 product scope |
| `com.apple.security.device.camera` | not in v1 product scope |
| `com.apple.security.personal-information.*` | not in v1 product scope |

Daemon pairing: the macOS app talks to the local daemon over a Unix
domain socket or local TCP loopback on a paired port. UDS does not
require any network entitlement; local TCP loopback to a listening
peer (the daemon) is permitted by `network.client` (the daemon, not
this app, holds the listening socket — so this app does not need
`network.server`). This is the wiring assumed by Sprint 14;
US-14.1/2 will pin the actual transport.

## Fastfile contract

`apps/Fastfile` (committed v1):

```ruby
# fastlane Fastfile for h-uman native apps.
# Two lanes: mac_archive, ios_archive.
# Each delegates to the per-platform archive logic owned by
# US-14.1 (mac) and US-14.3 (ios). This file MUST NOT contain
# signing identity or provisioning profile logic — that lives
# in the per-platform helpers so it can be tested in isolation.

default_platform(:mac)

MAC_BUNDLE_ID = "ai.humanlabs.HumanMac"
IOS_BUNDLE_ID = "ai.humanlabs.HumaniOS"

platform :mac do
  desc "Archive HumanMac.app (delegates to US-14.1 archive script)"
  lane :mac_archive do
    script = File.expand_path("../macos/scripts/archive.sh", __dir__)
    unless File.executable?(script)
      UI.user_error!("mac archive script missing: #{script} " \
                     "(owned by US-14.1; lane stub until that lands)")
    end
    sh(script)
  end
end

platform :ios do
  desc "Archive HumaniOS.app (delegates to US-14.3 archive script)"
  lane :ios_archive do
    script = File.expand_path("../ios/scripts/archive.sh", __dir__)
    unless File.executable?(script)
      UI.user_error!("ios archive script missing: #{script} " \
                     "(owned by US-14.3; lane stub until that lands)")
    end
    sh(script)
  end
end
```

`apps/fastlane/Appfile` (bundle id + team id constants, committed v1):

```ruby
for_platform :mac do
  app_identifier "ai.humanlabs.HumanMac"
end
for_platform :ios do
  app_identifier "ai.humanlabs.HumaniOS"
end
# team_id intentionally NOT pinned here; set via APPLE_TEAM_ID env
# (US-14.1/2 own signing identity).
```

Bundle ID convention: `ai.humanlabs.HumanMac` and
`ai.humanlabs.HumaniOS`. The stories.md open question on this is
resolved here in favor of `ai.humanlabs.*` because:
- Matches the reverse-DNS of the marketing domain (`humanlabs.ai`).
- Distinct per-platform bundle id avoids the "two products, one ID"
  ambiguity that breaks TestFlight crash grouping.
- Capitalized product suffix is the Apple convention for app names
  embedded in bundle IDs.

If the canonical resolution lands elsewhere (e.g. `ai.h-uman.*`),
flip the constants in `Appfile` and the two `*_BUNDLE_ID`
constants in `Fastfile`. Both are single-string edits.

## Implementation steps (for the implementer agent)

1. Create `apps/macos/Human.entitlements` with the exact plist above.
   `plutil -lint apps/macos/Human.entitlements` must exit 0.
2. Create `apps/fastlane/Appfile` with the bundle-id constants.
3. Create `apps/Fastfile` with the two lanes above.
4. From `apps/`, run `bundle exec fastlane lanes` and confirm both
   `mac mac_archive` and `ios ios_archive` are listed. (If
   `bundle`/`fastlane` is not installed locally, skip and let CI
   prove it.)
5. Add a CI step to `.github/workflows/native-apps-fleet.yml` (mac
   job) that runs `plutil -lint apps/macos/Human.entitlements`
   before any archive step. Step must be a hard fail (no
   `continue-on-error`).
6. Grep the repo for any other `*.entitlements` file. If one exists,
   diff against the new one and document the divergence in the PR
   description. (Two entitlements files in one app = sandbox bypass
   risk via the wrong one being selected.)
7. Run `/verify` with the verifier contract below.

## Verifier contract

Pin these as the executable acceptance:

- `plutil -lint apps/macos/Human.entitlements` exit 0.
- `grep -E 'disable-library-validation|allow-unsigned-executable-memory|disable-executable-page-protection|allow-dyld-environment-variables' apps/macos/Human.entitlements` returns no matches (exit 1).
- `grep -F 'com.apple.security.app-sandbox' apps/macos/Human.entitlements` returns a match AND the next non-whitespace line is `<true/>`.
- `grep -F 'com.apple.security.network.server' apps/macos/Human.entitlements` returns a match AND the next non-whitespace line is `<false/>`.
- `bundle exec fastlane lanes 2>&1 | grep -F 'mac_archive'` returns a match.
- `bundle exec fastlane lanes 2>&1 | grep -F 'ios_archive'` returns a match.
- `grep -F 'ai.humanlabs.HumanMac' apps/fastlane/Appfile` returns a match.
- `grep -F 'ai.humanlabs.HumaniOS' apps/fastlane/Appfile` returns a match.

## Risks

- **Sandbox escape via misconfiguration (MED probability, LARGE impact).**
  Any of the four blacklisted entitlements silently widens the sandbox
  and defeats the value of `app-sandbox = YES`. Mitigation: grep-based
  check in the verifier contract above; CI step runs on every PR; rule
  documented in the entitlements section of this design with the
  exhaustive blacklist. Reviewer must diff this file against any
  proposed change.

- **Duplicate entitlements file (LOW probability, LARGE impact).**
  If Xcode's project file references a different `*.entitlements` than
  the one in `apps/macos/`, the committed one is decoration. Mitigation:
  implementation step 6 greps for siblings; if found, the PR must
  reconcile to a single file or document why two exist.

- **Bundle ID drift (LOW probability, MEDIUM impact).**
  Bundle ID encoded in three places (Fastfile constants, Appfile,
  Xcode project). Mitigation: Fastfile imports the constants from a
  single location (the `*_BUNDLE_ID` constants at the top); Xcode
  project will be wired up by US-14.1/3 to read from the same source
  of truth (likely a `.xcconfig`). For v1 (this story), enforcement is
  visual review.

- **Lane stub masking missing dependency (LOW probability, SMALL impact).**
  `mac_archive` calls a script that may not exist yet (US-14.1). The
  `UI.user_error!` guard ensures `bundle exec fastlane lanes` listing
  works (discovery only) while executing the lane fails loudly with a
  pointer at the owning story. Acceptable transitional state.

- **Network entitlement drift (LOW probability, MEDIUM impact).**
  If a future story enables `network.server` without realizing the
  daemon (not the app) is the listener, the app surface widens.
  Mitigation: blacklist note in the entitlements section + grep in
  verifier contract.

- **Backward compat (LOW probability, SMALL impact).** No existing
  callers of these files; both are new artifacts.

- **Concurrency (N/A).** Static config files; no runtime state.

- **Migration (N/A).** New files only.

- **Observability (SMALL).** Sandbox violations show up in `Console.app`
  with subsystem `com.apple.sandbox`. Not added to product telemetry;
  out of scope.

## Test strategy

- **CI lint** (mandatory): `plutil -lint apps/macos/Human.entitlements`
  in the native-apps-fleet workflow on macOS runners.
- **CI grep guard** (mandatory): a one-line shell step that fails if
  any blacklisted entitlement key appears. Pin as a separate CI step
  so the failure message names the offending key.
- **Local smoke** (informational): `bundle exec fastlane lanes`
  enumerates both lanes. Not in CI for v1 because fastlane install in
  CI is a US-14.1/3 concern; revisit when those land.
- **No unit tests in `tests/`.** This story has no C surface.

## Acceptance criteria mapping

| AC | Verification |
|---|---|
| AC-1: entitlements file exists with `app-sandbox = YES`, `network.client = YES`, `network.server = NO` | verifier contract greps 1–4 |
| AC-2: `apps/Fastfile` has `mac_archive` lane | `fastlane lanes` lists it; grep 5 |
| AC-3: `apps/Fastfile` has `ios_archive` lane | `fastlane lanes` lists it; grep 6 |
| AC-4: bundle IDs `ai.humanlabs.HumanMac` / `HumaniOS` | grep 7–8 on Appfile |
| AC-5: `plutil -lint` exits 0 | verifier 1 + CI step |
| AC-6: no sandbox-escape entitlements | verifier 2 (negative grep) |
| AC-7: lanes delegate to US-14.1/3 (do not duplicate signing logic) | code review of Fastfile body — no `gym`/`match`/cert refs in this file |

## Out of scope (per story brief)

- Signing certificate handling (US-14.1/2 own this).
- App Store metadata beyond bundle ID + version (US-14.7+ if any).
- iOS entitlements file (US-14.3 owns its own entitlements; not
  shared with mac).
- Provisioning profile management (`match` setup) — US-14.1/2.
- Notarization (US-14.1).

## Open questions resolved by this design

1. **Bundle ID convention.** Resolved: `ai.humanlabs.HumanMac` /
   `ai.humanlabs.HumaniOS`. If a different convention is preferred,
   the change is two string edits.
2. **Single Fastfile vs split.** Resolved: single file, multi-platform
   blocks.
3. **Entitlements file location.** Resolved: `apps/macos/`. iOS gets
   its own under `apps/ios/` (US-14.3).
