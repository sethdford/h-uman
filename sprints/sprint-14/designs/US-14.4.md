# Design for US-14.4: HumanKit — public API stabilization with availability annotations

**Status:** v2 (audit complete)
**Priority/Size/Risk:** P1 / S / LOW
**Sprint:** 14, Wave 1 (parallel with US-14.1, no deps)

## Approach

HumanKit is the Swift Package at `apps/shared/HumanKit/`. `Package.swift` declares the platform floor as `.macOS(.v14), .iOS(.v17)`. Today the package ships three in-scope public targets — `HumanProtocol`, `HumanClient`, `HumanChatUI` — with **0 `@available` annotations** across **371 public declarations**, and ad-hoc `///` doc comments on only ~41 lines (mostly in `Methods.swift` and a header here or there). The two `HumanOnDevice*` targets are explicitly out of scope per the story (they belong to the M3 lane).

The cheapest design is mechanical and additive:

1. **Pin the package-level concurrency flag in `Package.swift`** (AC-14.4.1 explicitly requires adding `-strict-concurrency=complete` to `swiftSettings`). This makes the regression-pin part of the source of truth, not a one-shot CLI flag the implementer happens to type.
2. **One `@available(macOS 14, iOS 17, *)` per public top-level type, extension, or free declaration.** Nested public members inside an annotated type inherit availability and do NOT need their own attribute — this matters because `DesignTokens.swift` and `Methods.swift` together account for ~290 of the 371 public lines, and annotating each one would be churn for no compiler benefit.
3. **One `///` summary per public declaration** (top-level AND nested). Minimum: one sentence. `func` with parameters / non-Void return adds `- Parameter foo:` and `- Returns:`. Match Swift API Design Guidelines voice.

Alternatives considered and rejected:

- **Annotate every nested member with `@available`:** unnecessary noise; nested members inherit. Story does not require it; AC-14.4.2 (doc comments) is satisfied without it.
- **DocC catalog (`.docc`):** out of scope. Story specifies `///` comments and `swift package generate-documentation` running clean — DocC compiler reads `///` directly; no catalog needed.
- **Introduce `@_spi` boundaries for "internal-public" symbols:** scope creep. Story explicitly says "no new public API surface."
- **Move `Methods` enum to `internal`:** would satisfy AC-14.4.3 trivially but breaks the documented intent ("Swift developer embedding HumanKit"). Keep public; add `@available`.

## Implementation steps (for the implementer agent)

1. **Land `Package.swift` change first** (smallest, reversible). Add per-target `swiftSettings`:
   ```swift
   .target(
       name: "HumanProtocol",
       path: "Sources/HumanProtocol",
       swiftSettings: [.unsafeFlags(["-strict-concurrency=complete"])]
   ),
   ```
   Repeat for `HumanClient` and `HumanChatUI` only. Do NOT touch `HumanOnDevice*` targets (out of scope, owns M3 lane).

   Verify: `cd apps/shared/HumanKit && swift build` — observe whatever warnings strict-concurrency surfaces NOW (baseline). Capture this list; the goal in step 7 is "zero new warnings about missing availability or concurrency annotations on public symbols" (AC-14.4.1 verbatim). Pre-existing non-public concurrency warnings, if any, are not blockers — surface them as a separate finding.

2. **Annotate `HumanProtocol/ControlFrame.swift`** — 7 top-level structs. For each: prepend `@available(macOS 14.0, iOS 17.0, *)`. Add `///` summary on each struct and on each `public let` property. Build after this file.

3. **Annotate `HumanProtocol/Methods.swift`** — `@available` on the enum. Add `///` summary on the enum itself ("RPC method name constants for the Human gateway control protocol." — already there, keep). Add a one-line `///` on each `public static let` constant. Match the existing doc style. Build.

4. **Annotate `HumanClient/HumanConnection.swift`** — `@available` on `HumanConnection` and `HumanConnectionError`. `///` on the class, on each public method (with `- Parameter` and `- Returns:` where applicable), and on each error case. Build.

5. **Annotate `HumanClient/IntentHandler.swift`** — `@available` on `HumanGatewayClient`, `HumanGatewayClientError`, AND on the `public extension HumanGatewayClient` block at line 68. `///` on each public member. Build.

6. **Annotate all 6 `HumanChatUI` files** — one type per file (plus `SCGlassModifier`'s `public extension View`). `DesignTokens.swift` is the bulk: `@available` on `HUTokens` itself; `///` summary on each of ~220 nested constants. A scripted template like `/// <SemanticName> color (dark mode).` is acceptable when names are self-descriptive (e.g. `accentSecondaryHover`).

7. **Verify clean strict-concurrency build:**
   ```
   cd apps/shared/HumanKit && swift build
   ```
   (Flag is now baked into `Package.swift` per step 1, so a bare `swift build` exercises it.) Expect 0 errors and 0 new warnings about missing availability or concurrency annotations on public symbols.

8. **Run existing tests:**
   ```
   cd apps/shared/HumanKit && swift test
   ```
   All three in-scope test targets (`HumanProtocolTests`, `HumanClientTests`, `HumanChatUITests`) must pass. Also `HumanOnDevice*Tests` if they incidentally depend on the affected sources (they shouldn't — separate targets).

9. **Verify doc-comment coverage:**
   ```
   cd apps/shared/HumanKit && swift package generate-documentation \
     --target HumanProtocol --target HumanClient --target HumanChatUI 2>&1 \
     | grep -i "undocumented"
   ```
   Must return zero lines. If `swift-docc-plugin` is not yet added, add it to `Package.swift` as a `dependencies` entry — that's a one-line addition and satisfies AC-14.4.2's `swift package generate-documentation` clause. Confirm the docc plugin add is acceptable with the implementer before landing; otherwise rely on `swift-doc` CLI as the AC's alternative.

10. **Manual QuickHelp check** (one-time): open `Package.swift` in Xcode, Option-click `HumanGatewayClient`, `ChatBubble`, `Methods.connect`. Confirm QuickHelp shows the new `///` summary and the "Availability: macOS 14.0+, iOS 17.0+" row.

11. **CI green:** push; confirm `human-kit-swift` job in `.github/workflows/native-apps-fleet.yml` (line 34) and the duplicate `swift test` step in `ci.yml` (line 207) both pass.

## Risks

- **Backward compat (LOW / SMALL):** `Package.swift` already declares `.macOS(.v14), .iOS(.v17)` — `@available(macOS 14, iOS 17, *)` cannot reject any caller that previously compiled. The annotation is documentation, not a new constraint. Mitigation: pull versions from `Package.swift` exactly; do not invent (e.g. don't write `macOS 14.1`).

- **Strict-concurrency cascade (MEDIUM / MEDIUM):** Turning on `-strict-concurrency=complete` on three targets that currently have `@unchecked Sendable` on `HumanGatewayClient` and `HumanConnection` may surface real isolation gaps the codebase has been ignoring. AC-14.4.1 says "zero new warnings about missing availability or concurrency annotations on public symbols" — narrow scope. **Mitigation:** in step 1, capture baseline warnings BEFORE annotating anything. If strict-concurrency surfaces non-availability warnings, classify them: availability-related → fix in this story; genuine concurrency issues on already-`@unchecked Sendable` types → surface as a separate finding for product-owner to triage (do not silently `@unchecked` everything to make the build green — that's exactly the bug the `tests-that-pin-bugs.md` rule warns about, in a different form).

- **DesignTokens.swift doc-comment fatigue (LOW / SMALL):** ~220 nearly-identical doc strings. Risk: implementer writes useless `/// accent` for `public static let accent`. **Mitigation:** insist on the semantic pattern `/// <Role> color (<mode>).` — e.g. `/// Primary brand accent color (dark mode).` Encode this in the implementer's task instructions.

- **DocC plugin dependency creep (LOW / SMALL):** AC-14.4.2 says `swift package generate-documentation` must run clean, which requires `swift-docc-plugin`. Adding it is a one-line dependency, but it's a new external dep. **Mitigation:** confirm with product-owner before adding. Acceptable fallback: use the `swift-doc` binary if already on CI, or run `xcrun docc` against the targets. If neither is acceptable, escalate.

- **`@unchecked Sendable` interaction with `@available` (LOW / SMALL):** annotating `HumanGatewayClient` or `HumanConnection` with `@available` does not change `Sendable` synthesis (the class is `@unchecked` so synthesis is bypassed). No risk of accidental conformance flip.

- **Observability (N/A):** annotations are compile-time only. No runtime behavior change, nothing to log.

- **Cross-story conflict (LOW / SMALL):** US-14.4 is in Wave 1 alongside US-14.1; per the story spec they are independent. Sanity check: US-14.1 is the iOS XCUITest fixture story — does NOT touch `apps/shared/HumanKit/`. Confirmed independent.

## Test strategy

No new unit tests. The contract is enforced by:

1. **Compiler (AC-14.4.1):** `swift build` with package-level `-strict-concurrency=complete` exits 0 with no new availability/concurrency warnings on public symbols.
2. **Doc tool (AC-14.4.2):** `swift package generate-documentation` reports zero undocumented public symbols across the three targets.
3. **Availability error path (AC-14.4.3):** manually verifiable: create a throwaway file `// swift-tools-version: 5.9; targets: [.macOS(.v13)]` and try to import `HumanProtocol.Methods` — expect compiler error referencing `macOS 14`. Document this verification step in the implementer's PR description but do NOT add it as a permanent test (it requires a separate package manifest).
4. **Test targets (AC-14.4.4):** `swift test` green for `HumanProtocolTests`, `HumanClientTests`, `HumanChatUITests`.
5. **CI:** `human-kit-swift` job in `native-apps-fleet.yml` and the parallel `swift test` step in `ci.yml` both green.

## Acceptance criteria mapping

- **AC-14.4.1** (strict-concurrency clean) → step 1 adds the flag to `Package.swift`; step 7 verifies clean build.
- **AC-14.4.2** (every public symbol has non-empty doc comment) → steps 2–6 add `///`; step 9 verifies via `swift package generate-documentation`.
- **AC-14.4.3** (`Methods` enum: macOS-13 consumer gets availability error) → step 3 adds `@available(macOS 14.0, iOS 17.0, *)` to `Methods`; manual verification in test strategy item 3.
- **AC-14.4.4** (existing tests still green) → step 8.

## What's NOT in this story (explicit out-of-scope)

- `HumanOnDevice` / `HumanOnDeviceServer` targets — M3 lane.
- New public APIs, language bindings (Python/Node) — Sprint 14 doesn't ship those (US-14.4 brief and M5 lane).
- Swift 6 migration — out of scope per story.
- DocC catalog / hosted docs site — `///` inline comments only; rendering is future work.
- `@_spi` partition of "public-but-internal" symbols — no new partitioning, even if some symbols look like SPI candidates.
- Renames, refactors, type changes — the diff should be **attributes + comments only**. Any line that changes a symbol name, type, or body is out of scope.
