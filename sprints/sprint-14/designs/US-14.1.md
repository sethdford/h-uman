# Design for US-14.1: macOS archivable + dev-cert codesign

**Status:** DESIGN_READY
**Sprint:** 14
**Priority/Size/Risk:** P0 / M / MEDIUM
**Out of scope:** notarization (US-14.2), iOS archive (US-14.3)

## Approach

The goal is the smallest, repeatable CI-runnable proof that `apps/macos/Human` can be
archived in `Release` configuration and the resulting `.app` bundle is codesigned with
an Apple development certificate that verifies under `codesign --verify --deep --strict`.

We do this in two thin slices:

1. **Project config slice.** Make the macOS target's `Release` build settings emit a
   codesigned, archivable `.app`. If `apps/macos/` already uses XcodeGen
   (`project.yml`), we add `CODE_SIGN_STYLE: Manual`,
   `CODE_SIGN_IDENTITY: "Apple Development"` (the *generic name*, not a SHA-1 hash —
   see Risk 1), and a `DEVELOPMENT_TEAM` placeholder resolved at CI time from a
   secret. If the project is hand-maintained `.pbxproj`, we set the same three keys
   via `xcodebuild` override flags rather than mutating the pbxproj — fewer merge
   conflicts, no generated-file drift.

2. **CI slice.** Add a `macos-app-archive` job to `.github/workflows/native-apps-fleet.yml`
   that runs on `macos-14`, imports a development cert from secrets into a temporary
   keychain, runs `xcodebuild ... archive`, then runs `codesign --verify --deep --strict`
   against the archived `.app`. Both commands must exit 0.

We deliberately choose **"Apple Development" identity by name** over hash-pinning
because the cert SHA-1 differs per machine/keychain — a hash works on the developer's
laptop and silently breaks the CI runner. Name-based selection lets `xcodebuild` find
*the* development cert that was just imported into the ephemeral CI keychain.

Notarization, stapling, and the Developer-ID (distribution) identity are explicitly
deferred to US-14.2. This story only proves the bundle is archivable + dev-signed
end-to-end in CI.

## Implementation steps (for the implementer)

1. **Gating check.** `ls apps/macos/` and confirm one of: `Human.xcodeproj`,
   `project.yml` (XcodeGen), or `Package.swift`. If none, STOP and report
   `RESULT=NEEDS_AC_REFINEMENT` — project generation is a separate story.
2. **Local archive smoke (no signing).** From `apps/macos/`:
   ```
   xcodebuild -scheme Human -configuration Release \
              -archivePath /tmp/Human-unsigned.xcarchive \
              CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO archive
   ```
   This proves the project is structurally archivable before introducing signing.
3. **Codesign config.** Edit `project.yml` (or job flags) per the table above.
   Regenerate the `.xcodeproj` via `xcodegen generate` if using XcodeGen.
4. **Cert import helper.** Write `scripts/ci/import-macos-cert.sh`:
   - `KEYCHAIN=$(mktemp -d)/build.keychain`
   - `security create-keychain -p "$KEYCHAIN_PWD" "$KEYCHAIN"`
   - `security default-keychain -s "$KEYCHAIN"`
   - `security unlock-keychain -p "$KEYCHAIN_PWD" "$KEYCHAIN"`
   - `echo "$MACOS_DEV_CERT_P12_BASE64" | base64 -d > /tmp/dev.p12`
   - `security import /tmp/dev.p12 -k "$KEYCHAIN" -P "$P12_PWD" -T /usr/bin/codesign`
   - `security set-key-partition-list -S apple-tool:,apple: -s -k "$KEYCHAIN_PWD" "$KEYCHAIN"`
   - `rm /tmp/dev.p12`
5. **CI job.** Add to `native-apps-fleet.yml`:
   ```yaml
   macos-app-archive:
     runs-on: macos-14
     needs: [ ... existing macOS deps if any ... ]
     env:
       MACOS_DEV_CERT_P12_BASE64: ${{ secrets.MACOS_DEV_CERT_P12_BASE64 }}
       P12_PWD: ${{ secrets.MACOS_DEV_CERT_P12_PWD }}
       KEYCHAIN_PWD: ${{ secrets.MACOS_KEYCHAIN_PWD }}
       TEAM_ID:    ${{ secrets.APPLE_TEAM_ID }}
     steps:
       - uses: actions/checkout@v4
       - name: Select Xcode
         run: sudo xcode-select -s /Applications/Xcode_15.4.app
       - name: Import dev cert
         run: bash scripts/ci/import-macos-cert.sh
       - name: Archive (Release, signed)
         working-directory: apps/macos
         run: |
           xcodebuild -scheme Human -configuration Release \
             -archivePath /tmp/Human.xcarchive \
             CODE_SIGN_STYLE=Manual \
             CODE_SIGN_IDENTITY="Apple Development" \
             DEVELOPMENT_TEAM="$TEAM_ID" \
             archive | xcpretty
           test -d /tmp/Human.xcarchive/Products/Applications/Human.app
       - name: Verify codesign
         run: |
           codesign --verify --deep --strict --verbose=2 \
             /tmp/Human.xcarchive/Products/Applications/Human.app
           codesign -dv --verbose=4 \
             /tmp/Human.xcarchive/Products/Applications/Human.app 2>&1 \
             | grep -E "Authority=Apple Development"
       - name: Upload archive
         if: always()
         uses: actions/upload-artifact@v4
         with:
           name: Human-macOS-xcarchive
           path: /tmp/Human.xcarchive
           retention-days: 7
   ```
6. **Push, watch the run.** First green run is acceptance for US-14.1.

## Risks

- **Risk 1 — Codesign identity selection by hash (HIGH probability if naive / SMALL impact once caught).**
  A hash-pinned `CODE_SIGN_IDENTITY: 7A8F...` works on the dev laptop and fails on the
  CI runner because the cert SHA-1 is keychain-local. **Mitigation:** use the generic
  string `"Apple Development"` everywhere; verify via `codesign -dv` step that
  `Authority=Apple Development` appears in the signed bundle. Documented in the
  design above; PR review must reject any literal SHA-1 in `CODE_SIGN_IDENTITY`.

- **Risk 2 — Missing secrets in CI (MEDIUM / MEDIUM).**
  If `MACOS_DEV_CERT_P12_BASE64`, `MACOS_DEV_CERT_P12_PWD`, `MACOS_KEYCHAIN_PWD`,
  `APPLE_TEAM_ID` are not provisioned, the job hard-fails at `security import`.
  **Mitigation:** the import script `set -euo pipefail` and prints which env var is
  empty before exiting 1. Tech Lead asks user to confirm secrets exist BEFORE
  implementer pushes. Surface as `BLOCKED_HIGH_RISK` only if secrets cannot be
  provisioned this sprint.

- **Risk 3 — `--deep` is deprecated in modern codesign (LOW / SMALL).**
  Apple discourages `--deep` for *signing* but still supports it for *verifying*.
  AC explicitly calls for `--verify --deep --strict`. **Mitigation:** keep `--deep`
  on the verify call only; do not pass it during signing (Xcode handles nested
  bundles).

- **Risk 4 — Keychain leaks across jobs (LOW / MEDIUM).**
  A keychain created on a hosted runner is destroyed with the runner, so leakage is
  bounded. **Mitigation:** none required for hosted runners; document `if: always()`
  cleanup step if we ever move to self-hosted.

- **Risk 5 — `xcodebuild archive` requires a real `.xcodeproj`, not just SwiftPM
  (MEDIUM / LARGE if true).** If `apps/macos/` is currently Swift-Package-only, the
  archive command will fail. **Mitigation:** step 1 gating check above. If true,
  bounce back to product-owner to add a project-generation story before this one.

- **Risk 6 — Backward compat for local dev builds (LOW / SMALL).** Switching to
  `CODE_SIGN_STYLE=Manual` could break developers who relied on automatic signing.
  **Mitigation:** apply the manual override only via xcodebuild flags in the CI job,
  not as a permanent project setting — local builds keep their existing
  automatic-signing default. If we go the `project.yml` route, scope the manual
  block to the `Release` configuration only and leave `Debug` on `Automatic`.

- **Observability (LOW).** Failure surfaces in GitHub Actions logs. The archive is
  uploaded as an artifact on success AND failure (`if: always()`) so an engineer
  can `codesign -dv` it locally to diagnose.

## Test strategy

- **CI integration test = the AC.** The new `macos-app-archive` job IS the test;
  green = AC satisfied.
- **No new unit tests** — there is no production C/Swift code change; this is
  build-config + workflow only.
- **Manual smoke (one-time, by implementer):** run the archive locally with a real
  dev cert before pushing the CI changes, capture the `codesign -dv` output, paste
  into the PR description.

## Acceptance criteria mapping

| AC | Verified by |
|---|---|
| `xcodebuild ... archive` exits 0 in Release config | "Archive (Release, signed)" step exit code |
| `.app` exists at expected path inside `.xcarchive` | `test -d /tmp/Human.xcarchive/Products/Applications/Human.app` |
| `codesign --verify --deep --strict` exits 0 | "Verify codesign" step exit code |
| Signed with dev cert (not ad-hoc, not Developer ID) | `codesign -dv` grep for `Authority=Apple Development` |
| Runs in CI, not just on a dev machine | The whole job runs on `macos-14` GitHub-hosted runner |

## Notes for implementer

- Do NOT add `--deep` to any *signing* invocation; only to verification.
- Do NOT hard-code a cert SHA-1 anywhere. PR review will reject.
- If you find `apps/macos/` lacks an `.xcodeproj` AND `project.yml`, STOP at step 1
  and surface — do not invent a project structure in this story.
- Keep all secret names matching exactly: `MACOS_DEV_CERT_P12_BASE64`,
  `MACOS_DEV_CERT_P12_PWD`, `MACOS_KEYCHAIN_PWD`, `APPLE_TEAM_ID`. US-14.2
  (notarization) will add `APPLE_ID`, `APPLE_APP_PASSWORD`, `MACOS_DIST_CERT_P12_*`.
- Job name `macos-app-archive` is load-bearing for branch protection later; do not
  rename without updating required-checks.
