# Design for US-103: Thompson-Sampling Contextual Bandit for Proactivity

## Summary

Build a Thompson-sampling contextual bandit to learn per-contact "send vs defer" decisions from implicit reply signals. The implementation uses a closed-form deterministic Beta sampler (inverse-CDF via Marsaglia-Tsang Gamma variates) with no external dependencies, compact binary serialization, and deterministic seeding for tests. The bandit operates standalone in this task; wiring into the proactive throttle (AC-103.3 integration point) happens in US-104.

## Approach

Thompson sampling is the right algorithm here because it naturally balances exploration (when a contact's reply rate is uncertain, sample high θ with some probability) and exploitation (when confident, mostly sample low θ for low-engagement contacts). A Beta(α, β) posterior per contact requires only two scalars per arm, making the design lightweight and serializable.

The design choices:

1. **Deterministic Beta sampling via Marsaglia-Tsang Gamma method**: instead of GSL (external dependency), use two Gamma(α, 1) variates drawn from seeded exponentials. This is mathematically exact and deterministic if the RNG is seeded. The project already uses seeded LCG (from `follow_up.c:63`) for temporal jitter; we follow the same pattern.

2. **Per-contact arm lookup via contact_handle hash into fixed array**: contact_handle is a uint64_t. Hash via `FNV-1a` (cheap, one-liner) into a bounded `arms[]` array. On collision, linear-probe to the next free slot (up to capacity). This avoids heap-per-contact and keeps memory predictable. Capacity is 64 contacts (AC-103.1 spec says "indexed by hash").

3. **Outcome enum and semantics**: defined as `hu_bandit_outcome_t { HU_BANDIT_REPLY=0, HU_BANDIT_IGNORED=1, HU_BANDIT_BLOCKED=2 }`. REPLY increments α (success), IGNORED increments β (failure), BLOCKED increments β by 3 (strong penalty for user opting out). This is the contract with US-104's signal layer.

4. **Serialization**: binary format (magic, version, num_contacts, for-each: contact_handle, α, β, updates). Uses the checkpoint.c pattern (fwrite header + fread validation). Deterministic deserialization via direct struct memcpy (no float rounding surprises).

5. **Convergence and ranking tests**: AC-103.5 simulates 50 updates per contact with fixed reply rates (60%, 20%, 0%), then samples θ 100 times and verifies empirical P(θ > threshold) ≈ true_rate. AC-103.7 asserts arm ranking (60% > 20% > 0%) with ≥90% confidence by counting how many of 100 random samples respect the ordering.

## Detailed Design

### Header: contextual_bandit.h

```c
#ifndef HU_AGENT_CONTEXTUAL_BANDIT_H
#define HU_AGENT_CONTEXTUAL_BANDIT_H

#include "human/core/allocator.h"
#include "human/core/error.h"
#include <stdint.h>
#include <stdbool.h>
#include <stdio.h>

#ifdef __cplusplus
extern "C" {
#endif

/* Bandit outcome signal (from US-104 signal layer). */
typedef enum {
    HU_BANDIT_REPLY    = 0,  /* contact replied: α++ */
    HU_BANDIT_IGNORED  = 1,  /* contact did not reply: β++ */
    HU_BANDIT_BLOCKED  = 2   /* contact blocked/opted out: β += 3 */
} hu_bandit_outcome_t;

/* Per-contact arm state — Beta(α, β) posterior. */
typedef struct hu_contextual_bandit_arm {
    uint64_t contact_handle;  /* uint64_t identifier for deduplification */
    double alpha;             /* successes; initialization: 1.0 (weak prior) */
    double beta;              /* failures; initialization: 1.0 (weak prior) */
    uint64_t updates;         /* cumulative update count for diagnostics */
} hu_contextual_bandit_arm_t;

/* Bandit state container. */
typedef struct hu_contextual_bandit {
    hu_allocator_t *alloc;
    hu_contextual_bandit_arm_t *arms;  /* fixed array, sized at create */
    size_t capacity;                    /* max number of contacts */
    size_t count;                       /* current number of arms in use */
    double threshold;                   /* decision threshold (default 0.3) */
    uint32_t rng_seed;                  /* for deterministic Thompson samples */
} hu_contextual_bandit_t;

/* Create a bandit with capacity for num_contacts. Each arm initializes to
 * Beta(1, 1). Returns HU_OK or HU_ERR_OUT_OF_MEMORY. */
hu_error_t hu_contextual_bandit_create(hu_allocator_t *alloc, size_t capacity,
                                       hu_contextual_bandit_t **out);

/* Destroy and free all bandit state. */
void hu_contextual_bandit_destroy(hu_contextual_bandit_t *bandit);

/* Thompson sample and decide: return true if θ > threshold.
 * If contact_handle is not yet in arms[], initialize a new arm and add it.
 * Deterministic if rng_seed is set (test mode). */
hu_error_t hu_contextual_bandit_decide_send(hu_contextual_bandit_t *bandit,
                                           uint64_t contact_handle,
                                           bool *out_should_send);

/* Update an arm based on outcome. Initializes the arm if not yet present.
 * Returns HU_OK or HU_ERR_OUT_OF_MEMORY (if capacity exhausted). */
hu_error_t hu_contextual_bandit_update(hu_contextual_bandit_t *bandit,
                                       uint64_t contact_handle,
                                       hu_bandit_outcome_t outcome);

/* Serialize bandit state to binary file. Atomic via tmp + fwrite + rename.
 * Returns HU_OK or HU_ERR_IO. */
hu_error_t hu_contextual_bandit_save(hu_contextual_bandit_t *bandit,
                                     const char *path);

/* Deserialize bandit state from binary file. Allocates arms array via alloc.
 * Returns HU_OK, HU_ERR_IO, or HU_ERR_OUT_OF_MEMORY. */
hu_error_t hu_contextual_bandit_load(hu_allocator_t *alloc, const char *path,
                                     hu_contextual_bandit_t **out);

/* Retrieve an arm's current state for diagnostics (read-only). */
hu_error_t hu_contextual_bandit_get_arm(hu_contextual_bandit_t *bandit,
                                        uint64_t contact_handle,
                                        hu_contextual_bandit_arm_t *out_arm);

/* Internal: deterministic Beta(α, β) sampler. Public for testing.
 * Uses Marsaglia-Tsang method: sample two Gamma(α,1) and Gamma(β,1)
 * via exponentials, then θ = Γ(α) / (Γ(α) + Γ(β)). */
double hu_contextual_bandit_sample_beta(double alpha, double beta,
                                        uint32_t *inout_seed);

#ifdef __cplusplus
}
#endif

#endif
```

### Beta Sampler Algorithm

The Marsaglia-Tsang Gamma method is exact and deterministic:

1. **Standard Exponential** (seed s → next sample, new seed):
   ```
   u = (s * 1103515245 + 12345) & 0xFFFFFFFF  // LCG
   e = -log(u / 2^32)                         // scale to [0, ∞)
   return e, s ← u
   ```

2. **Gamma(α, 1)** for α ≥ 1 (Marsaglia acceptance-rejection):
   ```
   d = α - 1/3
   c = 1 / sqrt(9 * d)
   loop:
       z ~ N(0, 1) via Box-Muller (two exponentials + trig)
       v = (1 + c*z)^3
       if v > 0 and log(u) < 0.5*z^2 + d - d*v + d*log(v):
           return d * v
   ```

3. **Beta(α, β)** (simple form):
   ```
   g_alpha = Gamma(α, 1) with seed s1
   g_beta  = Gamma(β, 1) with seed s2 (threaded from s1)
   θ = g_alpha / (g_alpha + g_beta)
   return θ, s1 ← s2
   ```

For speed, we use a simplified Gamma sampler sufficient for typical (α, β) ∈ [1, 100]:
- If α < 1: use ratio-of-uniforms or accept-reject on exponentials.
- If α ≥ 1: Marsaglia method.
- If α = β: use the symmetric Beta-to-Uniform relationship for speed.

The critical property: **given the same seed, two runs produce identical sequences**. We pin the seed at test time via `HU_IS_TEST`.

### Arm Lookup and Collision Handling

Contact lookup via FNV-1a hash:

```c
static uint64_t fnv1a_hash(uint64_t x) {
    const uint64_t FNV_PRIME = 0x100000001B3ULL;
    const uint64_t FNV_OFFSET = 0xCBF29CE484222325ULL;
    uint64_t h = FNV_OFFSET;
    for (int i = 0; i < 8; i++) {
        h ^= (x >> (i * 8)) & 0xFF;
        h *= FNV_PRIME;
    }
    return h;
}

/* Linear-probe insertion. On collision, try (idx + 1) % capacity. */
static hu_contextual_bandit_arm_t *lookup_or_insert(
    hu_contextual_bandit_t *bandit, uint64_t handle, hu_error_t *out_err)
{
    uint64_t idx = fnv1a_hash(handle) % bandit->capacity;
    for (size_t i = 0; i < bandit->capacity; i++) {
        size_t probe = (idx + i) % bandit->capacity;
        if (bandit->arms[probe].contact_handle == 0 ||
            bandit->arms[probe].contact_handle == handle) {
            if (bandit->arms[probe].contact_handle == 0) {
                /* Initialize new arm */
                bandit->arms[probe].contact_handle = handle;
                bandit->arms[probe].alpha = 1.0;
                bandit->arms[probe].beta = 1.0;
                bandit->arms[probe].updates = 0;
                bandit->count++;
            }
            *out_err = HU_OK;
            return &bandit->arms[probe];
        }
    }
    *out_err = HU_ERR_OUT_OF_MEMORY;  /* table full */
    return NULL;
}
```

Capacity is fixed at create time (e.g., 64 contacts). If overflow, return HU_ERR_OUT_OF_MEMORY and log a warning (the throttle will defer the proactive).

### Serialization Format

Binary file format (little-endian, no padding):

```
[0:4]   magic      = 0x425B4E44  ("BAN\0D" reversed for little-endian clarity)
[4:8]   version    = 1
[8:16]  num_arms   = count (uint64_t)
[16:24] rng_seed   = seed at save time
[24:N]  for each arm:
  [0:8]   contact_handle (uint64_t)
  [8:16]  alpha (double, IEEE 754)
  [16:24] beta  (double, IEEE 754)
  [24:32] updates (uint64_t)
```

Load validates magic + version, then reads arms. A malformed file (wrong count, bad doubles) returns HU_ERR_IO.

### Test Structure

**test_contextual_bandit.c** (~420 LOC):

1. **Determinism test** (`test_contextual_bandit_sample_beta_deterministic`):
   - Fix seed to 42
   - Sample θ 10 times, store in array A
   - Reset seed to 42
   - Sample θ 10 times, store in array B
   - Assert A == B (bitwise, within floating-point ULP tolerance)

2. **Convergence test** (`test_contextual_bandit_convergence_after_50_updates`):
   - Initialize bandit with 3 contacts (A, B, C)
   - Simulate 50 outcomes per contact (60%, 20%, 0% true reply rate)
   - After 50 updates each, sample θ 100 times per contact
   - Compute empirical P(decide_send) = P(θ > 0.3)
   - Assert |empirical_P - true_rate| < 0.1 for each contact

3. **Ranking test** (`test_contextual_bandit_arm_ranking_90pct_confident`):
   - Same setup as convergence test
   - For each pair (A, B), count how many of 100 samples have P(A) > P(B)
   - Assert count ≥ 90 (≥90% confidence in ordering)

4. **Serialization round-trip** (`test_contextual_bandit_save_load_deterministic`):
   - Create bandit, add 5 contacts with known (α, β, updates)
   - Save to temp file
   - Load into new bandit
   - Assert all arms match exactly (bitwise for doubles)

5. **Capacity overflow** (`test_contextual_bandit_overflow_returns_err_out_of_memory`):
   - Create bandit with capacity 2
   - Add 3 contacts, assert 3rd returns HU_ERR_OUT_OF_MEMORY

6. **HU_IS_TEST mode** (`test_contextual_bandit_test_mode_uses_fixed_seed`):
   - Compile with HU_IS_TEST=1 (set in CMakeLists.txt test build)
   - Verify seed is pinned (not from clock)

## Risks

### Risk 1: Beta Sampler Correctness (MEDIUM/MEDIUM)
**What could go wrong**: Marsaglia-Tsang Gamma implementation has an off-by-one or sign error in the acceptance-rejection criterion, causing biased samples.

**Probability**: MEDIUM — the algorithm is well-documented but implementation details are easy to botch (Box-Muller requires two exponentials, the log test uses the wrong sign, etc.).

**Impact**: MEDIUM — converged arms will have incorrect posterior, leading to wrong arm rankings in AC-103.7.

**Mitigation**:
- Pin each Gamma(α, 1) against reference implementations (scipy.stats.gamma with same seed)
- Run convergence test with 200 samples (not just 100) to catch subtle biases
- Include reference paper citation in code comments

### Risk 2: Floating-Point Determinism (MEDIUM/SMALL)
**What could go wrong**: Different compiler optimizations (-O0 vs -O3) produce slightly different IEEE 754 results due to FMA (fused multiply-add) or excess precision in x87 FPU registers.

**Probability**: MEDIUM — the project has C11 strict mode, but cross-platform FP variance is common.

**Impact**: SMALL — tests fail intermittently across builds, but the actual algorithm is correct.

**Mitigation**:
- Use a deterministic RNG (seeded LCG) not clock-dependent randomness
- Store intermediate samples as `double` (no precision coercion)
- Run tests with `-ffloat-store` (force memory store) if variance observed
- Accept ULP-level tolerance (±1 ULP) in convergence test assertions

### Risk 3: Hash Collision Under Pathological Contact Handles (LOW/SMALL)
**What could go wrong**: A specific set of contact_handle values (e.g., consecutive integers) hash to the same bucket, causing linear-probe chains to degrade to O(capacity) on every lookup.

**Probability**: LOW — FNV-1a has good avalanche properties; contact handles are typically random IDs (UUIDs or database PKs).

**Impact**: SMALL — lookup becomes O(n) instead of O(1), but with capacity=64 and typical 5-10 active contacts, chain length is short. Latency impact <1 ms even in worst case.

**Mitigation**:
- Use FNV-1a (good mixing for 64-bit keys)
- If needed, switch to quadratic probing or cuckoo hashing (not required for this design)
- Monitor collision depth in production via per-arm `updates` field (older arms = longer-lived collisions)

### Risk 4: Binary Serialization Endianness (LOW/SMALL)
**What could go wrong**: Load an `.bandit` file created on a big-endian system on a little-endian host (or vice versa), causing α, β to be byte-swapped.

**Probability**: LOW — h-uman is x86_64-native (little-endian). Big-endian platforms (ARM EABI, PowerPC) are not primary targets.

**Impact**: SMALL — one wrong byte-order load corrupts the bandit state, but the bug is caught immediately (next Thompson sample will be NaN or out-of-range).

**Mitigation**:
- Document the format as little-endian only in the header comment
- Add endian-check macro at file load time (optional; not blocking for this design)
- Store magic as 0x425B4E44 to catch byte-swap on reload

## Summary

**Chosen Beta-sampling method**: Marsaglia-Tsang Gamma via exponential-based LCG seed threading. Deterministic, no external libs, fits h-uman's zero-dependency contract. Convergence validated via simulated outcomes at known reply rates.

**Top three risks**:
1. **Beta sampler bias** (MEDIUM) — mitigated by pinning against scipy + extended convergence tests
2. **FP determinism variance** (MEDIUM) — mitigated by strict RNG seeding + ULP tolerance in tests
3. **Hash collisions** (LOW) — FNV-1a provides good mixing; linear-probe O(n) acceptable for small capacity

Implementation is 280 LOC in `.c` + 85 LOC in `.h` + 420 LOC in tests, fitting the M estimate. Convergence test design (50 updates + 100 samples + ≥90% ranking accuracy) directly pins AC-103.5 and AC-103.7.
