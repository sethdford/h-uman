# Design for US-105: Nightly LoRA Retraining from Implicit Feedback

## Approach

The nightly LoRA retraining gate already exists in `src/daemon.c:4210` checking `cfg.learning.nightly_lora_enabled`. We wire mining (AC-105.2) to precede training invocation, execute the subprocess deterministically with mocked behavior under tests (AC-105.3), persist checkpoint locations with logging (AC-105.4/5), and enforce a 12-hour cooldown post-success (AC-105.6). The design trades a simple subprocess abstraction for test repeatability: under `HU_IS_TEST`, subprocess invocation is stubbed to return success and write a synthetic adapter file; in production, the real `scripts/training_loop.py` script is invoked.

## Implementation steps

1. **Create header + skeleton** (`include/human/ml/nightly_lora.h`): define `hu_nightly_lora_config_t` (dpo_db path, pairs_threshold, training_script path, output_dir, cooldown_hours), cooldown predicates, `hu_daemon_nightly_lora_run()` signature.
2. **Implement core logic** (`src/ml/nightly_lora.c`): mining → training invocation → checkpoint write → logging. Stub subprocess via `HU_IS_TEST` guard (write synthetic adapter, emit success).
3. **Wire nightly gate** (`src/daemon.c:4210`): replace the comment placeholder with call to `hu_daemon_nightly_lora_run()` after the time/date check.
4. **Add test fixtures** (`tests/test_nightly_lora.c`): create 10 synthetic outcomes, open SQLite fixture DB, call mining, verify pairs count ≥2, verify subprocess was invoked with correct args (via mock), verify checkpoint path created + training.log written.
5. **Build + test**: wire CMakeLists.txt, run suite, verify all 12,800+ pass.

## Risks

- **Subprocess availability (MEDIUM/MEDIUM)**: `scripts/training_loop.py` or symlink does not exist in prod; AC-105.3 says "script is assumed to exist". Mitigation: design specifies that failure to invoke the script is logged but does not crash daemon (continues with previous adapter); tests mock completely so prod deployment is the first real proof.
- **Cooldown drift (LOW/SMALL)**: if daemon process restarts between training runs, cooldown timer resets (in-memory `static atomic_bool`). Mitigation: cooldown flag is one-shot per boot; design accepts this scope — operator can manually trigger if needed by restarting daemon.
- **Determinism under floating-point (LOW/SMALL)**: AC-105.8 says same inputs → same weights within tolerance. Mocked subprocess in tests returns a fixed synthetic adapter, so test determinism is guaranteed. Production determinism depends on the Python script's randomness seed (operator responsibility).

## Test strategy

- **Unit**: fixture DB + mining + mocked subprocess invocation (AC-105.2 + 3) in `test_nightly_lora_mining_and_training_invocation`.
- **Integration**: 10 outcomes → pairs → subprocess mock logs correct args (AC-105.1 gate, AC-105.3 args, AC-105.4 checkpoint, AC-105.5 logging, AC-105.6 cooldown).
- **Determinism**: run scenario 3 times with same fixture; verify identical pairs and logs (AC-105.8).
- **Error case**: subprocess mock returns HU_ERR_IO; verify daemon logs error and continues (graceful fallback per AC-106.2 design).
