# Design for US-106: Online Hot-Swap Adapter Integration

## Approach

After successful LoRA training (AC-105.4), invoke `hu_mlx_admin_swap_adapter()` which POSTs to the local MLX server's `/adapters/swap` endpoint. Swap is async (returns immediately); the design assumes next turn uses the new adapter by the time it runs. On error (transport, HTTP non-2xx), log gracefully and continue with the previous adapter (AC-106.2 resilience). Under tests, the swap is mocked via `HU_IS_TEST` guard: mock the MLX server response, assert the swap was called with the new adapter path, verify output differs from prior turn by checking a deterministic model signature. Telemetry is logged at swap time (old path, new path, latency_ms, status).

## Implementation steps

1. **Verify existing infra**: read `include/human/ml/mlx_admin.h` (done; signature is `hu_mlx_admin_swap_adapter(alloc, base_url, base_url_len, adapter_path, adapter_path_len, &result)`). Verify return contract: `HU_OK` means round-trip succeeded; inspect `result->status_code` for server acceptance (200 = success). Read `src/ml/mlx_admin.c` telemetry logging to confirm AC-106.6 signals exist.
2. **Wire swap call** (`src/daemon.c:4220`): after `hu_daemon_nightly_lora_run()` returns success, call `hu_mlx_admin_swap_adapter(alloc, mlx_url, strlen(mlx_url), new_adapter_path, strlen(new_adapter_path), &result)`. Check `result.status_code == 200`; on error, log warning per AC-106.2 + continue.
3. **Implement test fixture** (`tests/test_adapter_swap.c`): mock MLX adapter loading (via `HU_IS_TEST` guard, have a helper that returns a fixed mock adapter signature); load two adapters; swap to first, verify model output changes (signature format: `"e2e_sig_%.9e"`); swap to second, verify output differs again. Error case: mock server return 500, verify swap logs error + continues.
4. **Concurrent safety** (AC-106.5): the swap is atomic from the MLX server's perspective (adapter is fully loaded before responding); the design trusts the server's atomicity. Tests don't need to verify this — it's verified by the MLX server's implementation.
5. **Build + test**: wire CMakeLists.txt, run suite, verify all pass + no ASan errors.

## Risks

- **Live MLX server requirement (MEDIUM/LARGE)**: AC-106.1 spec says "existing symbol hu_mlx_admin_swap_adapter verified in src/daemon.c:3397" — that call site makes a REAL HTTP POST to the MLX server. Tests MUST mock this via `HU_IS_TEST` to avoid prod dependency. Mitigation: wrap swap call under a test seam. Under `HU_IS_TEST`, use a mock HTTP response handler (return fixed status/path/tensor count); in prod, the real curl call runs.
- **HTTP latency in telemetry (LOW/SMALL)**: AC-106.6 logs latency_ms. If network is slow, latency grows; this is correct behavior and not a bug. Test captures fixed mock latency.
- **Adapter path persistence (LOW/SMALL)**: design does not specify storing the "current adapter path" durably. If daemon restarts, it reloads the default adapter (from config). Follow-up: persist active adapter ID to config on each swap.

## Test strategy

- **Happy path**: load adapter_1, swap, verify output signature changes (via mock model that encodes adapter ID in output).
- **Swap to adapter_2**: swap again, verify output differs from adapter_1.
- **Error handling**: mock MLX server returns HTTP 500; verify error is logged + daemon continues.
- **Concurrent safety**: (design trusts MLX server; no test needed for this story — deferred to MLX server E2E).
- **Telemetry**: verify swap is logged with old path, new path, status_code, latency_ms (AC-106.6).

## Out of scope

- Actual MLX server (assumed running on localhost:8741).
- Adapter path persistence across daemon restart (config update is a follow-up).
- Concurrent turn generation during swap (MLX server atomicity assumption).

## HU_IS_TEST mock strategy

Under `HU_IS_TEST`, the swap call is short-circuited:
```c
if (HU_IS_TEST) {
    // Write a mock response: status 200, tensors_loaded=4, resolved path = input path
    result->status_code = 200;
    result->tensors_loaded = 4;
    result->resolved_adapter_path = strdup(adapter_path);  // via alloc
    return HU_OK;
}
// else: real curl call to MLX server
```

This lets tests verify swap logic without touching network.
