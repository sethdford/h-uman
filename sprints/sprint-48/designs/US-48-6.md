# Design for US-48-6: Smoke test — daemon sends first proactive message within 60s of human onboard

## Approach

US-48-6 is an end-to-end integration test proving the A-loop autoresponder pipeline in CI: `human onboard` completes, spawns the daemon, daemon loads config + opens iMessage chat.db, detects an unresponded message, schedules a follow-up via `hu_daemon_tick_follow_up_watcher()`, flushes it when contact enters active hours, and sends via iMessage—all within 60 seconds of virtual time.

The test runs deterministically without real network or iMessage sends by:
1. **Virtual clock**: Test harness overrides time source via `hu_time_set_test_override_ms()`. Daemon calls `hu_time_get_current_ms()` instead of raw system time. Eliminates time-dependent flake.
2. **iMessage send stub**: Test-mode gate in `src/channels/imessage.c` — when `HU_IS_TEST && test_send_stub_fn` is set, write send attempt to JSON log file instead of spawning osascript.
3. **In-process daemon**: New `src/daemon_test_harness.c` exposes `hu_daemon_init_for_test()` to link daemon as a library. Test drives tick loop directly (no forking, per CLAUDE.md).
4. **Chat.db fixture**: Pre-built SQLite database (checked into `tests/fixtures/chatdb/`) with one unresponded iMessage from seth → seth (marked read, no reply).

## Implementation steps (for the implementer agent)

1. **Audit and refactor time calls** — Grep `src/daemon.c` and `src/follow_up.c` for `time()`, `gettimeofday()`, `clock_gettime()`. Replace with calls to `hu_time_get_current_ms()`. Add time.c + time.h with override mechanism (step 2).

2. **Create time abstraction** — `src/core/time.c` + `include/human/core/time.h`. Export:
   - `int64_t hu_time_get_current_ms(void)` — production uses `clock_gettime()`, test overrides via static var
   - `void hu_time_set_test_override_ms(int64_t ms)` — test only
   - Use `#ifdef HU_IS_TEST` guards for override paths

3. **Build daemon test harness** — `src/daemon_test_harness.c`:
   ```c
   hu_error_t hu_daemon_init_for_test(
       const char *config_path,
       const char *home_path,
       hu_allocator_t *alloc,
       hu_daemon_test_ctx_t **out_ctx
   );
   hu_error_t hu_daemon_tick_once(hu_daemon_test_ctx_t *ctx);
   void hu_daemon_cleanup(hu_daemon_test_ctx_t *ctx);
   ```
   Harness skips forking, daemonization. Loads config from explicit path (no fallback to ~/.human/).

4. **Add iMessage send stub** — In `src/channels/imessage.c`, find the point where osascript is invoked (grep for 'osascript'). Wrap with:
   ```c
   #if defined(HU_IS_TEST) && HU_IS_TEST
   if (hu_imessage_get_test_send_stub_fn() != NULL) {
       hu_imessage_write_test_send_log(target, message);
       return HU_OK;
   }
   #endif
   ```
   Implement `hu_imessage_write_test_send_log()` to append JSON to a temp file.

5. **Create config fixture** — `tests/fixtures/aloop_config.json`:
   ```json
   {
     "follow_up_watcher": { "enabled": true, "interval_seconds": 1 },
     "proactive_throttle": { "enabled": true },
     "providers": { "gemini": { "model": "gemini-3.1-flash" } }
   }
   ```

6. **Create/use chat.db fixture** — Copy template from `tests/fixtures/chatdb/schema_ventura.sql`. Insert one message: seth (is_from_me=1) → seth (chat_id=self), is_read=1, no reply. Save as `tests/fixtures/chatdb/aloop_unresponded.db` (binary).

7. **Write main test** — `tests/test_daemon_aloop_smoke.c`:
   - Init daemon with aloop_config.json + tmpdir home
   - Verify config loaded: `follow_up_watcher.enabled=true`
   - Set time to T+0: `hu_time_set_test_override_ms(1000)`
   - Loop 60 times: `hu_daemon_tick_once(ctx)` + advance time by 1000ms
   - After loop: verify log file contains "scheduled follow-up" + verify stub output contains send attempt
   - Cleanup

8. **Wire test into suite** — Add `run_daemon_aloop_smoke_tests()` to `tests/test_main.c`

9. **Run tests** — `./build/human_tests --filter=daemon_aloop_smoke` → must PASS

10. **Verify full suite** — `./build/human_tests` → all 10,600+ tests must PASS, no ASan errors

## Risks

- **Time call audit incomplete (HIGH/LARGE)** — If daemon.c or follow_up.c calls system time directly in the tick path, time override won't apply. Mitigated by exhaustive grep before step 1. **ACTION**: `grep -rn 'time()\|gettimeofday\|clock_gettime' src/daemon.c src/follow_up.c src/agent/proactive_throttle.c` and replace all with `hu_time_get_current_ms()`.

- **iMessage send stub not covering all paths (MEDIUM/MEDIUM)** — If osascript is invoked from multiple places in imessage.c, stub gate may miss some. Mitigated by adding gate at the ONLY `execve` or `system()` call site, not upstream. **ACTION**: Grep `src/channels/imessage.c` for exact spawn point, add gate there.

- **Chat.db schema version mismatch (MEDIUM/MEDIUM)** — Fixture may use old schema; daemon queries may expect Ventura columns. Mitigated by using same schema version as US-48-3 targets. **Depends on**: US-48-3 design must specify schema version (Catalina / Ventura / Sonoma).

- **Config path isolation (LOW/SMALL)** — Test config in tmpdir; daemon must not fall back to ~/.human/config.json. Mitigated by harness refusing fallback. **TEST**: Add assertion that daemon errors if config_path doesn't exist.

- **Interval compression (LOW/SMALL)** — Test sets interval_seconds=1 (unrealistic). Mitigated by comment in fixture explaining compression is TEST-ONLY. Production defaults to 300s. **TEST**: Fixture includes comment: "# interval_seconds=1 for CI test compression only".

## Test strategy

- **Time override unit test**: `tests/test_core_time.c` — verify `hu_time_set_test_override_ms()` is respected by tick functions.
- **iMessage stub unit test**: `tests/test_daemon_imessage_stub.c` (new) — send a test message, verify it writes to stub output, not osascript.
- **Integration test**: `tests/test_daemon_aloop_smoke.c::test_daemon_sends_proactive_within_60s()` — full daemon loop, config load, follow-up detection, send.
- **Optional boundary test**: `test_scheduled_at_contact_active_hours_boundary()` — time-cross at midnight, verify send fires at contact's awake start, not before.

## Acceptance criteria mapping

- **AC-6.1** (onboard spawns daemon) → `hu_daemon_init_for_test()` call in test
- **AC-6.2** (daemon loads config, enables subsystems) → `HU_ASSERT_TRUE(ctx->config->follow_up_watcher.enabled)`
- **AC-6.3** (daemon finds unresponded message) → Chat.db fixture + watcher tick (from US-48-3)
- **AC-6.4** (within 60s, sends draft) → Stub output file contains send JSON within 60 ticks
- **AC-6.5** (log trace) → Log file grep for "scheduled follow-up" + "flush_scheduled_for"

## Out of scope

- Real iMessage sends (stub only; no macOS AppKit interaction)
- Multi-daemon coordination or restart recovery
- Persona Tier-2+ enrichment (uses Tier-1 from M1)
- DPO feedback on follow-ups (wired later)
- Other channels (iMessage only in this sprint)
- Retry logic on send failure
