# Design for US-48-5: Harden onboarding config to enable A-loop + proactive subsystems by default

## Approach

The onboarding wizard will be extended to detect seth's own iMessage handle from Messages.app's chat.db, prompt for autoresponder + follow-up watcher + proactive throttle enablement with sensible defaults, and write a comprehensive config.json with all required fields. The approach prioritizes safety (never over-prompt, always show detected values before confirming) and backwards compatibility (existing users with prior config are asked to merge or replace).

## Config fields written

**Mandatory output from wizard (MUST all be present in config.json):**

| Field | Location | Type | Default | Source | Notes |
|---|---|---|---|---|---|
| `autoresponder.enabled` | Top-level | bool | true | User prompt (Y/n) | User can opt-out; default yes for iMessage |
| `autoresponder.allowlist` | Top-level | string array | `[<detected-handle>, ...user-provided]` | Auto-detect + manual | Always includes self-chat; user can add more |
| `autoresponder.dnd_schedule` | Top-level | array of hu_dnd_schedule_t | `[{start: 22*60=1320, end: 8*60=480, dow_mask: 0x7F}]` | Default 22:00–08:00 local, all days | User can customize; field name per config schema |
| `follow_up_watcher.enabled` | Top-level | bool | true | User prompt (Y/n) | User can opt-out; default yes |
| `proactive_throttle.enabled` | Top-level | bool | true | Implicit from follow_up_watcher | Default yes; inherit from US-48-4 config structure |
| `proactive_throttle.per_contact_daily_max` | Top-level | uint32 | 1 | Stakeholder decision | Fixed default; configurable later |

**Backwards compat field (detect existing config):**
| Field | Detection | Action |
|---|---|---|
| `~/.human/config.json` exists | Stat the path | Prompt: "Config exists. Merge into it (Y/n) or replace?" |

## Implementation steps (for implementer)

1. **Add iMessage handle-detection helper** (`src/channels/imessage.c`):
   - `hu_error_t hu_imessage_detect_self_handle(hu_allocator_t *alloc, char *buf, size_t buf_size)`
   - Opens chat.db at `~/Library/Messages/chat.db` (macOS only; return `HU_ERR_NOT_SUPPORTED` on other platforms)
   - Queries: `SELECT handle FROM handle WHERE ROWID = 0` (the "Me" record per iMessage schema)
   - Returns `HU_OK` + fills buf with the handle, or `HU_ERR_NOT_FOUND` if chat.db unreadable/missing
   - Guarded by `HU_IS_TEST` so tests can mock it without accessing real chat.db

2. **Extend onboard wizard** (`src/onboard.c`, refactor existing `hu_onboard_run()`):
   - After existing config prompts (provider, model), add new subsection:
     ```
     Enable autoresponder (reply-while-you're-busy) for iMessage? [Y/n] 
     [if yes]
       Detected your iMessage handle: +1555xxxxx. Add to autoresponder allowlist? [Y/n]
       Any other contacts to enable for A-loop? Enter handles comma-separated, or blank to skip:
     Enable proactive follow-ups (auto-detect when you read but don't reply)? [Y/n]
     Quiet hours (default 22:00–08:00 local)? Press enter to accept or enter NN:NN-NN:NN:
     ```
   - Collect inputs; validate handle format (basic: non-empty, under 128 chars)
   - If config exists, prompt: "Merge into existing (Y) or replace (N)? [Y/n]"
   - Build JSON structure with all config fields above
   - Write to `~/.human/config.json` via safe temp-file + rename pattern

3. **Add test fixture** (`tests/test_onboard_aloop.c`, new file):
   - Use stdin redirect pattern (similar to `test_config_parse.c`) to feed wizard prompts
   - Test case: `test_onboard_generates_aloop_config_for_imessage`:
     - Mock stdin with: "Y\nY\n+15551234567,+15559876543\nY\n\n" (yes all, two contacts, default DND)
     - Mock `hu_imessage_detect_self_handle()` to return "+1555detect0"
     - Run `hu_onboard_run()`, read resulting config.json
     - Assert: `autoresponder.enabled=true`, allowlist contains ["+1555detect0", "+15551234567", "+15559876543"]
     - Assert: `follow_up_watcher.enabled=true`, `proactive_throttle.enabled=true`
     - Assert: dnd_schedule has one entry with start=1320 (22:00), end=480 (08:00)

4. **Error paths**:
   - If chat.db unreadable (FDA missing, old macOS, non-Apple): prompt for manual handle entry
   - If user enters empty contacts list: proceed with self-chat only
   - If existing config parse fails after merge: warn but continue (operator can fix via `human doctor`)

## Risk analysis

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| **Chat.db missing on dev machines** | HIGH | MEDIUM | Fallback to manual prompt; document in CLI output. Test mocks the helper. |
| **Auto-detect returns wrong handle** | LOW | MEDIUM | Show detected value in the prompt; user can override. Test with realistic fixtures. |
| **Over-prompting (UX friction)** | MEDIUM | SMALL | Keep to 4–5 new prompts; all optional (user can press enter to skip). Defaults are sensible. |
| **Existing config gets corrupted on merge** | LOW | LARGE | Use atomic temp-file pattern; validate JSON parse before commit; revert on error. Test merge path. |
| **DND window time format confused (24h vs AM/PM)** | MEDIUM | SMALL | Always show default as "22:00–08:00" (24h); accept "NN:NN-NN:NN" only. No AM/PM ambiguity. |
| **Cross-story config key mismatch with US-48-3/4** | MEDIUM | LARGE | **Must coordinate:** confirm field names with US-48-3 tech-lead before implementation. Flag any name drift. |

## Test strategy

- **Unit tests** (test_onboard_aloop.c): mock stdin + `hu_imessage_detect_self_handle()` helper; 5–6 cases
  - Happy path: all prompts yes, self-chat + 2 extra handles, default DND
  - Alternative: all prompts no (minimal config)
  - Edge case: existing config merge
  - Edge case: chat.db unreadable → manual entry
- **Integration smoke test** (test_onboard_aloop.c or test_daemon_aloop_smoke.c):
  - Run `human onboard` via CLI wrapper, verify output config parses and is valid per config schema

## Backwards compatibility

- If `~/.human/config.json` exists:
  - Prompt: "Config found. Merge new A-loop fields into it? [Y/n]"
  - Default: yes (merge)
  - Merge strategy: add new top-level keys only; do not overwrite existing user values
  - Log at INFO: "Merged A-loop config; pre-existing fields preserved"
- If config does not exist:
  - Create fresh with all A-loop fields enabled by default
