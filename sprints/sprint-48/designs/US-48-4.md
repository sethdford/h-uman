# Design for US-48-4: Audit + harden silent config-gated subsystems

## Approach

This story hardens operator visibility for config-gated subsystems that silently no-op when disabled. The rule (`.claude/rules/silent-config-gated-subsystems.md`) requires:

1. Every `if (!cfg->X.enabled)` site emits ONE log line per process lifetime via `hu_log_info_once()` — when disabled AND when enabled.
2. Config parser consolidates "unknown key" warnings into a single startup banner (already implemented in `src/config_validate.c`).
3. Per-subsystem tests verify exactly-1-line-per-invocation discipline.

The `hu_log_info_once()` macro already exists in `include/human/core/log.h` (lines 68–81) backed by atomic CAS; config validation already has the unknown-key banner in `src/config_validate.c` (lines 150–200). This story fills the gap: audit existing subsystems and wire the one-shot logs.

**Scope**: US-48-4 audits pre-existing subsystems (only `reaction_collection` currently exists) and ensures the pattern is complete. US-48-3 is responsible for new sites.

## Implementation steps (for the implementer)

1. Run audit grep: `grep -rn '!cfg->.*\.enabled\b' src/ | grep -v _test.c | grep -v fuzz`
2. For each match, verify the subsystem's tick function has BOTH disabled-path and enabled-path one-shot logs using `hu_log_info_once()` with the atomic guard pattern from `daemon_reaction_poll.c:27–30`
3. Create `tests/test_config_gated_subsystems.c` with one test per subsystem:
   - `test_<subsystem>_disabled_logs_once()` — call tick with `enabled=false`, assert exactly 1 log line, reset guard, call again, assert 0 new lines
   - `test_<subsystem>_enabled_logs_once()` — call tick with `enabled=true`, assert exactly 1 log line, reset guard, call again, assert 0 new lines
4. Log-capture pattern: use existing test infrastructure (check `test_daemon_reaction_poll_wiring.c` for counter/fixture pattern)
5. Verify `src/config_validate.c` emits unknown-key banner at daemon startup (already implemented; no code needed)

## Risks

- **Log spam if guard is wrong** (LOW/SMALL): atomic CAS is thread-safe by design; false-positives would be visible in test (mitigated by per-subsystem tests)
- **Missed subsystem because grep is too narrow** (MEDIUM/SMALL): mitigate by also grepping `enabled\s*=\s*false` and reviewing all daemon_tick_* functions
- **Unknown-key banner ordering** (LOW/SMALL): banner is emitted after all top-level keys are scanned (src/config_validate.c:150–200); safe from multi-pass parser issues
- **US-48-3 conflict** (LOW): follow_up_watcher and proactive_throttle are NEW subsystems; US-48-3's tech-lead is aware and responsible for compliance at birth. No merge conflict expected.

## Test strategy

- Unit tests in `tests/test_config_gated_subsystems.c` (one per subsystem, ~8–10 tests total)
- Extend `tests/test_daemon_reaction_poll_wiring.c` with one-shot log assertions
- No integration tests needed; the log-once guards fire deterministically

## Acceptance criteria mapping

- AC-4.1 (audit grep) → grep output in audit section above

- AC-4.4 (unknown-key banner) → already implemented in `src/config_validate.c`; audit only
