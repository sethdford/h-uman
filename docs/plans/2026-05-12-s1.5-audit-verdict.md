## §5. S1.5 (a) widen `hu_provider_t.load_adapter`

### Decision and divergence from original target

The originally-proposed signature was:

```c
hu_error_t (*load_adapter)(hu_provider_t *self,
                           const hu_lora_adapter_t *adapter,
                           hu_lora_apply_mode_t mode);
```

That naming collided with the existing `hu_lora_adapter_t` in `include/human/ml/lora.h`, which is the on-device *training* artifact (opaque, owns float arrays). The two surfaces answer different questions ("how do I learn this?" vs "how do I serve this?") and must not share a type. The original implementer subagent stalled waiting for a typedef decision; the parent agent took over and landed:

```c
hu_error_t (*load_adapter)(void *ctx,
                           const hu_lora_adapter_spec_t *spec,
                           hu_lora_apply_mode_t mode);
```

Renaming the new deployment-time type to `hu_lora_adapter_spec_t` is non-confusable and matches the "spec" idiom used elsewhere in the codebase for short-lived stack descriptors. `hu_lora_apply_mode_t` was hoisted from `include/human/providers/mlx_qwen3.h` into the new public `include/human/lora.h` header so initiatives #02 (MoLoRA), #05 (verifier-driven TTT), and #08 (federated LoRA) can consume it without taking a dependency on the MLX-specific header.
