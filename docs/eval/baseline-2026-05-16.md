# Persona-Fidelity Baseline — 2026-05-16

First recorded composite-fidelity baseline. Captured before any M3 LoRA
training run touches a frontier model. Any subsequent personalization
work must beat these numbers to claim it actually moved the moat.

Traits: `direct`, `warm`, `low-formality`.

Style fingerprint synthesized from defaults at

## Interpretation

The 0.923 / 0.614 gap is real and informative:

- The **single-axis style score** ceiling-pegs because the fixture
  responses were authored to match the lowercase / abbreviation /
  length axes. This is the BEST a frontier model with this fingerprint
  could realistically do, since the bank is literally the ground truth.

- The **composite score** is dragged down by two non-style axes:
  - `trait coverage = 0.20` — the 5 example responses ("hey, sounds
    good lmk if u want anything else from me today", etc.) are short
    pleasantries. They don't lexically reference "direct", "warm", or
    "low-formality" — the prompt-alignment scorer at
    [src/eval/consistency.c:60](src/eval/consistency.c:60) looks for
    trait words AS substrings in the response. A persona whose traits
    are abstract qualities (style, not topic) will always score low on
    this axis. Fixable by either authoring richer traits or weighting
    this axis down.
  - `line consistency = 0.46` — turn-to-turn word overlap is low when
    consecutive responses talk about different topics ("ready when you
    are" → "got time later?" → "appreciate it"). Mid-range is expected
    for a varied bank.

## Future targets

- **M3 LoRA success (target):** composite ≥ 0.65 (+0.04, ~10 stderr)
  on this fixture, AND single-axis style stays ≥ 0.92.
- **CI gate floor:** composite ≥ 0.55 (today − 0.06). Generous so a
  legitimate scoring nudge doesn't flag, but a broken composite
  (zero / NaN / always-pass) fails fast.
- **Drift watch:** composite stderr should stay ≤ 0.05 on this fixture.
  If it climbs, the underlying scorer's variance changed — investigate
  before trusting the mean.

## How to retake this baseline

1. Run the command above on a clean build (no `personal_model.bin` on
   disk, so the synthetic fingerprint is used).
2. Update the values in this table.
3. Move the previous file to `baseline-<previous-date>.md` for
   trail-of-evidence.
4. Update the CI gate floor in `scripts/check-lora-baseline.sh` only
   if the new baseline justifies it (and explain why in commit message).
